# smartJC 执行计划

> 版本：MVP v0.4 · 2026-09-06
> 当前状态：M0–M6 的 v0.3 MVP 已完成并发布，M7–M12 均已完成并通过 Gate；各阶段实际证据见对应工作记录。
> 范围与交互见 [产品文档](产品文档.md)，字段、接口和运行规则见 [架构文档](架构文档.md)。本文件只规定实施顺序、交付和必要验收。

## 1. 执行约定

M0–M6 保留为已完成历史；v0.4 按 M7 → M8 → M9 → M10 → M11 → M12 逐个推进。M7 只交付文档，其余阶段形成可运行增量。开始前检查最新用户要求、三份文档、现有代码和未提交改动；只处理当前阶段需要的模块。主分支为 `main`，每个里程碑实施前从 `main` 创建独立的 `milestone/m<编号>` 分支；上一阶段验收、记录并合并后再开始下一阶段。用户已授权顺序完成剩余项目开发，无需逐子步骤重新授权；每个里程碑仍独立实现、验收和合并。

复用顺序为现有代码、已选依赖官方能力、必要薄封装。沿用已接入的 React + TypeScript + Vite + Tailwind CSS。M8 已按架构第 1 节迁移 app/modules/shared 的真实职责并保持 v0.3 行为；M9 以 `preparePaper()`、`prepareOutline()`、`buildPresentation()` 落地显式 workflow；M10 才以 pi-agent-core 替换交互式通用轮次循环。不得围绕未来平台预建空目录、空接口、通用 validator framework 或第二套实现。

协作习惯和日常工作流程见根目录 [AGENTS.md](../AGENTS.md)。三份设计文档责任不重叠：产品文档维护范围，架构文档维护唯一契约，本计划引用它们。页面线框、控件及状态表现以产品文档第 3 节为唯一规格，各阶段逐步接入对应页面。实现发现冲突时修正对应权威段落和受影响引用，不在末尾追加第二套“最终定义”。

每个里程碑完成后将实际工作情况写入 `docs/spec/M<编号>.md`，包含完成内容、关键变更、验证证据、未解决问题及 Gate 结论；格式和分支收尾流程遵循 AGENTS.md。本文记录区只同步状态、结论和记录链接，不复制详细报告或另建日报。验收通过、记录提交后自动合并回 `main`；未通过时保留工作分支并如实记录阻塞。技术参数以实际测量为准，未验证项明确标注。

### M0：技术路线验证

建立一个最小 Vite 浏览器验证入口，复用一个 PDF 样例和一个 Deck fixture，不创建三个独立应用。该 PDF 从后续三篇代表论文中选取；固定 Deck 可由其中的图源构造，避免另扩样本集。

- 核对架构中的两个模型候选及官方端点。分别确认能否浏览器直连；至少一个完成文本、图片、结构化结果/工具调用、Streaming 和 Abort。记录实际限制，不为另一个候选增加后端代理。
- 用选定 PDF 确认文本提取、页渲染和同一 bbox 在分析图片、预览、导出裁图中区域一致。用一个固定 Deck 验证 Web/PPTX 共享几何，实际打开导出文件查看文字和图片。
- 简查 IndexedDB 原 PDF Blob 保存与重读，提前排除选定浏览器的基础存储阻塞，不建设完整项目管理。
- 在实际配置的 GitHub Pages 项目子路径验证入口、Hash 路由刷新、静态资源和 PDF.js worker 路径，记录仓库与发布配置。没有远程或访问条件时保留“未验证”，不把本地开发服务器成功写成 Pages 通过。
- 根据代表样例和候选服务限制确定首版 PDF 文件/页数上限、图片分辨率及请求大小预算；这些放在实现常量，不写入领域 Schema，不开启性能基准项目。

Gate：三条浏览器技术路线及 Pages 路径成立，至少一个模型候选可用。未通过的模型不进入生产选项；全部不可用则停在 M0 讨论实际阻塞，不能以引入代理悄悄改变部署边界。

### M1：最小 Deck 与导出

按架构中的唯一类型建立实际 Schema，并从 Schema 派生校验和工具需要的描述。先实现固定学术主题、六类布局、四类元素和共享几何，接通 HTML/SVG 预览及 PptxGenJS 导出。

接入页导航、文字编辑、新增/删除、重排和会话内 Undo/Redo，使用统一内存提交函数保护版本号。包括删图后的现有布局回退，以及删空后的空文稿状态、撤销和导出禁用；复用同一 fixture 派生这些状态。Figure fixture 通过最小 Paper/Source 数据与测试资源映射提供，不因此新增通用 image 元素或接入 PDF 解析。

Gate：固定 Deck 可以预览、编辑、撤销、重做和导出；非法修改不改变 Current。文字可继续编辑，Figure 比例与主要位置合理，具备 typecheck/build 和本阶段必要契约检查。后续复用同一 fixture 与提交语义。

### M2：React 界面、项目、PDF 与来源

从 M1 已验收并合并的 main 创建 milestone/m2，首先按架构第 1 节迁移已有编辑器：核对并安装 React、React DOM 及配套类型和 Vite 插件，更新 TSX 入口与构建配置；将编辑器组件放入 `src/ui/`，保留现有业务模块、Tailwind 主题、共享布局及提交语义。完成后移除已替换的 HTML 字符串界面与手工事件绑定，不长期并行维护两套页面。

迁移验收复用同一 M1 fixture，运行现有 `npm run build`（含 TypeScript 检查）及受影响的浏览器检查：文字草稿、焦点与中文输入法，切页/重排后的选中状态，Undo/Redo、空文稿与 PPTX 导出。确认组件重新渲染、挂载与清理不会重复创建会话或提交修改。通过后继续本阶段新增功能；此项检查不调用真实模型，不增加论文或重复的端到端流程。

接入 IndexedDB 的项目、论文、原 PDF 和 Deck 存储，将 M1 提交函数接到持久化事务。使用 React 实现首页、项目打开/重命名/删除，接入 PDF.js 页文本/元数据解析。

建立集中 SourceReference、Figure/Panel 引用，复用一个 React PDF 页面查看组件完成来源查看及当前元素的裁图覆盖。新增组件按架构第 1 节文件树就近组织，并核对项目切换、卸载时的 PDF 资源释放与旧任务失效。开发样例可提供初始 Figure/Panel 标注，不建设独立的共享原图修正编辑器。

Gate：React 迁移及上述 M1 编辑行为复核通过；保存并重开项目后 PDF、来源和当前元素裁图可恢复；第二个引用同一 Figure 的元素不受裁图影响；内存位图释放后可从 PDF 重建；删除项目不影响模型设置。产物与 checkpoint 通过同一存储函数写入；项目子路径下的 Hash 导航、刷新与 PDF.js worker 加载正常。

### M3：图源和论文理解

产品化 M0 已验证的模型调用，添加独立设置、连接检查和 Key 清除。模型调用、结构化解析、取消和错误信息复用依赖能力，不再写通用 Provider 平台。

按架构顺序实现候选图页分析、Figure/Panel 来源生成、论文理解与 Claim–Evidence–Source 组装。使用同一 Paper 契约，研究类型只保存事实描述；来源和证据引用由应用统一校验与映射。

按架构第 7 节创建公共提示词、首批研究策略 Markdown 文件及本阶段实际使用的阶段提示词，接通 Vite 加载和最小格式检查。按产品文档第 4 节的首批策略内容要求编写提示词，公共规则集中维护。论文理解同时完成默认策略选择，strategyId 随 paper-ready 原子保存；不新增分类模型调用、研究类型工作流或配置界面。

开发核对复用来源查看和必要的临时调试输出，不建设独立 Inspector 页面、知识图谱 UI 或科学验证引擎。阶段提示词只按实际调用拆分，具体研究指导以策略文件为唯一实现来源。

Gate：一个代表样例得到可追溯的主要图源、论文理解及有效策略选择，完整阶段可保存；不合法输出不覆盖稳定 Paper。策略文件的最小格式检查纳入现有构建检查。其余两类论文的内容问题记入同一人工检查记录，不要求每类另建 Schema 或自动测试流水线。

### M4：完整生成与阶段续跑

把前面已经验证的能力接成唯一 GenerationCoordinator：消费自然语言要求和 Paper，带入所选研究策略形成 DeckPlan、生成 Working Deck，校验后保存为 Current，并自动进入编辑器。规划和生成提示词复用 M3 的公共规则及策略加载，不复制按研究类型区分的流程；实际章节顺序和页数由内容及用户要求决定。

此阶段同时完成所有首次生成检查点、阶段产物原子保存、取消、有效任务检查和手动续跑。阶段提交按架构契约核对项目存在和前置 checkpoint，拒绝其他标签页推进或删除后的旧结果。界面只显示高层阶段；不把恢复推迟到 M6，也不增加逐页恢复或后台任务系统。

实现来源、裁图、手工编辑和导出的端到端连接。完成初次生成前保留必要质量提示，不加入默认的第二轮模型复审。

Gate：代表论文从上传一路生成完整 Deck；中途取消/刷新后从最近完整阶段继续；未完成阶段重做，已完成阶段不重跑。按同一主链检查预览、来源和导出，可开始内部 Alpha 使用。

### M5：AI 修改与事务

加入 AI 面板、当前选择上下文、问答/审核与修改意图区分，以及必要的论文/Deck 读取工具。仅开放架构定义的 deck.apply_revision 写入口，绑定请求开始时的目标与版本；复用现有手工编辑提交函数。

实现简短修改摘要、一次请求一次 Undo，以及多轮指代。手工草稿出现时即失效旧 AI 修改，其他改写先等待草稿保存；提交前在数据库事务中再次检查当前 Deck ID、revision 和有效任务，拒绝过期、重复或已取消的请求。科学措辞受证据约束，不以增加独立复审模型或复杂语言规则引擎替代来源查看。

Gate：明确页码不会被当前选择抢占；局部请求只改必要内容；批量操作原子完成；问答不写入；Undo 恢复内容并继续递增版本。用固定数据模拟旧响应和失败，不为这些场景反复调用真实模型。形成可用 Beta。

### M6：版本恢复、PWA 与发布

完成整套重生成与恢复上一版，执行成功后才交换版本，失败不修改已有 Current/Previous。重生成按新要求选用叙事策略，策略与其他生成偏好随新 Deck 成功提交，不重新分析 Paper。重开仍能恢复上一版，版本切换后清空会话撤销栈。

完成 Service Worker 静态缓存、Manifest、安装入口、离线操作和等待用户刷新的更新流程；使用 Pages 实际构建产物，确认延迟加载的 PDF/导出依赖也能离线使用。完成保存失败、资源缺失、模型错误和本地存储提示，禁用缺失资源所依赖的操作。

只对主链发现的性能问题做必要调整，例如按需渲染、释放 Canvas 和限制内存缓存，不另开大 PDF 压测、浏览器矩阵或 Worker 架构重构。

Gate：下面的同一套验收通过，生产界面只展示通过验证的模型；没有声称尚未验证的能力。完成实际 GitHub Pages 发布和入口检查后，才记录已部署与访问地址。

### M7：v0.4 设计契约统一

目标为产品文档、架构文档、执行计划与 AGENTS.md 的唯一一致定义，版本升为 MVP v0.4。吸收论文理解→编辑大纲→确认→Deck→检查/导出、章节与 v2 数据、迁移、prepare/build、模块边界、Agent 权限和工程约束；直接替换冲突段落、线框、字段和引用，不追加第二套方案。

修改仅限上述四份文件与完成时的 docs/spec/M7.md；必要时可给设计基线增加简短决策变更摘要，但不复制权威定义。禁止改 src、prompts、package.json、lockfile、tests、构建及工作流。临时重构任务书是一次性输入，不进入长期索引或提交。

Gate：四份文件的范围、页面状态、字段、checkpoint、目录和阶段定义可直接指导实施且无有效旧冲突；M0–M6 历史完整保留；本地链接、Markdown、术语、交叉引用及里程碑编号检查通过；git diff --check 通过；仅授权文档发生差异，未实现功能不标完成。记录实际结果后按 AGENTS.md 提交、合并并仅推送 main，然后停止。

### M8：行为保持的模块化与可读性重构

仅调整当前代码组织、依赖方向和可读性：建立真实 app/modules/shared 职责，拆 types.ts、storage.ts、analysis.ts、ai.ts、generation.ts 和大页面，提取 repository、service/use case、controller hooks；沿用既有生成、AI、编辑、来源、导出及 PWA 行为。M8 可隔离旧 Agent 循环，但替换留到 M10。

引入一个格式/lint 工具及 Vitest 或等价轻量测试，提供 format、lint、test、check 脚本。复用已有契约 fixture 与固定响应；必要全仓格式化独立提交。禁止引入 pi-agent-core、改变 Plan/Deck Schema、拆出确认门槛、修改生成质量或重做产品 UI；新大纲能力不预建空壳。

Gate：实际 npm run build、npm run check:browser、npm run check:pwa 通过；新增格式/lint/契约检查按实际脚本运行；既有项目可打开且主要用户行为不变，UI/Agent tool 不直接访问 IndexedDB，领域与适配器依赖方向符合架构；高密度单行、多职责文件得到实质改善。检查失败先修复，不以重构为由降低原 Gate。

### M9：DeckPlan v2、学术大纲与叙事校验

M9 保持现有模块边界，不重新设计 generation、DeckSession、Assistant、PDF 或导出基础设施。目标是把 Paper 理解、可编辑学术大纲、确认计划和严格 Build 串成单一显式流程；Narrative 不单独持久化，Section 保持单层，message 继续表示 take-home，确认独立于 PlanMutation，成功 build 后消费删除 DeckPlan，Deck.sections + Slide.sectionId 成为 build 后结构真值。

Recommended model 总则：默认由 GLM-5.3 实现；边界明确、局部且机械的改动可使用 Codex Spark。Codex Sol High 不承担大多数 implementation step，只用于 Schema/migration review、transaction/concurrency review、M9 最终 architecture review，或 GLM 无法可靠解决的高风险问题。

#### M9.1：v2 Domain Contract 与 Deck Propagation（已完成）

- Goal：激活单层 Section、PlannedSection.slideBudget、页面 purpose/message、稀疏 `ClaimEmphasis = "focus" | "omit"`、Deck.sections 与 Slide.sectionId 领域契约，并让现有 Deck 编辑链维护 Section invariant。
- Files：`src/modules/outline/outline.schema.ts`、`src/modules/deck/` 的 schema/mutations/DeckSession/validator、`validatePlan.ts`、`buildDeck.ts` 与相关测试 fixture。

### 自动检查

复用一个最小 Paper/Deck fixture；针对具体字段或请求派生失败输入，不按研究类型复制整套 fixture。模型响应使用固定结构化样例或替身，常规自动检查不使用真实 Key、不产生模型费用。

### 一条主链冒烟

Chrome 中选一篇代表论文、一个通过验证的模型，沿同一条流程检查：

**上传 → 论文分析 → Paper Understanding → 显式生成学术大纲 → 编辑并确认大纲 → 生成 Deck → 来源查看/当前页裁图 → 手工与 AI proposal 修改 → 重排 → 结构/证据检查 → Undo/Redo → PPTX 导出 → 刷新重开。**

这是 v0.4 主链；M8 只沿用原 v0.3 主链验证行为保持，不提前要求新页面。M9–M11 按已实现步骤扩充同一项目，M12 执行最终主链。

阶段续跑、上一版恢复和离线/更新检查复用这个项目，在对应里程碑补上动作，不复制整条主链反复组合。已通过的阶段不因进入下一阶段而全部重跑；修改触及主链或最终发布时再运行相关检查。

发布前在已缓存应用中离线重开、查看 PDF、裁图和导出；检查应用更新只在已保存且空闲时由用户刷新。提示词随同一应用构建更新，沿用该项目核对续跑保留已完成产物、旧策略缺失时按架构规则提示并回退。实际 Pages 子路径上的刷新和依赖加载是发布检查的一部分，不另建托管平台测试体系。

导出的 PPTX 在可用的 PowerPoint 中打开检查文字可编辑、图像不拉伸、来源和主要几何可用；环境只有 Keynote 时使用它并如实记录，不要求两套办公软件同时验收。Edge 只简查入口、项目创建/打开和导出，不重复真实模型主链。

### 三篇论文的人工内容检查

保持机制、组学、临床/转化各一篇，主链论文就是其中之一。另两篇只检查生成内容与必要来源，复用已有结果；仅在相关生成逻辑改变或发现问题时重新生成，不对每篇重复全部编辑、恢复和离线操作。

人工关注研究问题、主要结论与图源是否对应，组别/物种/终点是否准确，是否夸大因果，图例及必要证据是否保留，故事是否连贯且图文可读。v0.4 同时核对：背景/问题/必要设计先于结果、结果占主体、结果按科学问题而非 Figure 编号组织、每页 take-home 与图源相符、最后一个非 custom 章节为综合或 Take-home、局限/讨论位于最终综合之前，以及人工调整后的生成严格遵循确认计划版本。记录发现与修复即可，不建设评分平台或多模型对照矩阵。

提示词调整继续使用这三篇论文，仅复查受影响样例的叙事、证据取舍和用户要求是否落实；修改策略文件无需改代码即可在下次构建后的生成中生效。不为每个策略增加论文、端到端流程、Prompt 快照断言或自动模型评分。

可用本地样例或允许使用的公开论文；只按实际授权保存 PDF，不能把论文或 Key 自动打包进部署产物。
