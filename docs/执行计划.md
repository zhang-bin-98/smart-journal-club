2026-09-07 用户先要求复核并讨论，随后依次授权完成 M11 与 M12。两个里程碑均在各自分支完成实现、验收和记录后合并到 `main`；已有提交与有效历史证据按其版本边界保留。

协作习惯和日常工作流程见根目录 [AGENTS.md](../AGENTS.md)。三份设计文档责任不重叠：产品文档维护范围，架构文档维护唯一契约，本计划引用它们。页面线框、控件及状态表现以产品文档第 3 节为唯一规格，各阶段逐步接入对应页面。实现发现冲突时修正对应权威段落和受影响引用，不在末尾追加第二套“最终定义”。

### M14：全文底稿与版本基础

目标：让 Paper 真正承载完整文章而非 PPT 摘要，并保护既有 Current/Previous。

涉及：project/paper 领域、相关 app 用例与 infrastructure 的 PDF/存储接线，以及旧 outline/deck 的必要引用迁移。先为本阶段触及代码落实单向依赖：纯定义/校验留领域，解析调用顺序归应用，PDF/数据库归适配器；不预搬所有 UI 或生成模块。按架构第 2、4 节将全文转为可定位块，关联原句/段落、实验观察、Claim、Figure/Panel；保留多对多反向查询，不按篇幅删除发现。实现工作 Paper 与冻结证据 Paper 的归属、复制、引用和有界回收，不改 PDF 关联、不创建版本树。

交付与 Gate：本阶段已迁模块不反向依赖 React/DOM/数据库，实际公开入口及依赖方向纳入轻量检查；旧 v0.3/v0.4 当前/上一版完整可打开、旧图框及科学内容保留；旧稿缺讲稿或精确句子关系明确未生成，不被强制补全；迁移幂等/失败保留、不同文稿绑定不同 Paper、跨项目引用拒绝、原句片段定位及关联保护通过。使用同一 fixture 派生风险输入，复用已有论文观察全文提取缺口。该阶段不宣称新切分算法、手动核对或一键新链已完成。

### M15：Figure 切分与核对工作台

目标：降低真实切分错误，并让用户直接修正自动结果。首先建立可复用固定窗口外壳及图源视图，其他视图暂接现有功能；不在本阶段夹带讲稿生成。

涉及：paper/figures 纯几何与内容操作、app 图源用例/分析步骤、infrastructure/pdf/llm/persistence 适配器、ui/workspace 和 ui/paper。纯像素规则接收数据，重计算由 Worker 适配器执行，PDF/Canvas 不进入领域；拖框复用位图并合并帧更新、松手一次保存，同页裁图复用及资源并发有界。会话/核对与保存失败通过应用用例连接 UI。按产品第 3.4、架构第 3 节实现整图定位、局部高清识别、像素间隙辅助、疑点检查及原页/裁图联动。加入整图/Panel 拖框、缩放、补删、改标签、Undo/Redo、恢复自动基线与候选重识别；共享图例允许适度重叠，不抹白或强行归网格。

核对确认绑定切分版本，任何身份/标签/几何变化使其失效；模型重识别不得覆盖人工结果。来源级修改保护旧稿，单页 cropOverride 继续独立。用户只改可视对象，系统维护 ID 与证据关联。

Gate：既有三篇图源中选实际有风险的图，与当前自动框比较漏 Panel、切断坐标/图例、串图和手动修框操作；至少包含共享图例、不同 Panel 尺寸与必要旋转/缩放坐标风险，不新建论文矩阵。固定响应覆盖保存/取消/重试/恢复/旧响应，浏览器实操拖框与撤销、局部重新识别、刷新保留人工框及核对失效。真实结果未改善就记录具体失败，不以“像素算法已接入”宣称准确率提高。完整工作台外壳按产品第 3.1、3.4 节重新实现，不仅搬旧卡片：两行导航/主操作、对象筛选、八手柄与添加模式、自动保存、候选对照、键盘/抽屉及固定滚动所有者实际检查通过。

### M16：大纲、演讲稿与一键生成

目标：用户确认切分后，自动完成大纲与讲稿、页面规划、PPT；可选暂停和主动编辑在同一条链中生效。

涉及：presentation/planning 与 editing 共享内容定义、app/workflows 和提交用例、阶段 Prompt/模型适配，以及大纲讲稿 UI 接线。把旧 outline/deck 的领域职责收敛到 presentation；保留两个会话而复用共同纯规则，把项目 hook 的阶段分支与任务生命周期移到可脱离 React 执行的用例。复用 M14 底稿，按证据生成完整讲述，再决定页面。主线/补充默认充分覆盖发现，显式篇幅要求或人工删除才形成省略记录；去掉双重预算、focus 最少页数和人工 confirmed 的生成门槛。程序处理来源登记、布局分配与有限修复，不要求用户填字段排错。

保存 outline-ready 与 deck-plan-ready；ready 是程序就绪而非用户确认。支持阶段暂停选择、立即暂停/取消、继续、刷新恢复；上游编辑失效旧任务，仅重做依赖内容；阶段进度与 AI 消息不触发整稿重复校验、复制或无关视图重建。Build 遵守所绑定计划与讲稿版本，失败保护稳定稿。

Gate：应用层在无 React/真实模型时可用窄替身测试连续推进、暂停选择、迟到结果、失败与版本冲突；同一 fixture 主链在切分核对后不需额外点击即可得到完整 Deck；在同项目另行操作可选暂停、编辑大纲/讲稿、继续和取消，旧响应不覆盖人工改动。原句/图证据进入规划上下文，覆盖缺口与科学不确定分开，自动格式修复有上限。用已有代表论文必要真实调用验证新链和模型原稿，不用历史人工稿或固定响应证明生成质量。

### M17：汇报编辑工作台与讲稿同步

目标：把大纲/讲稿、幻灯片、检查与导出接入 M15 的同一固定窗口外壳，完成生成后的修改闭环。

涉及：ui/workspace、ui/presentation、presentation/editing/layout、app 的内容提交/导出用例与 assistant 接线、infrastructure/pptx。完成剩余旧编辑/Agent/导出职责归位，界面 hook 不承载事务或工作流；按可见范围挂载缩略图，讲稿局部更新，预览/导出清晰度和缓存分离，导出按有限批次准备资源并处理迟到结果；工具调用同一内容用例，不复制手工编辑规则。左侧主线/补充与章节缩略图，中间 Canvas，下方当前页讲稿，右侧 Inspector/AI；底部为共用紧凑状态条和按需展开 AI 输入；主操作固定、低频操作进菜单。支持多选删页、重排、讲稿编辑和受影响页面更新候选；删除不删除论文发现，不要求用户修预算。

手工与 AI 修改沿同一提交/提案/Undo；更新候选不能覆盖人工内容。Current/Previous 一并保存讲稿与论文绑定，导出讲稿到 PPTX 对应页备注，保留原生文字与图像。

Gate：按产品第 3.1、3.5、3.6、3.10 节重新设计讲述、幻灯片和检查视图；1440×900、1280×720、1024×768 及 200% 缩放下检查关键操作入口，复用同一主链，不复制全套 E2E。外层不成长网页，内容区域独立滚动；验证对象往返定位、直接编辑、讲稿调高/收起、AI 展开、键盘/输入法和抽屉焦点，不能用缩小字体或只断言无横向溢出替代验收。实际验证生成后大纲可编辑、删页同步讲稿分配、手工内容冲突与版本恢复；顶栏/检查统一导出，普通叙事警告不成为逐项确认门槛，资源/引用错误仍拦截。沿同一主链验证 PPTX 页与备注对应。

### M0：技术路线验证

建立一个最小 Vite 浏览器验证入口，复用一个 PDF 样例和一个 Deck fixture，不创建三个独立应用。该 PDF 从后续三篇代表论文中选取；固定 Deck 可由其中的图源构造，避免另扩样本集。

- 核对架构中的两个模型候选及官方端点。分别确认能否浏览器直连；至少一个完成文本、图片、结构化结果/工具调用、Streaming 和 Abort。记录实际限制，不为另一个候选增加后端代理。
- 用选定 PDF 确认文本提取、页渲染和同一 bbox 在分析图片、预览、导出裁图中区域一致。用一个固定 Deck 验证 Web/PPTX 共享几何，实际打开导出文件查看文字和图片。
- 简查 IndexedDB 原 PDF Blob 保存与重读，提前排除选定浏览器的基础存储阻塞，不建设完整项目管理。
- 在实际配置的 GitHub Pages 项目子路径验证入口、Hash 路由刷新、静态资源和 PDF.js worker 路径，记录仓库与发布配置。没有远程或访问条件时保留“未验证”，不把本地开发服务器成功写成 Pages 通过。
- 根据代表样例和候选服务限制确定首版 PDF 文件/页数上限、图片分辨率及请求大小预算；这些放在实现常量，不写入领域 Schema，不开启性能基准项目。

Gate：三条浏览器技术路线及 Pages 路径成立，至少一个模型候选可用。未通过的模型不进入生产选项；全部不可用则停在 M0 讨论实际阻塞，不能以引入代理悄悄改变部署边界。

### M1：最小 Deck 与导出

### M11：编辑器工作区与检查页

目标是按产品文档第 3.6、3.10 节完成编辑工作区与检查流程。M11 已按本节范围完成，实际实现、验证与环境限制见 [M11 工作记录](spec/M11.md)；M10 已有的提问/修改、范围和 proposal 能力继续复用。

1. 工作区：顶部步骤导航；左侧按章节折叠，显示页数、警告、缩略图与选中态；中间 Canvas；右侧 Content/Source/Layout/AI Inspector。页目的、本页结论、Claim、来源、布局及选中元素操作按产品规格接入，不能用章节目的代替页目的。
2. AI 与空间：按产品第 3.6 节，右侧 Inspector 的 AI 标签展示对话、工具状态、proposal 影响页/差异及应用/放弃；整个编辑器底部独立命令区承载 scope chips、提问/修改模式、实际范围、输入与发送/取消。两区共用同一请求状态；右侧 Inspector 可手动收起，空间不足时优先保留画布，再收起章节导航。
3. 检查与导出：汇总叙事、证据、视觉、科学人工复核及资源问题；每条问题能返回对应章节、页或元素，全局缺项指向可编辑入口。顶栏和检查页使用同一导出门槛：硬错误阻止导出，警告确认绑定已保存 Deck ID/revision，内容改变后重新检查；保留导出快照、进度、防重复点击、错误与重试。
4. 验证：在同一 fixture 和主链中实际操作上述新 UI。检查页和顶栏分别验证叙事硬错误拦截、警告确认与版本失效；复核问题定位、导出失败、旧稿修复和零页状态。检查桌面及收起布局的可用空间，不仅检查页面节点存在或没有横向溢出。

保留文字编辑、草稿/输入法、来源查看、当前元素裁图、增删/重排、空文稿、Undo/Redo 和共享几何导出。AI/Inspector 优先收起以保留画布，不建设自由坐标或完整 WYSIWYG。

Gate：上述工作区和检查流程均可实际使用；章节可折叠、问题可定位、页目的和结论可编辑、实际 AI 范围与 proposal 应用动作清楚，画布空间可用；顶栏不能绕过检查与警告确认，导出进度和失败可见。现有编辑及来源未退化，桌面 Chrome/Edge 主链按第 3 节范围验证；只能记录实际运行浏览器，不将未安装环境视为实测。通用单元测试或旧主链通过不能替代新增行为验收。

### M12：内容质量、兼容与发布验收

使用既有机制、组学、临床/转化三篇论文，核对大纲、叙事、证据、Figure 可读性和可编辑导出；修复真实暴露的 Prompt/validator/layout 问题。检查 v0.3 迁移、Current/Previous、离线、更新及既有 Pages 发布，不新增论文/模型组合或评分平台。

### v0.5 验证规则

本节新规则用于 M14–M18；M13 只执行文档静态检查。复用既有一个最小 fixture、一条主链及机制、组学、临床/转化三篇论文，只增加实际新增风险的检查，不建多模型/多浏览器/多论文组合矩阵。

| 保护风险 | 必要验证 |

| 全文被提前压缩、来源对应失真 | 全文块与原句定位、Claim–Evidence–Source 多对多关系、汇报偏好不删底稿发现 |
| 切分越界、串图、漏图及人工结果丢失 | 图局部/原页坐标换算、共享图例重叠、补删/改框/标签、重识别候选、撤销和刷新 |

| 不能干预或旧任务覆盖编辑 | 阶段暂停与立即取消、编辑失效、手工草稿、继续、迟到回调和事务版本复核 |

新主链：

**上传 → 全文与图源分析 → 查看并手动调整切分 → 确认一次 → 自动完成大纲/讲稿/规划/PPT → 编辑讲稿和页面、删页/重排 → 来源与单页裁图 → AI 提案应用 → 导出含讲者备注的 PPTX → 刷新重开。**

在同一项目补充“大纲/讲稿后暂停”“规划后暂停”、立即取消和继续，验证每步可介入；不复制完整 E2E 多次运行。自动回归用固定响应，真实模型只用于阶段必要能力与内容验收。三篇只对当前修改影响的内容重新生成，但新初稿质量结论必须有当前生成证据，不能用人工修正稿代替。

人工核对分别记录：自动框缺陷与实际修框；模型原稿遗漏/错误与用户修正；讲述是否完整、组别/物种/终点与因果边界、图例及证据保留、主线收尾及补充覆盖。切分确认是产品操作，不替代验收人员对科学表达的独立检查。无确定性代码能证明的内容标人工判断。

实际办公软件打开新稿并检查备注、文字编辑、图片比例；PWA 离线、本地数据、更新与线上 Pages 继续沿旧边界验证。只记录实际可用的浏览器/办公软件，保持生产部署提交、Actions 和入口证据可追溯。论文与 Key 不进入源码或部署产物。

### 分层验证与 UI 任务验收

性能设计本轮仅纳入四项实现约束：轻量交互路径、重计算与 UI 分离、局部更新、图片资源及并发上限。用户明确暂不考虑第 5 项专项性能验收，因此不新增性能基准、响应时间阈值、帧率目标、扩展页数压力样例或硬件测试矩阵；M15–M17 实现上述职责时沿用原有必要正确性检查，不将其宣称为性能实测。原已约定的功能/UI 任务验收继续保留。

领域规则用普通数据和纯函数验证；应用用例注入有限外部替身验证步骤/暂停/取消/修复；IndexedDB 原子性、PDF 坐标和导出用真实适配器验证；UI 复用同一浏览器主链，不把用例每个分支都做成 E2E。真实模型只负责本阶段科学内容与能力证据。窄接口、职责依赖及具体边界以架构第 1 节为准，不新建第二套测试工具。

现有 npm run check 包含 lint、format、unit 与 build，不含 check:browser/check:pwa。各阶段按真实改动执行对应脚本并分别记录，不能把单个命令通过写成全栈验收通过。迁移后新增依赖检查纳入现有工具，禁止深层跨领域和反向基础设施引用；兼容性薄重导出的清理随实际调用迁移，不将“改了路径”作为完成。

UI 验收以实际任务为准：定位有疑点的 Figure → 放大并修一个边框 → 补漏 Panel / 修改标签 → 查看实际裁图和原文后返回 → 撤销/重做并确认保存 → 核对后自动生成 → 从讲稿定位页面 → 删除/重排并核对讲稿 → 查看 AI 差异 → 导出。必选操作无需滚动整页找按钮，任务状态持续可见，错误留在原对象并给恢复入口，跨视图不丢位置或输入。缩小窗口只重查受影响的布局与关键操作，不重跑模型链。

分别记录自动切分错误、用户修框步骤、模型原稿内容缺口和人为修订，不能把人工修好后的结果当初稿质量。全文相关段落/图注的提取遗漏与“已有 Claim 未进入汇报”分开查；提取覆盖不以引用数量或凭空百分比宣称完整。

### v0.3/v0.4 验证基线（历史）

### 自动检查

复用一个最小 Paper/Deck fixture；针对具体字段或请求派生失败输入，不按研究类型复制整套 fixture。模型响应使用固定结构化样例或替身，常规自动检查不使用真实 Key、不产生模型费用。

| 保护的风险 | 必要检查 |
|---|---|
| 非法数据和断裂来源 | 元素/布局白名单、ID 与引用、Figure/Panel 归属、bbox 边界；零页可保存但禁用导出 |
| 改错页或裁图扩散 | 显式目标优先；当前元素覆盖值不改变 Source 或其他元素 |
| 半提交与旧响应覆盖 | 批量修改失败、写入失败、版本不符、手工草稿和取消使旧响应失效；导出使用开始时快照 |
| 撤销破坏版本检查 | 内容恢复，revision 递增，Undo 后新编辑清空 Redo |
| 刷新与替换丢成果 | 阶段产物/checkpoint 一起保存；paper-ready/deck-plan-ready 显式暂停；阶段已推进或项目已删除时拒绝旧结果；重生成成功后才切换版本 |
| 迁移及章节归属 | M9：Plan/Deck v1→v2 纯函数、Current/Previous、迁移失败保留数据、章节顺序与 sectionId 完整性 |
| 大纲叙事与 Build 失配 | M9：Plan/Deck 两个叙事入口；独立 build-contract validator；Plan revision/原子性/草稿恢复、confirmed 唯一前提、人工顺序与图源保持；Current 可编辑且候选基准过期后 stale 拒绝 |
| Agent 权限与提案 | M10：提问无写工具、一次请求一个 proposal、scope/旧版本/取消/草稿失效、abort 不写入、应用失败不改 Current |
| 检查与导出门槛 | M11：问题定位、版本变更后重算、硬错误不可导出、警告确认、零页/旧稿恢复及共享几何不退化 |

同一检查随实现补齐和复用，不在每个 Mx 重建单元、集成、E2E 三套重叠覆盖。M1 已有内存检查到 M2 增加实际存储边界即可；M5/M6 只补新增风险。无覆盖率目标、UI 文案快照、逐像素对比、随机 LLM 字符串断言或通用故障注入框架。

M8 迁移已复查受影响的既有行为并交付 format/lint/test/check；M9、M10 已接入计划与 Agent 权限；M11 已完成工作区、问题定位和统一导出门槛；M12 已完成最终内容、兼容、PowerPoint 与实际发布验收。各阶段均按实际脚本记录单元、构建、浏览器与 PWA 证据。

### 一条主链冒烟

Chrome 中选一篇代表论文、一个通过验证的模型，沿同一条流程检查：

**上传 → 论文分析 → Paper Understanding → 显式生成学术大纲 → 编辑并确认大纲 → 生成 Deck → 来源查看/当前页裁图 → 手工与 AI proposal 修改 → 重排 → 结构/证据检查 → Undo/Redo → PPTX 导出 → 刷新重开。**

这是 v0.4 主链；M8 只沿用原 v0.3 主链验证行为保持，不提前要求新页面。M9–M11 按已实现步骤扩充同一项目，M12 已沿同一主链完成最终验收。

阶段续跑、上一版恢复和离线/更新检查复用这个项目，在对应里程碑补上动作，不复制整条主链反复组合。已通过的阶段不因进入下一阶段而全部重跑；修改触及主链或最终发布时再运行相关检查。

发布前在已缓存应用中离线重开、查看 PDF、裁图和导出；检查应用更新只在已保存且空闲时由用户刷新。提示词随同一应用构建更新，沿用该项目核对续跑保留已完成产物、旧策略缺失时按架构规则提示并回退。实际 Pages 子路径上的刷新和依赖加载是发布检查的一部分，不另建托管平台测试体系。

导出的 PPTX 在可用的 PowerPoint 中打开检查文字可编辑、图像不拉伸、来源和主要几何可用；环境只有 Keynote 时使用它并如实记录，不要求两套办公软件同时验收。Edge 只简查入口、项目创建/打开和导出，不重复真实模型主链。

### 三篇论文的人工内容检查

保持机制、组学、临床/转化各一篇，主链论文就是其中之一。另两篇只检查生成内容与必要来源，复用已有结果；仅在相关生成逻辑改变或发现问题时重新生成，不对每篇重复全部编辑、恢复和离线操作。

人工关注研究问题、主要结论与图源是否对应，组别/物种/终点是否准确，是否夸大因果，图例及必要证据是否保留，故事是否连贯且图文可读。v0.4 同时核对：背景/问题/必要设计先于结果、结果占主体、结果按科学问题而非 Figure 编号组织、每页 take-home 与图源相符、最后一个非 custom 章节为综合或 Take-home、局限/讨论位于最终综合之前，以及人工调整后的生成严格遵循确认计划版本。记录发现与修复即可，不建设评分平台或多模型对照矩阵。

提示词调整继续使用这三篇论文，仅复查受影响样例的叙事、证据取舍和用户要求是否落实；修改策略文件无需改代码即可在下次构建后的生成中生效。不为每个策略增加论文、端到端流程、Prompt 快照断言或自动模型评分。

可用本地样例或允许使用的公开论文；只按实际授权保存 PDF，不能把论文或 Key 自动打包进部署产物。
