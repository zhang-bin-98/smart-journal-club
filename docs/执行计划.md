# smartJC 执行计划

> 版本：MVP v0.3 · 2026-09-05
> 当前状态：仅完成文档设计，M0–M6 均未开始；没有应用代码、已落成 Schema 或部署验证记录。
> 范围与交互见 [产品文档](产品文档.md)，字段、接口和运行规则见 [架构文档](架构文档.md)。本文件只规定实施顺序、交付和必要验收。

## 1. 执行约定

按 M0 → M6 推进，每阶段形成可运行增量。开始前检查最新用户要求、三份文档、现有代码和未提交改动；只处理当前阶段需要的模块。

复用顺序为现有代码、已选依赖官方能力、必要薄封装。Pi AI/Core 按实际需要使用，不围绕未来平台抽象，不预建目录树、空接口或第二套实现。UI 选型只需支撑当前页面和已有 Pi 调用，不因框架比较另立工程阶段。

协作习惯和日常工作流程见根目录 [AGENTS.md](../AGENTS.md)。三份设计文档责任不重叠：产品文档维护范围，架构文档维护唯一契约，本计划引用它们。页面线框、控件及状态表现以产品文档第 3 节为唯一规格，各阶段逐步接入对应页面。实现发现冲突时修正对应权威段落和受影响引用，不在末尾追加第二套“最终定义”。

每个阶段结束只记录完成内容、验证证据、未解决阻塞及是否通过 Gate。结论更新到本文的记录区；不新建重复任务索引、日报或阶段报告文档。技术参数以实际测量为准，未验证项明确标注。

## 2. 阶段交付

| 阶段 | 可运行增量 | 进入下一阶段的条件 |
|---|---|---|
| M0 | 单个浏览器验证入口证明模型、PDF、导出和静态托管路线 | 至少一个模型可用，裁图和共享布局成立，Pages 路径验证通过 |
| M1 | 固定 Deck → 预览 → 手工编辑/Undo → PPTX | 四类元素与六类布局足以完成演示，导出可编辑 |
| M2 | PDF → 本地项目 → 来源查看/当前页裁图 → 重开 | IndexedDB 持久化可靠，来源与当前页裁图可恢复 |
| M3 | 图源与论文理解 → 带来源 Paper | 主要结论有有效证据链，失败不覆盖稳定分析 |
| M4 | 上传 → 全阶段自动生成 → 完整 Deck | 阶段保存、取消和续跑在同一主链中可用 |
| M5 | AI 问答/修改 → 原子提交 → 一次 Undo | 显式目标正确、局部修改可控、过期响应不覆盖新内容 |
| M6 | 上一版恢复 + PWA 离线/更新 + Pages 发布 | 同一主链及必要内容检查通过，无首版外阻塞项 |

### M0：技术路线验证

建立一个最小 Vite 浏览器验证入口，复用一个 PDF 样例和一个 Deck fixture，不创建三个独立应用。该 PDF 从后续三篇代表论文中选取；固定 Deck 可由其中的图源构造，避免另扩样本集。

- 核对架构中的两个模型候选及官方端点。分别确认能否浏览器直连；至少一个完成文本、图片、结构化结果/工具调用、Streaming 和 Abort。记录实际限制，不为另一个候选增加后端代理。
- 用选定 PDF 确认文本提取、页渲染和同一 bbox 在分析图片、预览、导出裁图中区域一致。用一个固定 Deck 验证 Web/PPTX 共享几何，实际打开导出文件查看文字和图片。
- 简查 IndexedDB 原 PDF Blob 保存与重读，提前排除选定浏览器的基础存储阻塞，不建设完整项目管理。
- 在实际配置的 GitHub Pages 项目子路径验证入口、Hash 路由刷新、静态资源和 PDF.js worker 路径，记录仓库与发布配置。没有远程或访问条件时保留“未验证”，不把本地开发服务器成功写成 Pages 通过。
- 根据代表样例和候选服务限制确定首版 PDF 文件/页数上限、图片分辨率及请求大小预算；这些放在实现常量，不写入领域 Schema，不开启性能基准项目。

Gate：三条浏览器技术路线及 Pages 路径成立，至少一个模型候选可用。未通过的模型不进入生产选项；全部不可用则停在 M0 讨论实际阻塞，不能以引入代理悄悄改变部署边界。

### M1：最小 Deck 与导出

按架构中的唯一类型建立实际 Schema，并从 Schema 派生校验和工具需要的描述。先实现固定学术主题、六类布局、四类元素和共享几何，接通 HTML/SVG 预览及 PptxGenJS 导出。

接入页导航、文字编辑、新增/删除、重排和会话内 Undo/Redo，使用统一内存提交函数保护版本号。Figure fixture 通过最小 Paper/Source 数据与测试资源映射提供，不因此新增通用 image 元素或接入 PDF 解析。

Gate：固定 Deck 可以预览、编辑、撤销、重做和导出；非法修改不改变 Current。文字可继续编辑，Figure 比例与主要位置合理，具备 typecheck/build 和本阶段必要契约检查。后续复用同一 fixture 与提交语义。

### M2：项目、PDF 与来源

接入 IndexedDB 的项目、论文、原 PDF 和 Deck 存储，将 M1 提交函数接到持久化事务。完成首页、项目打开/重命名/删除和 PDF.js 页文本/元数据解析。

建立集中 SourceReference、Figure/Panel 引用，复用一个页面查看组件完成来源查看及当前元素的裁图覆盖。开发样例可提供初始 Figure/Panel 标注，不建设独立的共享原图修正编辑器。

Gate：保存并重开项目后 PDF、来源和当前元素裁图可恢复；第二个引用同一 Figure 的元素不受裁图影响；内存位图释放后可从 PDF 重建；删除项目不影响模型设置。产物与 checkpoint 通过同一存储函数写入。

### M3：图源和论文理解

产品化 M0 已验证的模型调用，添加独立设置、连接检查和 Key 清除。模型调用、结构化解析、取消和错误信息复用依赖能力，不再写通用 Provider 平台。

按架构顺序实现候选图页分析、Figure/Panel 来源生成、论文理解与 Claim–Evidence–Source 组装。使用同一 Paper 契约，研究类型只保存事实描述；来源和证据引用由应用统一校验与映射。

按架构第 7 节创建公共提示词、首批研究策略 Markdown 文件及本阶段实际使用的阶段提示词，接通 Vite 加载和最小格式检查。按产品文档第 4 节的首批策略内容要求编写提示词，公共规则集中维护。论文理解同时完成默认策略选择，strategyId 随 paper-ready 原子保存；不新增分类模型调用、研究类型工作流或配置界面。

开发核对复用来源查看和必要的临时调试输出，不建设独立 Inspector 页面、知识图谱 UI 或科学验证引擎。阶段提示词只按实际调用拆分，具体研究指导以策略文件为唯一实现来源。

Gate：一个代表样例得到可追溯的主要图源、论文理解及有效策略选择，完整阶段可保存；不合法输出不覆盖稳定 Paper。策略文件的最小格式检查纳入现有构建检查。其余两类论文的内容问题记入同一人工检查记录，不要求每类另建 Schema 或自动测试流水线。

### M4：完整生成与阶段续跑

把前面已经验证的能力接成唯一 GenerationCoordinator：消费自然语言要求和 Paper，带入所选研究策略形成 DeckPlan、生成 Working Deck，校验后保存为 Current，并自动进入编辑器。规划和生成提示词复用 M3 的公共规则及策略加载，不复制按研究类型区分的流程；实际章节顺序和页数由内容及用户要求决定。

此阶段同时完成所有首次生成检查点、阶段产物原子保存、取消、有效任务检查和手动续跑。界面只显示高层阶段；不把恢复推迟到 M6，也不增加逐页恢复或后台任务系统。

实现来源、裁图、手工编辑和导出的端到端连接。完成初次生成前保留必要质量提示，不加入默认的第二轮模型复审。

Gate：代表论文从上传一路生成完整 Deck；中途取消/刷新后从最近完整阶段继续；未完成阶段重做，已完成阶段不重跑。按同一主链检查预览、来源和导出，可开始内部 Alpha 使用。

### M5：AI 修改与事务

加入 AI 面板、当前选择上下文、问答/审核与修改意图区分，以及必要的论文/Deck 读取工具。仅开放架构定义的 deck.apply_revision 写入口，绑定请求开始时的目标与版本；复用现有手工编辑提交函数。

实现简短修改摘要、一次请求一次 Undo，以及多轮指代。提交前在数据库事务中再次检查当前 Deck ID 和 revision，拒绝过期、重复或已取消的请求。科学措辞受证据约束，不以增加独立复审模型或复杂语言规则引擎替代来源查看。

Gate：明确页码不会被当前选择抢占；局部请求只改必要内容；批量操作原子完成；问答不写入；Undo 恢复内容并继续递增版本。用固定数据模拟旧响应和失败，不为这些场景反复调用真实模型。形成可用 Beta。

### M6：版本恢复、PWA 与发布

完成整套重生成与恢复上一版，执行成功后才交换版本，失败不修改已有 Current/Previous。重生成按新要求选用叙事策略，策略与其他生成偏好随新 Deck 成功提交，不重新分析 Paper。重开仍能恢复上一版，版本切换后清空会话撤销栈。

完成 Service Worker 静态缓存、Manifest、安装入口、离线操作和等待用户刷新的更新流程；使用 Pages 实际构建产物，确认延迟加载的 PDF/导出依赖也能离线使用。完成保存失败、资源缺失、模型错误和本地存储提示，禁用缺失资源所依赖的操作。

只对主链发现的性能问题做必要调整，例如按需渲染、释放 Canvas 和限制内存缓存，不另开大 PDF 压测、浏览器矩阵或 Worker 架构重构。

Gate：下面的同一套验收通过，生产界面只展示通过验证的模型；没有声称尚未验证的能力。完成实际 GitHub Pages 发布和入口检查后，才记录已部署与访问地址。

## 3. 唯一验证范围

### 自动检查

复用一个最小 Paper/Deck fixture；针对具体字段或请求派生失败输入，不按研究类型复制整套 fixture。模型响应使用固定结构化样例或替身，常规自动检查不使用真实 Key、不产生模型费用。

| 保护的风险 | 必要检查 |
|---|---|
| 非法数据和断裂来源 | 元素/布局白名单、ID 与引用、Figure/Panel 归属、bbox 边界 |
| 改错页或裁图扩散 | 显式目标优先；当前元素覆盖值不改变 Source 或其他元素 |
| 半提交与旧响应覆盖 | 批量修改失败、数据库写入失败、版本不符、取消后的响应不写入 |
| 撤销破坏版本检查 | 内容恢复，revision 递增，Undo 后新编辑清空 Redo |
| 刷新与替换丢成果 | 阶段产物/checkpoint 一起保存；重生成失败保留 Current/Previous，成功后才切换 |

同一检查随实现补齐和复用，不在每个 Mx 重建单元、集成、E2E 三套重叠覆盖。M1 已有内存检查到 M2 增加实际存储边界即可；M5/M6 只补新增风险。无覆盖率目标、UI 文案快照、逐像素对比、随机 LLM 字符串断言或通用故障注入框架。

### 一条主链冒烟

Chrome 中选一篇代表论文、一个通过验证的模型，沿同一条流程检查：

**上传 → 自动生成 → 来源查看 → 当前页裁图 → 手工/AI 修改 → 重排 → Undo/Redo → PPTX 导出 → 刷新重开。**

阶段续跑、上一版恢复和离线/更新检查复用这个项目，在对应里程碑补上动作，不复制整条主链反复组合。已通过的阶段不因进入下一阶段而全部重跑；修改触及主链或最终发布时再运行相关检查。

发布前在已缓存应用中离线重开、查看 PDF、裁图和导出；检查应用更新只在已保存且空闲时由用户刷新。提示词随同一应用构建更新，沿用该项目核对续跑保留已完成产物、旧策略缺失时按架构规则提示并回退。实际 Pages 子路径上的刷新和依赖加载是发布检查的一部分，不另建托管平台测试体系。

导出的 PPTX 在可用的 PowerPoint 中打开检查文字可编辑、图像不拉伸、来源和主要几何可用；环境只有 Keynote 时使用它并如实记录，不要求两套办公软件同时验收。Edge 只简查入口、项目创建/打开和导出，不重复真实模型主链。

### 三篇论文的人工内容检查

保持机制、组学、临床/转化各一篇，主链论文就是其中之一。另两篇只检查生成内容与必要来源，复用已有结果；仅在相关生成逻辑改变或发现问题时重新生成，不对每篇重复全部编辑、恢复和离线操作。

人工关注研究问题、主要结论与图源是否对应，组别/物种/终点是否准确，是否夸大因果，图例及必要证据是否保留，故事是否连贯且图文可读。记录发现与修复即可，不建设评分平台或多模型对照矩阵。

提示词调整继续使用这三篇论文，仅复查受影响样例的叙事、证据取舍和用户要求是否落实；修改策略文件无需改代码即可在下次构建后的生成中生效。不为每个策略增加论文、端到端流程、Prompt 快照断言或自动模型评分。

可用本地样例或允许使用的公开论文；只按实际授权保存 PDF，不能把论文或 Key 自动打包进部署产物。
