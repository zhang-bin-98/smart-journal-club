# M7 — P1 可用性增强（条件触发）

> 状态：MVP 后可选。  
> 原则：只有真实用户行为证明现有模板 / 本地项目能力不足时才进入，不作为 M0–M6 的拖延理由。

---

## 1. 可能范围

按真实需求选择，不要求全部完成：

- Element Drag；
- Element Resize；
- ElementLayoutOverride；
- 更完整 Theme switch；
- Project Backup；
- Project Import；
- Outline View；
- Speaker Notes UI；
- 更丰富 Agent Revision Summary。

---

## 2. Drag / Resize 的触发条件

只有当 Beta / MVP 用户频繁遇到：

- Figure 无法通过现有 Layout 放到合理尺寸；
- 用户需要少量手工微调才能完成最终稿；
- “换 Layout”无法解决主要视觉问题；

才实现。

实现要求：

```text
用户操作
→ ElementLayoutOverride
→ Mutation
→ Validation
→ Undo
```

Agent 默认仍不输出自由坐标。

不要因此改造成完整 PowerPoint Clone。

---

## 3. Project Backup / Import

触发条件：

- 用户需要浏览器迁移；
- 清站点数据风险成为真实痛点；
- 需要跨设备手工搬运。

Backup 是 smartJC Project 数据，不是 PPTX。

最小 Bundle 可含：

```text
project metadata
paper.json
deck.json
figure refs
theme
必要 assets
original PDF（根据体积 / 用户选择决定）
```

导入必须验证 schemaVersion。

不建设云同步。

---

## 4. Theme

如果真实用户需要更多视觉差异：

- 保持少量白名单主题；
- Theme 改变只影响 presentation；
- 不重新生成科学内容；
- 不复制受版权保护的期刊 / 商业模板。

---

## 5. Outline / Notes

只有 Agent Chat 不足以满足导航时才增加 Outline View。

Speaker Notes 只在真实用户需要演讲辅助时实现。

这两者不得反向改变核心 Paper / Deck AST。

---

## 6. Definition of Done

M7 不设置“大而全”的完成标准。

每个被触发能力独立要求：

- [ ] 有真实用户问题作为输入；
- [ ] 有最小实现方案；
- [ ] 不破坏 M0–M6 已冻结契约；
- [ ] 直接相关测试通过；
- [ ] 不顺带建设通用编辑器 / 同步 / 插件平台。

---

## 7. 仍然不自动进入的方向

即使完成 M7，也不意味着需要建设：

- 通用 Agent Workbench；
- MCP；
- Plugin Marketplace；
- 云协作；
- PPTX Import；
- 多论文 Project；
- Review 工作流；
- 自定义 Provider 平台。

这些都必须重新以真实产品需求立项。
