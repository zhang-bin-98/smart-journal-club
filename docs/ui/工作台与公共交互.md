# 工作台与公共交互

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

### 3.1 工作台信息架构与操作层级

本轮 UI 按应用工作台重新设计。旧页面只作为功能清单和兼容依据，不沿用“大块卡片逐段向下排列”的页面结构，也不以改色、加边栏或限制网页高度作为重设计完成。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 项目列表  项目名     已保存          当前主操作 ▾   导出   ⋯       │
│ 论文分析      图源核对      大纲与演讲稿      幻灯片                            │
├──────────────┬──────────────────────────────────┬────────────────────┤
│ 对象导航     │ 视图工具栏                       │ 当前对象           │
│ 搜索 / 筛选  ├──────────────────────────────────┤ 属性 / 证据 / AI   │
│ 分组与对象   │                                  │                    │
│ 独立滚动     │ Figure 连续列表 / 章节 / 幻灯片   │ 按需展开           │
│              │                                  │ 独立滚动           │
│              ├──────────────────────────────────┤                    │
│              │ 当前页讲稿（仅幻灯片视图）       │                    │
├──────────────┴──────────────────────────────────┴────────────────────┤
│ 当前对象与进度       [展开 AI 输入]              查看任务详情        │
└──────────────────────────────────────────────────────────────────────┘
```

首页与工作台沿用 Hash 导航；首页项目列表正常滚动，工作台内部独立滚动。工作台有四个步骤视图，共用项目、任务、保存状态和对象定位。首次生成按步骤主动推进；已有产物的视图可以自由往返，不因浏览重新确认或重新生成。切换视图保留该视图的选择、滚动与缩放位置，不重跑阶段、不修改数据；从证据链接进入另一视图时显式定位对象并提供“返回刚才位置”。目标不存在时显示原因并保留原视图，不跳到错误对象。

| 操作层级 | 位置与规则 |
|---|---|
| 项目与导航 | 顶部第一行显示项目名、保存状态、阶段主操作、导出与更多；第二行四个视图作为一组水平居中，间距适度加大、左右留白；各页一致，不堆项目设置 |
| 阶段主操作 | 同时只有一个高强调阶段按钮；分析页就绪为“下一步：图源核对”，待核对为“确认切分并生成讲稿”，大纲页为“下一步：生成幻灯片”，暂停为“继续当前步骤”，失败为“重试当前部分”，完成后已有导出按钮提升为主操作，不再复制第二个导出按钮 |
| 当前对象工具 | 中央顶部工具栏提供修框/缩放、讲稿编辑或页编辑；Undo/Redo 显示对应编辑对象，生成按钮不埋进右侧面板 |
| 低频项目操作 | 更多菜单放重命名、汇报要求、整套重生成、恢复上一版、在新项目重新分析及模型设置；上下文只显示可用项 |
| 状态与 AI | 底部紧凑状态条显示阶段/对象与任务详情，暂停始终在顶部主操作位；AI 输入按需展开，工作台内固定占位，不能遮挡画布或复制第二输入框 |

运行时主操作位置显示当前步骤与“暂停”；“取消本次运行”在同处次级入口，保留完整成果。“暂停”和“取消”都立即终止当前请求，不伪装后台继续；放弃候选是单独操作。分析前“分析论文”可用；尚无产物的视图仍可打开，看见当前进度/原因和唯一返回入口，不展示空编辑表单。

分析完成后留在[论文分析页](论文分析.md)，必须用户点击“下一步：图源核对”；补选页待处理、保存失败或必要分析失败时不可进入。此动作仅切换就绪视图，不代表确认切分、不调用讲稿生成。必须用户整体确认一次，不要求每个 Panel 打勾；主按钮先完成待保存切分，再保存确认并生成大纲与讲稿，完成后停在讲稿工作台。用户主动进入幻灯片步骤后，系统再规划并制作页面；之后在幻灯片内编辑、检查并直接导出。编辑前立即暂停受影响任务，保存后由用户继续。首次完整稿保存后进入幻灯片；重生成则展示候选，不自动替换人工稿。

已有 Deck 时各视图明确显示“当前稿”或“待生成方案/工作底稿”。当前稿的大纲和讲稿直接对应现有页面；打开候选是显式切换，候选栏固定显示“返回当前稿 / 查看变化 / 应用 / 放弃”。旧稿可继续编辑，候选过期后禁用应用并解释原因，不能静默切换编辑对象。

#### 布局与视觉基准

桌面参考画布为 1440×900，顶部两行合计约 88px、折叠状态条约 32px 仅为布局示意，实际控件以可读与可操作为准，尺寸不进入业务模型。

本项目桌面优先，本版不设计响应式断点、自动抽屉或手机布局，不再增加窄屏/200% 缩放的适配验收。窗口变化沿桌面分栏分配可用空间，不根据宽度自动隐藏导航或辅助面板。键盘、焦点和可读字号仍须保持。

图源核对页已确认的布局为左导航固定 176px，中栏与右栏初始按剩余空间的 5∶4 分配。右侧分隔线支持拖动调宽、方向键微调、双击或 Home 恢复默认比例；宽度偏好可保留，收起再展开恢复调整结果。普通桌面窗口中栏至少保留 360px、右栏至少保留 300px；这是原型的布局约束，不是科学数据或业务字段。其他页面复用桌面外壳，但具体分栏比例以后续页面讨论为准。

外层不纵向滚动；目录、中央 Figure 连续列表/PDF/章节正文、Inspector 和讲稿分别拥有滚动。图源页左导航与工具栏固定，中间列表连续浏览；这不是把整个工作台堆成长网页。PDF 放大后允许其自身平移/滚动，缩放只改变查看比例，图像不拉伸。辅助面板主动收起，讲稿高度可拖动调整，展开 AI 输入不能挤没主要内容。

采用统一浅色应用主题：浅灰工作区、白色内容表面、细分隔线、一个主操作强调色；不以大标题、装饰卡片、渐变和营销说明占用编辑空间。正文保持正常可读字号，主要按钮有文字，图标按钮有 tooltip 与可访问名称。选中态、疑点、未保存状态同时有文字/形状区分，不仅靠颜色。危险的项目删除需确认；可撤销的常规删页/删框不反复弹窗。

键盘焦点清晰，Tab 可到导航、工具、对象与主操作；快捷键仅在对应编辑域生效，不劫持输入框、输入法或浏览器常用操作。来源对话框关闭后恢复原选择和焦点。长名称截断可查看完整值，不挤掉按钮。

#### 保存与状态反馈

图源拖框结束、标签编辑结束、文字编辑完成后自动保存，一次完整操作一次 Undo；拖动/输入中只显示即时草稿。按 Esc 取消尚未提交的拖动或编辑，已保存修改用 Undo 恢复。高级操作（恢复自动框、重新识别、AI 改写、替换当前稿）先展示候选，明确应用或取消，不因自动保存而静默覆盖。

顶栏持续显示“已保存 / 保存中 / 未保存”，失败保留草稿并给出“重试保存”；不要求每个框点一次保存按钮。切换内容域、导出或离开时先尝试完成保存；失败时留在原处，允许重试或明确放弃未保存修改。普通浏览不取消任务或扩大 AI 范围。设置缺失、资源失败在原操作位置给恢复入口，不把原始接口错误和领域字段交给用户。

#### 交互期间的加载与反馈

- 拖框时边界持续跟随当前操作，右侧使用已加载图像更新裁图预览；拖动期间不反复闪现整页加载、不逐帧保存。松手后自动保存，未完成时显示保存状态，失败保留最终框。
- 新页面/图片尚未就绪时立即更新选中态并显示对应对象的加载占位，工具和导航保持可操作；旧页面若暂留作过渡必须明确其身份，不作为新对象的可编辑内容。快速切换后旧加载结果不能跳回或覆盖当前选择。
- 缩略图与长目录按可见范围呈现，滚动保持位置和尺寸稳定；离屏预览不持续重绘，键盘定位和拖放仍能到达目标。讲稿输入不等待其他页面的缩略图或全稿检查完成。
- 分析、生成和导出期间，已保存成果仍可浏览，当前任务的暂停/取消入口保持可响应；有版本冲突的编辑沿原规则处理，不能以锁住整个界面代替任务隔离。加载时间与操作失去响应分别处理，不用循环动画掩盖持续阻塞。

本轮只定义交互行为及计算/资源约束，不新增专项性能测试、响应时间指标或硬件验收矩阵；具体运行策略见[图源与渲染](../architecture/图源与渲染.md)。

### 3.3 生成、取消与继续

```text
论文分析：全文解析 → Figure 定位与 Panel 切分 → 论文发现与证据整理
                                                ↓
                                      分析页就绪（用户点击下一步）
                                                ↓
                                      图源核对（整体确认）
                                                ↓
确认切分 → 生成大纲与讲稿 → 编辑讲述（停止自动推进）
                             ↓ 用户点击下一步
          幻灯片：页面规划 → 页面草案制作 → 编辑分页与图组
                             ↓ 用户在幻灯片内点击导出
                    自动校验当前稿 → 导出 PPTX
```

进度显示当前阶段、来源文件名称及文件内页码或 Figure、已完成/总数和分析/修复状态，不显示工具 JSON、隐藏推理、token 或逐 API 日志。已完成内容可查看，尚未完成的预览明确标识，不能伪装成正式成果。

步骤间由用户推进，步骤内可立即暂停/取消当前请求。暂停或取消保留最近完整阶段；运行中未提交部分不自动发布。恢复后按已保存的完整分析单元及完整讲稿/页面阶段恢复，只重做未完成或因编辑失效的部分，独立未受影响的论文解析、图源、讲稿及页面成果复用。关闭、刷新、浏览器终止可能中断任务；重开恢复完整阶段、已保存分析单元与最近位置，但不自动发送模型请求，由用户点击“继续”。不建设后台留守或任务队列。

模型格式、确定性引用登记、页面分配和布局问题由系统归一化、检查与有限修复，不能要求用户补 ID、来源数组、章节预算或空白页面来通过生成。失败提示在当前对象附近给出原因、保留成果及“重试当前部分”“模型设置”等操作；不能用静默删发现、漏图、缩小到不可读或放松来源校验来通过。无法确定的切分提示核对，无法确定的科学解释标待核查，缺材料明确说明。

取消与请求超时须独立退出等待，迟到响应不更新 UI 或保存成果。实际网络、认证、额度和资源失败保持可见；自动修复有次数上限，不无限重试。用户暂停后，后台不能自作主张续跑。

### 3.7 来源查看与两类裁图

论文图源核对与当前页裁图共用原 PDF、渲染与框选能力，但写入目标明确不同：

| 入口 | 修改对象 | 影响 |
|---|---|---|
| 图源核对 → 调整切分 | 工作底稿的 Figure/Panel 来源 | 用于后续理解、讲稿和规划；已有稿更新先展示影响 |
| 幻灯片 → 调整本页裁图 | 当前 Figure 元素的裁图覆盖值 | 只改变当前页当前元素，其他元素和论文图源不变 |

普通来源查看保留对话框：

```text
┌────────────────────────────────────────────────────┐
│ Fig. 3B · 原文第 8 页                        [关闭] │
│ PDF 原页：虚线为文稿绑定的图源框，实线为本页裁图    │
│ 标签 / caption / 对应原句                          │
│ [查看论文图源工作区]                  [调整本页裁图]│
└────────────────────────────────────────────────────┘
```

没有覆盖值时只显示一个框。文字来源无精确 bbox 时展示原页、原句或段落，不伪造高亮。大纲可查看来源并转到图源工作区，不能隐式把单页覆盖操作当成论文源修改。

本页裁图通过原页框选，提供“恢复默认范围”“取消”“应用到本页”。恢复只改待应用框，应用后一次保存与 Undo；取消不变，失败保留框供重试。默认范围来自该文稿绑定的论文版本；论文工作底稿更新不自动改变旧稿默认框。换图清除旧覆盖，换布局保留覆盖。

### 3.8 模型设置与公共状态

全局模型配置为独立页面，不占论文四步。具体字段、保存/清除/检查取消与来源恢复规则统一维护在[模型配置](模型配置.md)；[已确认 HTML 原型](../prototypes/model-settings.html) 展示 Responses API 配置。保存或返回恢复原页面，保留项目和新建草稿。

| 状态 | 展示位置与操作 |
|---|---|
| 保存中 / 未保存 | 编辑器顶栏；失败时显示原因与重试，不用 Toast 代替持续的未保存提示 |
| 无网络 / 缺 Key | AI 面板和生成入口提示；本地查看、手工编辑及资源完整时的导出仍可用 |
| 来源缺失 | 来源对话框说明受限原因；导出缺图时指出具体页并提供定位入口 |
| 导出中 / 失败 | 顶栏导出按钮显示进度并防重复点击，失败后可重试，当前 Deck 保留 |
| 可安装 / 可更新 | 首页和编辑器共用的应用提示区；安装仅在浏览器支持时出现，更新按[离线与更新规则](../product/保存与离线.md)等待保存和空闲 |

### 3.9 AI 行为

论文分析和图源核对只提供只读问答，不显示“修改”模式；图源调整使用手工控件或“重新识别当前 Figure”按钮，不接受自然语言修改。大纲与演讲稿、幻灯片支持用户显式选择“提问”或“修改”；修改先生成提案，一次请求统一预览、应用与撤销，不要求逐个修改确认。各页能力与提交对象统一见[页面 AI 契约](../architecture/编辑与Agent.md)。

AI 输入按需展开，范围标签使用当前页面的对象：分析页文件/原页、图源页 Figure/Panel、讲稿页段落/章节/全文、幻灯片页元素/页面/章节/整稿。发送前显示实际范围，请求发出后固定目标；滚动与选择不改变正在处理的对象。对话与提案共用一套 controller，右栏显示回复及目标定位；只读页面不展示空的提案操作。尚未实现的只读入口不作为已确认 HTML 现有能力。

以下修改示例仅适用于幻灯片页的修改模式；其他视图不得据此扩大权限。

| 用户请求 | 预期行为 |
|---|---|
| “解释这张图”“检查有没有逻辑问题” | 回答或给建议，不改 Deck |
| “第 7 页标题短一点” | 明确页码优先，只修改目标标题 |
| “这页太挤”“这张图大一点” | 使用当前选择，先调整布局或精简辅助文字，必要时拆页 |
| “背景压成一页” | 修改背景部分，保留研究问题，不顺便改结果页 |
| “Figure 3 只留 B 和 D” | 使用原论文 Figure/Panel 标识；通过两个独立元素组合，保留各自来源 |
| “整体压到 12 页”“全部改成中文” | 按明确范围批量修改，提供摘要，一次撤销 |
| “按刚才的建议修改” | 使用最近审核上下文；如目标已变化，则重新核对 |

明确目标高于 UI 选择；指代不明确时依次使用当前选择和近期上下文，仍有多个合理目标才询问。“这页”等指代在发送时按所在视图解析，不能将 PDF 页、讲稿段落与幻灯片编号混用；后续浏览不更换本次目标。

一次请求最多一个有效提案；提案先在工作副本模拟，显示受影响章节、讲述或页面与差异摘要，用户应用时重新校验版本、范围、引用、叙事与布局，成功后产生一次 Undo。取消、手工草稿、项目或所编辑 Plan/Deck 切换或版本变化使提案立即失效，不能提供“仍然应用”。取消、失败或旧响应均不留下半完成修改。手工修改是后续 AI 请求的新事实，AI 不得用旧上下文覆盖它。
