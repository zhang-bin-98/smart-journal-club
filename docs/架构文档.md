## 1. 技术边界与术语

应用是 GitHub Pages 上的静态 PWA，项目处理、存储、裁图与 PPTX 导出在浏览器执行，仅模型请求访问用户选择的供应商。沿用 React + TypeScript + Vite + Tailwind CSS、Zod、PDF.js、PptxGenJS、IndexedDB、Pi AI 与已接入的 pi-agent-core；安装版本以 lockfile 为准，不因设计更新更换栈。

### 领域术语

术语集中在本节，不另建重复的 CONTEXT.md 或领域定义文档。

| 术语 | 唯一含义 |
|---|---|
| Project | 一份固定 PDF 及其工作底稿、汇报与编辑成果的本地工作单元 |
| Paper / 论文底稿 | 文章本身的完整解析、图源、观察与发现；独立于汇报篇幅和 PPT 布局 |
| TextBlock | PDF 中可定位的正文、方法、图注、表格等文本块；完整文本的唯一内容载体 |
| SourceReference | 原 PDF 中可定位的文字片段或图源；页码与原始 bbox 的持有者 |
| Figure / Panel | 论文整图与带身份的子图；Panel 是保留必要科学标注的裁图，不要求互斥分区 |
| Claim / 研究发现 | 基于论文证据的发现或结论，保留科学强度；不与一张 PPT 或单个 Panel 一一对应 |
| Evidence / 证据 | 实验、观察或分析结果及原文/图源依据；通过来源关联多个片段或 Panel |
| Figure review / 图源核对 | 用户查看并修正自动切分、确认当前切分版本；不表示逐条科学事实已人工验证 |
| SpeechSegment / 讲述片段 | 有来源的讲稿内容单元；先组织讲述，再分配到页面 |
| DeckPlan | 可编辑的大纲、演讲稿与页面规划的统一工作产物；不要求每次人工确认才能推进 |
| Section | 单层叙事章节；kind 为内容职责，track 为主线或补充，与布局独立 |
| Deck / Slide | 已保存的演示文稿与单页；包含其最终结构、讲稿和绑定的论文依据 |
| RevisionProposal | AI 对已有成果的内存修改提案，应用后才提交 |
| ResearchStrategy | 可配置的研究讲述建议，不是研究类型枚举或独立生成流程 |
| Revision | 一次逻辑编辑后的版本；批量修改原子提交，对应一次 Undo |
| Checkpoint | 已完整持久化的阶段产物，不是实时进度、用户授权或后台任务 |
| Current / Working / Previous | 当前稿、未替换当前稿的工作产物、唯一上一版；不存在版本树 |

### 运行与界面边界

固定解析、切分、全文理解、大纲与演讲稿、页面规划、制作与导出使用显式 workflow。交互式问答与修改使用 pi-agent-core 的 Agent、事件、工具和取消能力；不自维护第二套通用循环，不用自由 Agent loop 代替阶段编排。

UI → application/service → domain/schema；repository、LLM、PDF、export adapter 由应用用例组合。组件及 Agent tool 不直接读写 IndexedDB，领域函数不依赖 React、DOM、PDF.js、Pi 或 PptxGenJS。不建立通用事件总线、DI 容器、CQRS、注册中心或插件平台。

统一工作台外壳约束为可用窗口高度（如 h-dvh），外层 overflow-hidden；子区通过 min-h-0/min-w-0 与明确的滚动所有者分配空间。顶栏与命令区固定占位，目录、PDF、Inspector 和讲稿各自滚动，Canvas 根据剩余空间计算缩放。避免 min-h-screen 加上外部导航、固定最小画布和长表单造成整页滚动。保留键盘焦点可见、抽屉关闭返回焦点和窄窗口操作入口；不以隐藏内容或强制页面缩放通过验收。

界面使用 Tailwind CSS 4 完整工具类；公共主题在 src/style.css 的 @theme，控件共享样式。style.css 只保留 Tailwind 导入、主题及必要全局规则，不用成片 @apply 或组件 CSS 再建体系。运行时 PDF/Slide 几何用内联 style 或 CSS 变量传入，字体按画布比例变化。统一浅色主题，设置对话框与 Hash 导航继续使用。

组件只组合 UI；异步业务在 service/controller hook，不在 render/effect 动态 import 核心业务。选中项、面板、未提交输入归组件；已保存数据由领域提交入口持有。文字编辑使用稳定 ID，保留光标、焦点、换行和输入法，编辑结束一次保存，不逐按键写历史。挂载、重渲染与清理不能重复创建会话、PDF 资源或提交。AI 右侧对话与底部输入共享同一 controller、任务及提案，无第二输入或 Agent。

### 模块职责

M8 的模块化已完成，当前入口为 src/main.tsx；本表是 v0.5 职责安排，不代表新文件已存在，不预建空壳。

| 位置 | 职责 |
|---|---|
| src/app / src/ui/project | 工作台外壳、视图与用例组合、恢复、阶段进度及暂停 |
| src/modules/paper | 全文块、Figure/Panel、证据、切分修正、核对版本、论文 repository 与 UI |
| src/modules/outline | 大纲、讲稿与页面规划、OutlineSession、计划 repository、叙事/覆盖检查与 UI |
| src/modules/generation | 论文准备、讲述规划、页面规划、Build 的单一 workflow，任务与候选提交 |
| src/modules/deck | DeckSession、页面/讲稿修改、共享布局、来源快照绑定与导出 |
| src/modules/assistant | 目标解析、读工具、Agent runtime、受控提案与应用 |
| src/shared | PDF/模型/存储/错误等实际公共适配器与几何基础 |
| prompts | 公共规则、研究策略、实际阶段提示词；不承载数据协议和事务 |

跨模块经过公开入口。Paper 不反向依赖 Outline/Deck；Outline 可使用 Deck 的公开页面结构，Deck 不反向依赖 Outline，由应用组合构建契约与叙事检查。演讲稿随当前真实职责放在 outline/deck，不预建独立服务平台。

Paper 的图源编辑、OutlineSession、DeckSession 各有唯一内容提交入口，repository 封装数据库映射和原子事务。不复用 DeckMutation 直接修改论文，不把业务事务放 UI/tool。预览与导出共用布局，layout 不依赖 UI 或导出库。

一行一个主要动作；超过 5–6 个参数使用具名对象，Query 无副作用，Command 命名体现写入；关键不变量与失败语义写短 JSDoc。三种以上职责混杂或难独立验证才拆文件，不设机械 LOC 目标。沿用已安装的单一格式/lint 工具与轻量测试；不用额外框架、覆盖率目标或无关格式化扩大本轮。

## 2. 唯一数据契约

以下是 v0.5 的目标领域形状，尚未改动运行代码。实际实现以唯一 Zod Schema 派生类型与工具参数；这里只定义职责与必要字段，不维护第二套运行协议。Project/Paper 目标 schemaVersion=2，DeckPlan/Deck=3，PlanRecord recordVersion=2；数据库版本与对象版本分开，迁移见第 4 节。

ID 稳定且不含位置含义；PDF 页码从 1 开始，Slide 序号仅用于展示。新增/重排不重建既有身份；revision 单调递增，时间为毫秒，写入身份和基准由应用控制，模型不能分配持久化权限。

### 项目、全文与来源

```ts
type BBox = { x: number; y: number; width: number; height: number };
type Checkpoint =
  | "project-created" | "pdf-parsed" | "figures-ready" | "paper-ready"
  | "outline-ready" | "deck-plan-ready" | "deck-ready";
type Preferences = {
  instruction: string;
  language?: string;
  targetSlides?: number;
  strategyId?: string;
};
type PauseAfter = "outline" | "plan";
interface Project {
  schemaVersion: 2;
  id: string; name: string; nameIsCustom?: boolean;
  paperId: string; pdfAssetId: string;
  currentDeckId?: string; previousDeckId?: string;
  checkpoint: Checkpoint;
  preferences: Preferences;
  pauseAfter: PauseAfter[];
  lastOpenedSlideId?: string;
  createdAt: number; updatedAt: number;
}
interface TextBlock {
  id: string;
  pageNumber: number;
  kind: "heading" | "paragraph" | "caption" | "table" | "other";
  text: string;
}
interface SourceReference {
  id: string;
  kind: "text" | "figure" | "panel" | "caption";
  pageNumber: number;
  bbox?: BBox;
  textSpan?: { blockId: string; start: number; end: number };
  textQuote?: string;
  geometryOrigin?: "automatic" | "manual";
}
interface FigurePanel {
  id: string; label?: string; sourceId: string; description?: string;
  labelOrigin?: "automatic" | "manual";
}
interface FigureRef {
  id: string; label?: string; caption?: string;
  sourceId: string; description?: string; panels: FigurePanel[];
}
```

Project.paperId 指向当前工作底稿，Deck.paperId 指向该稿的证据版本；两者在编辑上游期间可不同，但必须属于同一 Project 和固定 PDF。Project 名称独立于原标题；用户重命名同事务设置 nameIsCustom，后续自动补标题不得覆盖。

全文以 TextBlock 为唯一文本载体，按原页保存阅读顺序、标题、段落、图注与表格内容，不只保留摘要。页记录保留尺寸和 blockIds，不再维护可独立修改的第二份 page.text。原句通过 blockId 与字符串区间定位，start/end 采用 JavaScript UTF-16 半开区间；需非空、不越块且页码一致。跨段/跨页句子使用多个 Source，不把不同页拼为虚假单页来源。textQuote 若存在必须对应原文片段；旧稿只有页级短引用时可保留并明确精度，不编造字符级几何。

Figure/Panel 通过 SourceReference 持有页码和 bbox，不复制坐标。BBox 基于 PDF.js 应用原页旋转后的整页，左上为原点、归一化 x/y/width/height；所有值有限、宽高大于零、起点在页内且终点不越页。局部高清图中的像素框须经同一几何函数映射回整页，不能把 Figure 局部坐标当页坐标。图源必须有 bbox，Panel 与 Figure 同页且范围包含于整图可读范围；手工调整导致冲突时以可视化方式修正/扩展整图，不静默切掉 Panel。

共享图例允许 Panel bbox 相交；不得以零重叠、L 形归属或矩形网格作为科学正确性的硬规则。保留原像素，不引入擦除、mask 或多边形输出契约。

### 论文底稿与证据关系

```ts
type ClaimStrength = "descriptive" | "associative" | "supportive" | "causal";
interface Claim {
  id: string; text: string; strength: ClaimStrength;
  importance: "primary" | "secondary"; evidenceIds: string[];
}
interface Evidence {
  id: string; kind: string; summary: string; sourceIds: string[];
}
interface StoryPoint { text: string; claimIds: string[]; sourceIds: string[] }
type StoryTopic = "background" | "knowledgeGap" | "question" | "studyDesign"
  | "mainFindings" | "novelty" | "limitations" | "conclusion";
interface FigureSourceSnapshot {
  figures: FigureRef[];
  sources: SourceReference[];
}
interface FigureReview {
  revision: number;
  confirmedRevision?: number;
  confirmedAt?: number;
  automaticBaseline?: FigureSourceSnapshot;
}
interface Paper {
  schemaVersion: 2;
  id: string; projectId: string; pdfAssetId: string; revision: number;
  metadata: { title?: string; authors?: string[]; journal?: string; year?: number; doi?: string };
  pages: { pageNumber: number; width: number; height: number; blockIds: string[] }[];
  blocks: TextBlock[];
  sources: SourceReference[];
  figures: FigureRef[];
  figureReview: FigureReview;
  pendingEvidenceFigureIds: string[];
  studyProfile?: { type: string; designSummary: string; sourceIds: string[] };
  story?: Record<StoryTopic, StoryPoint[]>;
  claims: Claim[];
  evidences: Evidence[];
}
```

Claim → Evidence → Source 是唯一持久化方向；Source 可定位原文、图注或 Panel。一个 Evidence 可关联多个来源，多个 Claim 可共用 Evidence；反向“这句/这个 Panel 属于哪个发现”由查询计算，不再重复存反向列表。对每个可提取发现保留观察、关键实验条件及来源，区分作者观察、解释与可支持强度。字段合法不代表科学解释真实。

Paper 不含 slideBudget、讲稿或主线/补充标签。研究类型是事实描述，不是路由枚举；汇报重点、时长或页数不得减少全文提取。策略在已有理解调用中选取默认建议，无法确定时 general，不能改变论文事实或支持范围。故事点是文章组织，不规定 PPT 顺序；无依据主题为空，遗漏或不确定关联给出可定位问题。

分析由全文解析、整图/Panel 处理和基于原文的证据整理组成，模型临时输出先校验再由应用映射 ID。不以 Figure 图形描述独立推断结果方向。下游上下文按 Claim/Evidence 取回原文片段、图注和所选裁图，必要时带相关段落；不能只传压缩摘要，也不默认传全篇 PDF。不引入向量数据库作为单篇论文的前置条件。

figureReview.revision 只随切分身份、标签、几何变化增加；确认绑定该 revision，两项确认字段同时存在且匹配才有效。科学关联重算增加 Paper.revision，但不冒充用户重新确认几何。pendingEvidenceFigureIds 保存因补删/改标签而需刷新关联的 Figure，保存与取消可恢复；只是边界变化且身份不变时无需重算科学解释。系统完成相应原文/证据整理后同事务清除标记，未完成前不能把旧关联用于新的规划。无依据的关系可保留明确缺口，不伪造完成；模型请求失败则继续保留待处理标记。确认只表示切分经过用户核对，不能命名为“论文事实已验证”。

automaticBaseline 保存当前完整自动识别的图身份与图源快照，仅用于“恢复自动结果”，不是第二个可写来源；不包含全文或模型响应。geometryOrigin/labelOrigin 用于保护人工调整，不表示科研置信度。重新识别候选暂不改 baseline 或人工结果，用户明确应用后才更新相应基线与当前来源。

### 大纲、演讲稿与文稿

```ts
type LayoutId = "title" | "text-only" | "figure-full" | "figure-text" | "two-figures" | "panel-grid";
type SlideKind = "title" | "background" | "question" | "method" | "result"
  | "summary" | "discussion" | "conclusion" | "custom";
type SectionKind = "opening" | "background" | "question" | "study-design"
  | "results" | "synthesis" | "limitations" | "takeaways" | "discussion" | "custom";
type ContentTrack = "main" | "supplement";
interface DeckSection {
  id: string; kind: SectionKind; track: ContentTrack;
  title: string; purpose: string; transitionToNext?: string;
}
interface PlannedFigure { figureId: string; panelId?: string }
interface SpeechSegment {
  id: string; sectionId: string;
  purpose: string; text: string;
  claimIds: string[]; sourceIds: string[];
}
interface PlannedSlide {
  id: string; sectionId: string; kind: SlideKind;
  title: string; purpose: string; message: string;
  layoutId: LayoutId; speechIds: string[];
  claimIds: string[]; sourceIds: string[]; figures: PlannedFigure[];
}
type SlideElement =
  | { id: string; type: "text"; text: string }
  | { id: string; type: "bullet-list"; items: string[] }
  | { id: string; type: "figure"; figureId: string; panelId?: string; cropOverride?: BBox }
  | { id: string; type: "citation"; sourceIds: string[] };
interface Slide {
  id: string; sectionId: string; kind: SlideKind; title: string;
  purpose?: string; message?: string; layoutId: LayoutId;
  speechIds: string[]; elements: SlideElement[];
  claimIds: string[]; sourceIds: string[];
}
interface CoverageOmission {
  claimId: string;
  reason: string;
  origin: "user";
}
interface DeckPlan {
  schemaVersion: 3;
  id: string; paperId: string; paperRevision: number;
  revision: number; status: "draft" | "ready";
  title: string; language: string;
  sections: DeckSection[]; speech: SpeechSegment[];
  slides: PlannedSlide[]; omissions: CoverageOmission[];
  createdAt: number; updatedAt: number;
}
interface Deck {
  schemaVersion: 3;
  id: string; paperId: string; paperRevision: number; revision: number;
  title: string; language: string;
  sections: DeckSection[]; speech: SpeechSegment[]; slides: Slide[];
  omissions: CoverageOmission[];
  createdAt: number; updatedAt: number;
}
```

sections 定义章节顺序，slides 定义页序，每页必须归属有效章节，章内连续。track 与 kind 独立，主线先形成完整故事，补充默认置后；编辑可调序或移动到主线。Claim 的主线/补充归属从引用它的章节推导，不能重复维护互相冲突的分类字段。

大纲与演讲稿先生成，页面规划随后分配。一个讲述段落可以在规划时拆成多个 SpeechSegment 跨页讲述；最终每个 segment 只分配给一页，一页可包含多个 segment，同属该页章节。对于一段对应多页，先按完整句意拆片段并保留原文/Claim 引用，再分配，不重复整段备注。讲稿文本只存 speech，不在 Slide 或导出 notes 再维护一份可编辑副本；本页讲稿按 speechIds 组合，写入 PPTX 备注时派生。拆段、更改分配、移动页面同时维护章节和来源，作为同一 revision。

outline-ready 表示章节与完整讲稿已保存，slides 可为空；deck-plan-ready 表示页面已分配，所有需要讲述的片段均有有效页面。draft 可以保留未完成的讲述/页面分配；ready 是应用校验完成的构建就绪状态，不是人工确认，模型不能自行设置。用户编辑 ready 后回到 draft，自动流程重新验证就绪；没有 confirmed/confirmedAt 或确认大纲门槛。

目的、take-home 与讲稿职责不同：purpose 解释页的作用，message 是屏幕 take-home，speech 承担完整口头表达，不用章节目的冒充讲稿。旧稿和手工空页可以无讲稿，不能迁移时编造；自动新稿的内容页须有相关讲述与来源。

默认覆盖 Paper.claims 的全部发现，允许在主线或补充表达，不以数量凑页。人工省略或用户明确压缩所需的省略写入 omissions，原因与来源于用户的要求可核对；模型自动漏掉的 Claim 不能伪造成 user omission。没有固定默认页数范围，targetSlides 仅表达用户要求，实际页数由 slides.length 派生；移除双重 slideBudget 维护和 focus 至少两页规则。

已选 Figure/Panel 来源由应用解析并自动合入有效来源集合；用户不维护引用登记。页面 Claim/Evidence 与图源应相符，不能以补全 ID 代替科学对应检查。计划与最终稿都保留 coverage 和讲稿，Deck 成功提交后由 Deck 承接最终结构，工作计划可消费删除。

每个 Figure 元素仅引用一个整图或一个 Panel，多图使用多个元素。panelId 必须属于 figureId；来源来自本稿绑定 Paper。cropOverride 是整页坐标，仅覆盖当前元素，换引用清除覆盖，换布局保留。所有新对象严格白名单，不预留任意坐标、themeId、脚本或通用 JSON Patch。

## 3. PDF、切分、布局与 PPTX

### 图切分与人工修正

切分借鉴 [split-multipanel-figure](https://github.com/Genesi599/split-multipanel-figure) 的标签锚点、内容块与间隙分析思路，不将其 README 的效果声明视为已验证能力，也不直接移植其 Python/SciPy、全图标签检测、固定阈值、L 形归属或遮罩输出。

1. PDF.js 解析全文、图注与页面图像信息，综合定位整图；不能仅以某一种 Fig. 标点正则决定是否存在图。参考文献或正文提到别页 Figure 不等于本页图源。
2. 在完整 Figure 的局部高清图上识别标签、内容关系与粗框；整图原始像素始终保留；对照图注中的实际标签检查漏识别，不按空间顺序补造标签。PDF 图像矩阵可能漏矢量标签，作为参考而非完整图边界。
3. 在粗框及标签邻域，用 Canvas ImageData 的颜色内容、连通内容与间隙提出有限边界调整；考虑浅色和灰色信息，不强制所有图适用同一阈值。
4. 检查空框、越界、漏/重复标签、边缘穿过密集内容和疑似串图；几何合法与科学完整分开。重叠不是硬错误，低把握不自动批准，也不靠删掉难切 Panel 掩盖。
5. 将自动结果提交为可核对来源，用户直接改框、补删 Panel 或更正标签。无清晰标签的图保留整图与疑点，不编造 A/B/C。共享标注难以独立矩形裁出时可组合展示或保留整图。

坐标运算统一使用原页旋转后的基准；局部放大倍率与窗口缩放不改变持久化坐标，最终导出从 PDF 重裁，不使用被压缩的预览截图。只在必要 Figure/页渲染，任务结束释放 Canvas 和 URL；不引入长期位图库。

图源编辑先在 working copy 模拟，再通过 paper service 的唯一提交入口核对 Paper ID/revision、figureReview.revision、PDF 归属、有效任务与引用。移动/缩放、更名、补删、恢复基线均为显式 mutation；保存成功才更新内存与 Undo。保存失败保留输入，取消不写入。删除来源同时处理 Evidence/Story 的该来源关联，保留原文事实及其他证据，缺失关系由系统重算/标疑点，不能写悬空 ID。

几何或标签改变会立即使旧核对失效，增加图核对 revision；相关语义待更新但未变的图不需重新切分。新增 Panel 的原句/发现由系统补充，不把手动补框变成领域数据录入。整图框调整与 Panel 归属冲突须显示影响，不能偷偷移动其它框。

重新识别仅作用于用户指定 Figure，保留原人工结果，显示自动候选供比较和应用；恢复基线也先进入草稿。只维护一份基线和一个当前候选，不保留识别历史树。人工框不被重试、换模型或全篇重新分析自动覆盖。

### 共享几何与导出

PDF 页尺寸使用 scale=1 且应用原页旋转的 viewport。布局输入为 Slide、固定主题与图像宽高比，输出统一 ComputedSlideLayout，含标题、元素、来源与文字排版参数；预览转换成显示尺寸，PptxGenJS 转成 PPT 单位，两端不各算一次布局。

保留白底、16:9 与六布局：标题、文字、一个大图、图文、双图、3–4 Panel 网格。1–2 Panel 使用单图或双图；超过容量先调整规划或拆页，不藏元素。图片等比 contain，不用 cover 截证据；同一来源的页码标签去重，显式 Citation 优先于自动脚注。

布局容量保持现有可验证边界，Citation 最多一个并与自动来源脚注去重：

| layoutId | 图与正文容量（不计 Citation） |
|---|---|
| title | 无图，最多一个副标题 text |
| text-only | 无图，最多四个 text / bullet-list |
| figure-full | 一个 Figure，无额外正文 |
| figure-text | 一个 Figure，最多两个短 text / bullet-list |
| two-figures | 两个 Figure，无额外正文 |
| panel-grid | 三至四个 Figure，无额外正文 |

删除元素后仅在布局不再适用时回退：无图 text-only；一图有辅助文字 figure-text，否则 figure-full；两图 two-figures。回退是同批修改，保留仍引用的来源与 cropOverride。手工空页可保存，不通过占位内容伪造证据。

标题、正文采用统一主题与最小可读字号，超预算优先减少非核心屏幕文字、利用讲稿、换布局或拆页，不能无限缩小字体。检查不承诺 Web 与 PowerPoint 像素相同；科研图像不重绘。

顶栏和检查视图调用同一个只读导出用例：先保存输入，捕获 Deck ID/revision、绑定的 Paper ID/revision、完整讲稿与裁图快照，检查非零页、结构引用、布局及必要资源；启动前版本改变须重查，启动后不混入新编辑。必需图片全部按此快照裁出，任何必需资源失败就停止，不下载部分文件。

PPTX 中标题/正文为原生可编辑文字，图像可移动缩放，讲稿按 speechIds 写入对应页讲者备注。备注序列按页面顺序和片段顺序导出，不混入未分配段落。notes 由当前讲稿派生，不持久化第二份文本。旧稿没有讲稿不妨碍按原稿导出。导出进度、防重复点击、失败重试和 URL 释放由同一用例管理；项目关闭/删除使任务失效，普通编辑仅影响下一次导出。

## 4. 存储、生成与迁移

继续使用 smartJC 命名空间的一个 IndexedDB、七个 store；通过显式 repository 事务维护，不引入通用持久化框架。

| Store | 内容 |
|---|---|
| projects | Project、当前工作底稿指针与最近位置 |
| papers | 工作 Paper 与 Current/Previous/有效计划仍引用的不可变 Paper |
| assets | 固定原 PDF Blob，同项目底稿版本复用同一资源 |
| plans | 按 projectId 唯一工作 PlanRecord，保存大纲/讲稿/页面规划及基准 |
| decks | 当前稿与唯一上一版，包含讲稿与论文绑定 |
| history | 有限可见消息和已提交摘要，不存模型隐藏推理或撤销快照 |
| settings | 独立模型配置与 Key |

页面、缩略图、裁图和 URL 仅有限内存缓存，键包含 Paper 身份/版本、来源、有效框和渲染尺寸，不能复用旧框。Undo/Redo 各最多 20 个内容快照，可见历史最多 100 条；不把这些上限写进领域对象。

创建项目、空 Paper 与原 PDF 同事务，失败不留下半项目。删除同时删除所有本项目工作/保留 Paper、计划、Deck、PDF 与历史，不删 settings。Paper 回收只在成功提交后的同一项目内，保留 Project.paperId、Current/Previous.paperId 和有效 PlanRecord 引用的全部底稿，拒绝跨项目或按猜测删除；不持久化论文版本树。

### 阶段与自动推进

| Checkpoint | 完整保存的产物 | 默认下一动作 |
|---|---|---|
| project-created | 项目、PDF、空 Paper | 解析全文 |
| pdf-parsed | 页、TextBlock、文字来源 | 分析 Figure/Panel |
| figures-ready | 完整自动图源与恢复基线 | 整理全文发现与证据 |
| paper-ready | 论文底稿、核对版本及关联状态 | 图切分待核对时暂停；确认后可连续生成 |
| outline-ready | 章节、主线/补充、大纲与完整演讲稿 | 未选 outline 暂停则继续页面规划 |
| deck-plan-ready | 已分配讲稿、图证据和布局的计划 | 未选 plan 暂停则校验 ready 后 Build |
| deck-ready | 完整 Deck、讲稿和冻结论文绑定 | 编辑/导出；候选更新不覆盖 Current |

checkpoint 记录完整产物，不等于核对确认或任务继续权限。已有 Deck 时 checkpoint 可维持 deck-ready，新的工作底稿/候选进度由各自记录表示，不能隐藏旧稿；不能只比较枚举大小来决定是否允许继续。

用例组合：preparePaper() 负责准备与必要关联刷新，confirmFigureReview() 保存用户核对，generatePresentation() 在一次用户启动后依次调用 prepareOutline()（大纲+讲稿）、planSlides()、buildPresentation()。首次与重生成共享这些步骤，不另建第二条 pipeline。名字为目标职责，实施时复用现有 generation 模块，不预建空接口。

图核对是唯一默认人工门槛。pauseAfter 记录用户选择，独立于产物 checkpoint；模型不得更改。阶段完成后检查暂停选择再进入下一阶段；用户可立即 abort，清除运行权限但保留完整阶段。编辑开始暂停依赖它的任务，完成保存后由用户继续；刷新恢复产物与暂停选项但不自动调用模型。用户选择继续只授权当前请求链，旧响应不能沿用新任务授权。

Plan ready 是程序校验，不得伪造为 user confirmed。生成前保存并绑定稳定计划 ID/revision、Paper ID/revision、核对版本、偏好及有效任务。模型仅填充计划允许的内容；构建严格遵守其页面身份、顺序、图源、讲稿分配和结构。布局或结构需改变时返回内部规划步骤形成新 revision 后再 build；有人工修改时先提出变化，不让用户修格式，也不绕过计划合同。

格式/结构、唯一明确的图标签映射和可派生来源由程序处理；需要模型修复时每个失败分析单元/讲述或页面单元最多一次定向 repair，携带相同原文/图像与诊断。认证、额度、网络、截断、取消与超时不自动重试。仍失败时保存已有完整成果，报告具体单元、原因类别和重试入口；不得用空计划、丢发现、丢 Panel 或放宽验证当成功。艺术/科学判断不给任意代码修复器。

每个请求保留现有 180 秒独立等待预算，覆盖 SDK 加载、流迭代与最终结果；取消和超时不能依赖底层结束才能退出。进度包含原页/Figure/讲述或页面单元与已完成数，迟到回调检查有效任务。所有计算、网络和渲染在事务之外，提交事务内重读项目、前置产物、版本与任务。任务取消且事务未完成时 abort；已经提交的成果如实保留。

内部可按页/小批完成制作，只有完整有效的计划或 Deck 才推进对应 checkpoint；不增加 UI-only checkpoint，不保存半条模型输出。局部重试复用同一任务内已完成工作，跨刷新保证最近完整阶段恢复；不承诺尚未持久化的单页结果跨刷新续跑。

### 基准、工作底稿与候选

```ts
interface PlanRecord {
  recordVersion: 2;
  projectId: string;
  stage: "outline-ready" | "deck-plan-ready";
  plan: DeckPlan;
  preferences: Preferences;
  mode: "initial" | "regeneration";
  base: {
    paperId: string;
    paperRevision: number;
    figureReviewRevision: number;
    current?: { deckId: string; revision: number };
    previous?: { deckId: string; revision: number };
  };
}
```

每项目一份计划，开始时捕获基准，保存/编辑/ready/Build/应用各环节重查；initial 不带 current/previous，regeneration 必带 current，previous 只在实际存在时成对记录。当前稿正常编辑后旧候选不可应用，不能自动重绑定到新基准。候选可查看或丢弃后重新生成，保存失败不清空最后完整计划。

Paper 被 Current/Previous 引用后冻结。再次源级编辑或必要局部关联刷新时先复制为新 ID 的工作 Paper，保留来源/图/Claim 的局部身份与固定 PDF，Project.paperId 指向工作底稿；旧稿继续按自己的 Paper ID/revision 读取。未被文稿引用的工作 Paper 可以在单一提交入口原地增加 revision。新稿成功保存时冻结其基准 Paper，禁止修改已经被文稿引用的底稿。纯单页裁图仍是 Deck 的 cropOverride，不复制 Paper。

只改边框：使核对失效、清理相应图像缓存，标记使用该图的计划/页面需更新；不重做全文。补删或改标签：还需重新核对该图的原文/发现关联，保留无关事实。重新解释 Claim：重算引用该 Claim 的讲述和页面。改讲稿：只重做关联页面/过渡；删页：维护讲稿分配与章节，不删除底稿。依赖根据稳定 ID 与引用现场计算，不建通用任务图或持久化第二套问题表。

全局主题/语言/主线重排可以影响整套，但必须显示实际范围。基准变化让旧任务整体失效是并发保护，不意味着重算所有未变内容；新任务可复用已验证且不受影响的产物。已有人工内容的覆盖、删改和候选应用必须可预览并显式应用。

全篇重新分析保留独立新项目入口，复制本地 PDF 与可复用的解析/图源，不继承旧科学解释为新结论，也不标作已核对的新结果；原项目完整保留。源级小调整在本项目工作底稿完成，不要求为每次拖框新建项目。

### 迁移与兼容

v0.3 Deck/Plan v1 仍先使用 M9 已验证的迁移路径；历史 M9 语义以工作记录为准。v0.5 再显式迁移 Project/Paper v1→v2、Deck/Plan v2→v3 与 PlanRecord v1→v2，不能只改类型后强转旧记录。

- 保留所有既有 ID、顺序、标题、元素、来源、图框、cropOverride、Current/Previous 指针和科学内容。页级原文转为带稳定 ID 的块，旧来源保留精度；不猜原句范围、Panel 标签、讲稿或主线取舍。
- 旧 Deck 缺讲稿时 speech/speechIds 为空；旧章节默认 main，明确未做补充分组，不从关键词推测。旧稿可查看编辑并按原内容导出，不因新自动生成要求被锁住。
- 旧计划保留人工内容并转 draft，移除预算确认门槛；旧 confirmed 不能视为已核对图源，也不自动赋予新生成权限。新讲稿和覆盖检查需用户启动后生成，不在迁移中调用模型。
- 旧 Paper 的图核对状态为未核对，现有图框保留；不把它标为已验证的新算法结果。没有自动基线时“恢复自动结果”不可用，不能拿用户旧框伪装自动结果。
- 迁移先在内存转换并校验，再事务重读基准一致性、原子写入。已升级读取幂等，不生成新身份；Unknown version、损坏引用或写入失败保留原数据，提示恢复，不清空数据库。
- 无法迁移临时计划时保留原记录供恢复，允许显式重新规划；稳定 PDF/Paper/Deck 不丢失。七个 store 无结构变化时不因对象升版而机械提升 IndexedDB 版本；确有存储结构变化才升级并处理旧标签页阻塞。
- Current/Previous 引用的旧 Paper 均冻结可追溯；复制工作底稿、应用更新、恢复上一版与回收必须作为同一数据生命周期验收，不用忽略旧版绑定来减小实现量。

## 5. 修改、撤销与版本

### 内容提交与同步

论文、计划、文稿各自使用显式 mutation 与唯一提交入口，白名单决定范围；UI 只提出命令。请求包含 requestId、projectId、目标 ID/baseRevision 与有效任务。先在内存副本应用整批，验证结构/引用/范围/依赖，再在事务重读基准并一次写入数据与摘要，成功才推进内存、版本与历史。重复 requestId 拒绝。

计划编辑支持章节/讲述片段/页面的新增、更新、删除、重排及主线/补充调整，不保留 set-slide-budget 命令。移动章节带其页面与讲稿，跨章移动页面同时迁移相关片段；同批删除空章，禁止悬空 sectionId/speechIds。页间顺序由稳定锚点表示，null 为目标章首，拒绝不存在目标、自身后移或超范围变更。

正文手动删除与编辑不因比例、顺序等叙事建议被阻断；去掉页面同步去掉只属于该页的讲稿分配，论文发现保留，省略作为用户操作记录。纯过渡/空页不伪造 Claim，结果页仍不能引用不存在的证据。需要模型改写过渡或更新图文时先形成候选差异；新内容不会静默替换用户写过的文字或框。

应用与提案模拟复用相同验证；冲突、取消、并发和写入失败不推进 Current、revision、Undo 或历史。草稿第一次出现就使会覆盖它的任务失效，不等保存时才比较版本。未保存草稿阻止其他写入、导出和离开，保存失败保留输入；纯浏览不属于修改。

### 交互式 Agent

继续使用 pi-agent-core 现有 Agent、事件和 abort/hook 能力，实际 API 以 M10 锁定版本与实现为准，不重新编写通用 turn loop。提问只注册读工具；修改模式额外注册受控 proposal 工具。固定生成的首次内容创作由 workflow 授权，不能与“改写已有成果须应用提案”混为每页都要确认。

Deck 修改沿用 deck_propose_revision，扩展实际需要的讲稿/分配白名单；图源拖框通过 paper service，不能让 Deck tool 越权改 Paper。若图源需要模型重识别，使用显式 workflow 的当前 Figure 候选入口，不注册任意文件、bash、代码执行或通用 MCP 工具。

读工具保留 paper_get_overview、paper_get_claims、paper_get_figure、outline_get_structure、deck_get_slides；逐步纳入当前任务的原文片段和讲稿查询职责，参数从实际 Schema 派生。作用于旧稿时读取其绑定 Paper，不能混用当前工作底稿。工具不直接访问 IndexedDB 或承载事务。

明确目标 > UI 选择 > 近期上下文；“这页”绑定当前 slideId，多处 Figure 无法消歧才询问。section scope 展开为请求时的页面集合，新增内容不超出该章；讲稿 scope 跟随稳定片段/页面。只有全局请求带完整 Deck，普通局部请求带必要相邻页、讲稿与原文证据。

一次请求最多一个有效提案，写意图顺序执行，模拟后显示影响页/片段、差异和应用/放弃；应用时再次核对版本和范围。取消、Agent 后续失败、手工草稿、项目/Deck 切换使提案失效，不提供强制应用。每次应用是一条 RevisionRecord 和一次 Undo。

事件映射为可读进度，右侧显示对话/提案，底部输入共享同一状态；不显示隐藏推理、原始 JSON、provider 错误体或 Key。仅有限可见消息与已提交摘要持久化，刷新不恢复待应用权限。有限轮次/工具/上下文预算使用 runtime 的已有 hook，不建设 Node/SQLite backend。

### Undo/Redo 与 Current/Previous

各会话快照只存该内容域的必要数据，不含运行权限、旧 revision、原 PDF 或位图。Undo 恢复内容而 revision 递增；图源 Undo 也使核对失效，计划 Undo 回 draft。图源确认动作不作为可以恢复的生成授权。Undo 后新编辑清空 Redo，关闭项目/整套切版清空会话栈；失败不弹出快照。

生成后大纲与讲稿读取 Current 的 sections/speech/slides；不依赖已消费计划，也不维护独立可写副本。编辑 Current 走 DeckSession；需要规划重做时创建唯一候选计划。新 Deck 的结构、讲稿、论文绑定和 omissions 在成功应用时一笔事务切换，原 Current 成为 Previous，更早 Previous 只在不再被引用后回收。失败不覆盖旧版本。

恢复上一版原子交换 Current/Previous，成为 Current 的 revision 递增，绑定该版自己的论文与讲稿，失效旧任务、候选和会话 Undo。Project 工作底稿如与恢复稿不同，界面明确显示，不偷偷重绑或覆盖它；再次恢复可切回另一版。并发 Current 变更让候选 stale，不能绕过事务通过锁 UI“解决”。

## 6. 校验与失败处理

Zod 负责形状白名单，普通函数负责引用与几何，不建通用校验框架。错误统一携带 stage、code、message、recovery，区分 PDF、模型认证/额度/限流/网络/无效输出、来源/布局、导出与存储失败；用户只看到必要产品信息。

| 类型 | 处理 |
|---|---|
| 非法 ID/跨项目引用/越界 bbox/错误 Panel 归属 | 进入系统定向修复或图源可视化调整，仍非法不得写入 |
| 漏标签、疑似切断内容、共享图例困难 | 标记图核对疑点，保留原图，不自动断言科学正确 |
| 可派生来源登记、布局容量、章节和讲稿分配 | 程序维护；生成失败由内部定向修复/重新规划处理，不交给用户填字段 |
| 原文或必需图源缺失、模型不可用 | 保留成果、定位并提供重试/设置；不得下载缺失证据的半成品 |
| 未覆盖论文发现 | 自动生成时补齐或报告该单元未完成；用户明确省略才记录 omission |
| 标题、叙事比例/顺序、过渡、重复表达 | 可定位建议，不阻止用户删页、保存或逐项要求确认 |
| 科学措辞或对应关系不确定 | 明确疑点与依据；用户确认切分不等于事实证明 |
| 过期版本、越权、重复请求或取消 | 拒绝提交，不改稳定成果或提供强制覆盖 |

validatePlanNarrative 与 validateDeckNarrative 仍为两个薄入口，共享确定性 helper，不使用混合 Plan|Deck validator。叙事建议按主线计算，补充在后不触发“最后必须 Take-home”硬错误；移除固定背景/结果比例和 focus 页数作为门槛的旧规则。

数据结构与引用始终有效，草稿可缺完整讲述分配，ready 才满足完整页面与讲稿覆盖。自动生成至少一页、内容页有讲述和依据；用户创建的空页、删空与旧稿允许保存，零页禁用导出。迁移后缺讲稿不是历史稿的阻断项。任何字段合法都不能证明科研事实。

构建合同 validateBuiltDeckAgainstPlan(deck, readyPlan) 独立于叙事检查：核对 plan/Paper revision、页面 ID/顺序/章节/track/kind、title/purpose/message、layout、Claim/Source、Figure/Panel 与 speech 分配和正文。Build 只填充指定元素，不暗改讲稿或图源；失配拒绝提交并保留计划，按受影响单元修复。必要重规划先形成新版本，再重新核验人工改动边界。

硬错误仍阻止依赖它的导出，普通警告无需逐项点击确认。检查结果由当前快照计算，不持久化第二套问题真值；每条有稳定 code 和定位，重复点击可再次定位，解决后移除说明，无对象的全局问题指向明确入口而非虚构页码。

## 7. 模型与 GitHub Pages/PWA

### 模型边界

固定候选为 DeepSeek deepseek-v4-flash-vision-exp 和 GLM glm-5.3-flash。候选不是已验证支持列表：M0 核对官方端点、模型 ID、Vision、结构化结果/工具调用、Streaming、Abort 和真实浏览器 CORS，生产界面仅显示通过验证的候选。至少一个可用才进入后续主线，不能用 Node 请求成功替代浏览器验证。

供应商通信复用 Pi AI；固定 workflow 的单次结构化输出保留薄封装，交互式工具循环由第 5 节的 Agent Core 承担，不重复实现通用 SDK 或 Agent runtime。模型设置只有固定候选、Key、连接检查和清除 Key；不存在自定义 Base URL、任意模型或混合路由。所有模型请求使用当前配置，运行中先完成或取消任务再切换。

Key 存在 settings，与项目生命周期分开。Key 不进入模型上下文、history、错误日志、构建变量或导出；供应商请求只发送必要文本与图片。论文和模型内容以文本/受控元素渲染，不执行其中的脚本、HTML 或工具指令。

浏览器直连不成立的候选不启用，也不为其引入代理或后台服务；若全部失败，M0 记录阻塞原因，不能把纯静态部署能力写成已通过。

### 研究叙事策略与提示词

现有公共规则、五个研究策略和五个阶段提示词是 v0.4 实现基线。M13 不修改 Prompt；v0.5 在实际实施阶段更新全文理解、Figure 局部切分、大纲/讲稿、页面规划与生成任务，只为真实调用增加或拆分提示词。职责如下：

| 文件约定 | 职责 |
|---|---|
| `prompts/common.md` | 统一维护来源、科学措辞和用户要求优先等公共生成/修改规则 |
| `prompts/research/<strategyId>.md` | 一种研究叙事策略的适用情况、叙事建议、证据重点和内容取舍 |
| `prompts/stages/<stage>.md` | 实际模型调用阶段的任务说明；不因研究类型复制阶段提示词 |

首批策略为 `general`、`mechanistic`、`omics`、`clinical`、`translational`，最后一项覆盖转化/混合研究。文件名是不重复的稳定 ID；YAML 头信息只含必填字符串 name、description，正文使用 Markdown。增加策略只需新增文件并构建，不维护第二份手写注册表或重复的 JSON 配置。以下仅示意 `omics.md` 的格式，正文实施时遵守产品第 4 节的主线/补充与证据原则：

```markdown
---
name: 组学与生物信息学
description: 适用于以高通量数据分析和生物学发现为主的研究
---

## 叙事建议
研究问题 → 样本与数据 → 主要发现 → 验证 → 生物学解释。
在基础学术骨架内按论文证据调整结果组织，不要求每部分独立成页。

## 证据重点
围绕主要结论组织 Figure/Panel，说明发现及其验证依据。

## 内容取舍
方法仅保留理解结论所需的信息，避免按分析工具步骤逐项汇报。
```

通过 Vite `import.meta.glob` 配合 `query: '?raw'`、`import: 'default'`、`eager: true` 将文件作为字符串随应用构建分发；由应用读取 YAML 头信息和正文，不能将正文执行为脚本或模板表达式。[Vite Glob Import](https://vite.dev/guide/features#glob-import) 只检查所需文件存在、ID 唯一、头信息格式及 name/description/正文非空，且必须有 `general`。构建检查与应用加载复用同一解析/校验函数；无效配置在发布前阻止构建，不能仅靠浏览器运行时抛错代替，不另建配置框架。

首次论文理解调用带入公共规则、全文与图源、该阶段任务及策略目录，在已有调用中选择默认 strategyId；应用校验后与完整论文阶段一同保存。策略与用户汇报要求不限制全文证据提取范围，不能先按 PPT 重点过滤发现。不为分类另开模型调用；无法确定策略时选 `general`，不使用类型分支或多策略组合执行器。

大纲/演讲稿、页面规划和生成带入一个所选策略、相关原文片段与实际图证据。按来源读取必要上下文，不能用省略全文的结构摘要作为后续唯一事实依据。用户明确的叙事要求优先于策略默认建议，但不能突破证据、来源、数据结构、布局或修改权限；策略不包含工具协议、Schema、事务逻辑和布局坐标，不能覆盖图核对、基准版本、`validatePlanNarrative()` / `validateDeckNarrative()` 的硬规则或 build contract。稳定规则由领域 Schema 和确定性校验保证，不能只写进 Prompt。公共规则只在 common.md 维护；运行时数据作为上下文附加，不写入提示词文件。首版不引入模板继承、远程配置或应用内提示词编辑器。

整套重生成复用已保存 Paper；用户要求改变叙事方式时，在大纲/讲稿调用中结合策略目录和正文选择策略并形成计划，不重做全文分析。候选 strategyId 随生成偏好保存在 PlanRecord，通过 ready 校验后默认继续 build，成功应用并切换 Current 时一同提交，失败不改已有偏好。局部 AI 修改按当次要求处理，不因此改写项目的默认策略；preferences 表示后续生成默认值，不承担各 Deck 的完整提示词历史。

提示词随 Git 管理，修改后重新构建发布；已打开页面在用户接受应用更新前继续使用原构建。更新只影响后续请求，已保存 Paper、DeckPlan 和 Deck 不重写；续跑仍重做未完成阶段，使用当前构建的提示词，不回退检查点。若存量 strategyId 已无对应文件，在下一次相关请求中提示并使用 `general`，下一次生成成功提交时保存实际 ID；单纯查看或恢复上一版不触发重新生成。不持久化提示词快照，不承诺跨应用版本逐字复现生成结果。

### 静态托管与离线

GitHub Pages 托管静态构建产物，不能承担应用的模型代理或任务执行。[GitHub Pages 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

采用 Vite 构建，通过 GitHub Actions 安装锁定依赖、构建并发布 dist。部署参数来自实际仓库配置，项目站点 base 为 /<仓库名>/，不能硬编码根路径。[Vite GitHub Pages 部署指南](https://vite.dev/guide/static-deploy.html#github-pages)

- 导航使用 Hash 路由，如 /<仓库名>/#/project/<id>，不依赖服务端 rewrite；刷新仍请求项目入口 HTML。
- JS/CSS、图标、字体、PDF.js worker 及所需 PDF 资源均随构建分发，遵循同一 base，不依赖运行时 CDN。
- Manifest 的 start_url 与 scope、Service Worker 的脚本和注册范围均在项目子路径。Manifest 范围不等同于 Service Worker 范围，二者分别正确配置。[Manifest scope](https://developer.mozilla.org/docs/Web/Progressive_web_apps/Manifest/Reference/scope)、[Service Worker 注册](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register)
- Service Worker 按完整构建清单缓存带应用命名空间的版本化静态资源，包含离线预览、PDF 裁图和 PPTX 导出所需的延迟加载模块，以及 PDF.js 的 cmaps、standard_fonts 和 wasm；每个文件按构建时 SHA-256 校验，全部缓存成功后才标记离线就绪。不缓存模型 API、Key 或项目数据。
- 请求浏览器持久化存储但不以获批为前提；离线能力在所需静态资源缓存完成后生效。
- 首次缓存安装失败可在原页面联网重试；补齐旧构建缓存时不得混入新构建文件。更新采用等待用户确认刷新，不强制激活并重载正在编辑/生成的页面。仅在空闲且保存完成时允许更新；存在其他同应用标签页时提示先关闭，随后由用户再次更新。保留最近一个旧构建的静态缓存用于旧资源读取，清理范围只包含更早的应用静态缓存，不能清理 IndexedDB 项目。
- v0.5 按第 4 节迁移对象与 PlanRecord，复用 M9 的旧稿迁移路径，不引入通用迁移框架。遇到无法识别的版本提示不兼容并保留数据，不能静默重置数据库。

主分支为 `main`，沿用已有 GitHub Pages 工作流，验收后仅推送 main，不改发布配置。M13 仅推送文档，触发现有工作流不等于新功能已部署。浏览器、模型及 Pages 验证状态和工作记录链接由 [执行计划](执行计划.md) 管理，详细证据写入 `docs/spec/` 的对应里程碑记录，不在本文重复建立验收矩阵。
