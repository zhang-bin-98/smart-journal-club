# 产品范围与目标

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

## 1. 产品目标

smartJC 是面向生物医学原创研究论文汇报的本地优先 PWA，静态部署在 GitHub Pages。

核心闭环：

**上传主论文 PDF（可附一份补充材料 PDF） → 全文解析、完整 Figure/Panel 切分与论文底稿 → 分析页查看进度并按需补选图源页 → 用户点击进入图源核对并按需手动调整切分 → 生成并调整大纲与演讲稿 → 用户进入幻灯片步骤，自动规划并生成页面草案 → 调整分页、图组与 PPT → 检查并导出可编辑 PPTX。**

主要用户是准备 Journal Club、组会和文献汇报的生物医学研究人员。成功标准是论文发现覆盖充分、图证据完整可读、演讲稿与页面相互配合、来源可查，用户主要做取舍和修改，不必自行找遗漏内容、补登记字段或解决模型格式错误。

论文底稿以文章为基础，不按 PPT 页数裁掉发现；汇报默认充分覆盖已识别的论文发现，明确标出主线与补充内容。用户可在任一步骤主动介入，大纲可改、演讲稿可改、PPT 可改。论文分析与图源核对是独立页面，合计四步；分析完成后留在分析页，用户手动进入下一步，不要求逐页勾选确认。Figure 切分必须整体确认；之后由用户主动进入大纲与讲稿、幻灯片步骤；检查融入编辑，最终在幻灯片内直接导出。当前暂不提供跨步骤一键生成；每步内部自动处理整理、生成与有限修复，不增加逐段或逐图确认。

项目只服务 smartJC，不承担通用 Agent 平台或未来组件复用目标。

## 2. 本版范围

| 必须具备 | 边界 |
|---|---|
| 单篇论文、本地项目列表、重命名、删除 | 一个项目包含一份主论文 PDF 与至多一份补充 PDF，属于同一篇论文；删除项目需确认 |
| 全文底稿、Figure/Panel 与证据关联 | 处理主论文和已上传补充 PDF 的正文、方法、图注、表格及内嵌附录；不联网寻找附件 |
| 论文分析与图源页查漏 | 双文件分别显示真实处理数量，全部页缩略图可见；人工补选/纠正图源页，自动补做局部处理；不按勾选范围删正文或决定 PPT 取舍 |
| 自动切分与图源核对工作台 | 所有识别到的 Figure 可见；支持修框、补删 Panel、改标签、Undo/Redo，保存至论文图源 |
| 原文片段、观察结果、发现与 Panel 双向查看 | 关联多对多；未确认的解释标疑点，不让用户逐条填写科学字段 |
| 大纲与演讲稿、幻灯片分步联动 | 先整理完整讲述及多对多图证据；下一步安排分页、图组与页面，运行中可暂停后编辑 |
| 主线与补充内容 | 默认充分覆盖，不设固定默认页数上限；用户可删页、移动内容或明确限制篇幅 |
| 固定窗口的应用工作台 | 目录、原文、画布、讲稿与 Inspector 各自滚动；不再堆成长网页 |
| 文字编辑、分页、增删页、图组与重排 | 幻灯片中组合多个独立 Panel，调整组内顺序、大小与间距；不扩展通用自由坐标或富文本编辑器 |
| AI 问答、审核与受控修改 | 显式提问/修改；改写已有成果先展示提案，应用后一次请求一次撤销 |
| 自动保存、续跑与版本保护 | 完整阶段可恢复；失败不破坏已保存成果；Current/Previous 各保留自己的证据与讲稿 |
| PPTX、演讲稿与离线操作 | PPTX 保留原生文字、图片及对应讲者备注；AI 需要联网与用户自己的 Key |

输入仍限定生物医学原创研究，覆盖机制、组学、临床和转化/混合研究。Review、系统综述、Meta-analysis、指南、纯病例报告和其他领域不纳入本版；不支持类型说明边界，不建设额外流程。扫描件、加密或损坏 PDF 提示更换可解析版本，不新增整篇 OCR。Panel 标签的局部识别不等于支持扫描论文，本版不引入独立 OCR 引擎。

正式编辑面向桌面 Chrome/Edge。本版不考虑响应式或手机专用布局；其他浏览器不扩充发布验收矩阵。

## 7. 后续候选与明确边界

只有实际使用证明必要时才评估：整页任意元素的自由拖动缩放、多主题、通用图片/图形、方法流程图、项目备份导入、完整 Paper 字段编辑、PDF 重新关联、跨重启撤销历史。演讲稿、PPTX 讲者备注、来源级图切分编辑和幻灯片中的有限图组编辑已纳入本版，不再列为候选。

本版不建设账号、云同步、后端代理、后台队列、多人协作、通用 Agent/插件/MCP 市场、多 Agent 编排、多论文工作区、联网补充材料、PPTX 导入、动画/模板市场或完整 PowerPoint 编辑器。沿用浏览器内静态 PWA；不为借鉴拆图项目直接引入 Python/SciPy 服务、独立 OCR 或多边形/遮罩裁图。后续确需改变这些技术边界时先讨论。

产品验收以 [执行计划](../execution/README.md) 的同一条主链和必要内容检查为准。当前实现与新目标的差异不能用历史测试通过来掩盖。
