# 并发与任务调度

> M14 已接入统一 API 调度；本地计算池和分析单元调度留在后续阶段实施；不承诺固定加速倍数，不新增服务端或通用任务平台。

## 两类资源分别调度

| 职责 | 所有者 | 约束 |
|---|---|---|
| 阶段顺序、依赖与有效任务 | Application workflow | 独立页/图可并行；完整阶段汇总、身份分配、校验与提交由单一用例协调；不要多个 Worker 同时修改 Paper |
| PDF 解析与图像计算 | Infrastructure PDF/Worker 适配器 | 复用 PDF.js 自带 Worker；业务像素纯函数进入小规模有界池，DOM 与预览留各自适配器；不将整个应用搬进 Worker |
| 模型发送与限额 | Infrastructure 模型调度器，composition 共享实例 | 文本、视觉、结构化修复及 Pi Agent 调用统一经过入口，不能各自额外获得一份并发额度 |
| 进度与操作 | UI 读取应用查询 | 展示文件/页/阶段计数与等待，不能由 UI 自己派发请求或决定就绪 |

Web Worker 主要隔离本地重计算；网络等待可以异步进行，新增线程不能缩短供应商单次推理。PDF.js 的 Worker 不代表所有 Canvas/像素工作都离开主线程。来源：[Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)、[PDF.js API](https://mozilla.github.io/pdf.js/api/draft/api.js.html)。

本地并发与 API 并发分别配置；先采用保守的小规模上限，实测后调整，不把默认核数当最佳线程数。限制同时存在的高清位图与待编码结果，API 队列满时停止无限预渲染，及时释放已消费资源；传输 ArrayBuffer 不分离仍由 UI 使用的缓冲。资源缓存/取消消费者规则沿[图源与渲染](图源与渲染.md)。

## 模型限额与公平性

按供应商端点、配置凭据身份及其实际共享限额桶调度，密钥只由既有适配器读取，不进入任务 ID、日志、Worker 消息或可见状态。同一账号/组织可能跨模型共享限额，不能机械地每个模型各开满额度。限制同时在途数，并按已知规则约束请求频率及估算 Token 预算；响应有可读取的剩余额度/重置头时校正，浏览器因 CORS 无法读取时保守处理，不假装已知精确额度。

分析、补选和交互请求共用桶；用户主动操作可优先，但应保证分析队列逐步推进，不因持续对话永久饥饿。跨应用页面视图共享同一个调度器，不随 React 组件卸载销毁。当前只有一套生效配置，采用单标签页全局保守桶，模型或配置变更不自动重置额度；这比为不同账号分别开满额度更严格，不推断未知服务的真实共享规则。初始同时在途 2、每 60 秒 30 次请求及 120000 估算 Token、待处理最多 64；响应实际用量校正预留，可读剩余/重置头只收紧窗口。交互连续获得两次优先后让待处理分析前进，等待和退避均可取消。第一版不新增多项目后台并行运行能力；跨标签页/其他应用使用同一账号无法由单标签页完全控制，因此不能承诺绝不触发供应商限流。

限额不仅是并发数，还可能包含请求数和 Token 速率，具体以供应商实际规则为准。参考：[API 限流示例](https://developers.openai.com/api/docs/guides/rate-limits)。临时限流的退避/次数与不可重试类别只在[校验与恢复](校验与恢复.md)维护；SDK 自动重试与外层重试不能叠乘，适配器统一预算，不绕过用户取消与单次请求超时。

## 乱序结果与补选

任务包含运行身份、Paper 基准、documentId、页码或图块身份、选择版本和实际输入 inputKey。完成次序不等于来源次序：按身份回填，最终按文件及页码展示；进度计数统计不同已完成单元，不能用最后完成页码充当完成数。文本提取、图页发现、图源处理和全文理解分别报告，页集合变化后总数可增加并说明补选来源。

各文件独立工作可并行，最终结论必须以全文和跨文件证据统一整理，不按页孤立形成互相矛盾的发现。页级人工修改通过原应用提交入口保存；旧选择任务失效，新运行只复用已校验且不受影响单元。整体基准变更可能需要创建新任务，但不能据此重跑全部模型调用。人工排除的影响候选与旧稿保护沿[数据约束](数据约束.md)。

## 生命周期与有限恢复

排队、供应商退避、运行和完成分别可观察；等待不增加完成数。用户暂停/取消先使当前任务失效，撤掉待处理项、终止可取消计算/网络；退避等待也必须可中断，不允许时间到了再偷发请求。Worker 崩溃定位单元，重建实例须服从有效任务与重试策略，不能伪造该页成功。

项目会话拥有任务，普通应用视图切换继续运行；关闭/刷新不承诺后台完成。每个完整有效分析单元及时保存成果和输入依据，不保存半条模型输出或运行权限；刷新后读取已保存单元，用户继续时只处理缺失/过期部分。兄弟单元的正常保存不使无关结果过期，单一应用入口按目标输入复核并合入最新底稿；不能以全局 revision 粗略变化导致整批重新请求。详细 checkpoint 与事务边界沿[工作流与存储](工作流与存储.md)。

## 必要验证

后续实施使用同一固定响应与可控延迟验证：在途/频率预算、取消排队与退避无迟到派发、乱序回填、双文件同页码不串用、补选和人工覆盖竞争、SDK 重试不叠乘、内存生产受消费速度约束。Worker 适配器用少量真实浏览器检查消息/释放/崩溃恢复；不扩展性能指标、设备矩阵或真实模型重复调用。
