# 内容编辑、Agent 与撤销

> v0.5 规格；实际交付与验收状态见 [执行目录](../execution/README.md)。

## 5. 修改、撤销与版本

### 内容提交与同步

论文、计划、文稿各自使用显式 mutation 与唯一应用提交入口，白名单决定范围；UI 和 tool 只提出命令。OutlineSession/DeckSession 的保存编排归应用，领域只保留内容/撤销候选与纯规则，不能持有异步保存回调。请求包含 requestId、projectId、目标 ID/baseRevision；模型结果另带有效任务，有草稿的手工保存携带对应编辑登记身份；无草稿按钮命令按原有目标/范围校验，不创建空登记。

1. 应用核对目标、请求、任务或编辑登记及当前权限，调用所属领域在内存副本应用整批，得到候选、问题和影响 ID。
2. 应用组合跨对象规则，向存储接口提交具体原子操作；事务重读基准，执行同步纯复核/必要合并，一次写入内容与摘要。纯规则只维护一份，适配器不自行选择覆盖范围或下一阶段。
3. 事务成功返回实际保存版本后，应用 Session 才接受该版本、推进内存 Undo 和历史并通知 UI；保存失败不改变已保存会话、revision 或撤销游标。撤销/重做同样先生成内容候选，经同一入口保存成功后才移动游标。

重复 requestId 拒绝。候选模拟不写入；内容用例/Session 不反向启动 workflow/Agent，也不在其内部增加模型重试。工作流需要继续时读取成功提交结果再决定。

计划编辑支持章节/讲述片段/页面的新增、更新、删除、重排及主线/补充调整，不保留 set-slide-budget 命令。移动章节带其页面与讲稿；仅调整页面展示顺序保留章节和片段身份，显式移动讲述段落才迁移其章节；改变页面所属章节或跨章合页只维护页归属/分配，不隐式迁移讲述段落；仅显式删除章节时处理空章，禁止悬空 sectionId/speechIds。页间顺序由稳定锚点表示，null 为目标章首，拒绝不存在目标、自身后移或超范围变更。

正文手动删除与编辑不因比例、顺序等叙事建议被阻断；去掉页面同步移除该页的讲稿分配，保留讲稿为待安排内容和全部论文发现；明确删除讲述或压缩要求导致不再覆盖时才记录用户省略。纯过渡/空页不伪造 Claim，结果页仍不能引用不存在的证据。需要模型改写过渡或更新图文时先形成候选差异；新内容不会静默替换用户写过的文字或框。

应用与提案模拟复用相同验证；冲突、取消、并发和写入失败不推进 Current、revision、Undo 或历史。第一次实际修改前，UI 向应用登记编辑目标、基准和 draftVersion；应用同步失效会覆盖它的任务并拒绝迟到结果，不等保存时才比较内容版本。草稿正文与临时框仍归 UI，不逐字写库。未保存登记阻止冲突写入、导出和离开；只有携带匹配 editId 的本次手工保存可提交该草稿。保存失败保留输入及登记；纯浏览、仅获得焦点不登记修改。

分页拆的是片段分配，段落身份和次序保持；主动拆合讲述才改变段落结构。同一保存操作更新唯一讲稿及其备注来源；页面标题、正文和图组不被后台同步改写。结论/Panel 变化可提示更新并生成候选，普通措辞变化不自动生成候选或阻断导出。非法引用、重复分配和无法生成正确备注的确定性错误须修复。

保存进行中再次编辑时，更新登记的 draftVersion；返回结果只能解除其实际保存版本对应的保护，不能清掉新输入。新草稿继续保留，并以成功保存的版本接续后续保存；显式放弃解除对应 editId，不复活已失效任务。在途提交期间的放弃按接口契约等待保存结果，不回滚已经成功保存的内容。浏览切页和 React 重新挂载不隐式清理登记；正常离开项目先保存或明确放弃。刷新后的未保存草稿不承诺恢复，已保存成果与新任务权限按既有规则恢复。接口的输入及失败语义见[接口契约](接口契约.md)。

### 交互式 Agent

继续使用 pi-agent-core 现有 Agent、事件和 abort/hook 能力，实际 API 以 M10 锁定版本与实现为准，不重新编写通用 turn loop。提问只注册读工具；仅大纲与演讲稿、幻灯片页的修改模式注册受控 proposal 工具。固定生成的首次内容创作由 workflow 授权，不能与“改写已有成果须应用提案”混为每页都要确认。

#### 页面能力与提交对象

| 视图 | AI 能力 | 范围与提交对象 |
|---|---|---|
| 论文分析 | 只读解释实际进度、失败原因和已解析内容，定位疑似漏图页 | 读取工作 Paper 与有效任务状态；补选、恢复选择和重试由用户操作已有控件，不由对话派发任务或写入 |
| 图源核对 | 只读解释 Figure/Panel 图注、查询原文和定位证据 | 默认当前 Figure/Panel，可按明确问题查询其他来源；不提供自然语言改框、补删、改号/归属、标签或关联，也不从对话触发重识别 |
| 大纲与演讲稿 | 提问，或对章节顺序、主线/补充、讲稿及图证据关联生成修改提案 | 默认当前段落，可显式扩大到章节或全文；已有稿编辑 Current Deck 的讲述内容，尚无稿时编辑有效 Plan，不要求先有 Deck；不修改页面排版 |
| 幻灯片 | 提问，或对页面内容、分页、图组及对应讲稿生成修改提案 | 元素、当前/所选页、章节或整稿；修改 Current Deck，保持已确认的来源/备注同步边界 |

论文/图源 Agent 不注册写入或 proposal 工具，也不复用幻灯片模式的工具集合；隐藏修改按钮不能代替应用层能力校验。用户在这些页面提出修改要求时，回答可使用的已有控件并提供对象定位，不宣称已执行，不自动切换成写模式。图源手动修改继续调用保存图源用例与 paper 内容入口；“重新识别当前 Figure”通过明确按钮启动显式 workflow，结果仍先对照候选再应用，这与自然语言编辑分开。

Deck 修改沿用 deck_propose_revision，扩展实际需要的讲稿/分配白名单；生成前的讲稿提案使用 Plan 的受控入口，复用同一助手编排和 presentation 纯规则，分别由 OutlineSession / DeckSession 提交，不创建空 Deck 或第二套 Agent loop。大纲页即使底层编辑 Deck，也只能修改授权的讲述内容及必要派生关联；备注按正文更新，PPT 标题、正文和图组不被顺带改写。所有页面均不注册任意文件、bash、代码执行或通用 MCP 工具。

读工具保留 paper_get_overview、paper_get_claims、paper_get_figure、outline_get_structure、deck_get_slides；逐步纳入当前任务的原文片段和讲稿查询职责，参数从实际 Schema 派生。作用于旧稿时读取其绑定 Paper，不能混用当前工作底稿。工具不直接访问 IndexedDB 或承载事务。

在页面允许的能力内按“明确目标 > UI 选择 > 近期上下文”解析，无法消歧才询问；明确文本不能突破该页面的修改白名单。发送前展示实际目标，派发时固定 projectId、内容类型与 ID/revision、绑定 Paper、操作模式及对象集合。分析页“这页”是 documentId+页码，图源页“这张图”是 Figure/图块/Panel，讲稿页“这一段”是稳定段落，幻灯片页“这页”是 slideId，不共用含糊的页码参数。

大纲的章节范围展开为该章讲述段落/片段；幻灯片的章节范围展开为页面集合，新增内容不得超出授权章节。只读查询同样固定来源与版本，未完成解析内容明示不可用，不把 AI 猜测当任务状态。滚动、选择或查看其他工作台视图不改变已发送范围或扩大权限，回复标出原目标；新的请求再读取当前上下文。项目或所编辑的 Plan/Deck 切换、内容基准变化仍按既有规则使提案失效。普通局部请求只携带必要邻近内容和证据，全局请求才读取对应完整 Plan/Deck。

一次请求最多一个有效提案，写意图顺序执行，模拟后显示影响章节/段落/页面、差异和应用/放弃；应用时再次核对版本和范围。取消、Agent 后续失败、手工草稿、项目或所编辑 Plan/Deck 切换使提案失效，不提供强制应用。每次应用是一条 RevisionRecord 和一次 Undo。

事件映射为可读进度，右侧显示对话/提案，底部输入共享同一状态；不显示隐藏推理、原始 JSON、provider 错误体或 Key。仅有限可见消息与已提交摘要持久化，交互式提案（包括整稿范围）只保留当前项目会话，刷新或关闭项目后丢弃，不从消息恢复待应用权限；完整工作流新稿候选的持久化独立遵循[工作流与存储](工作流与存储.md)。有限轮次/工具/上下文预算使用 Pi runtime 适配器的已有 hook，不建设 Node/SQLite backend。

### Undo/Redo 与 Current/Previous

各会话快照只存该内容域的必要数据，不含运行权限、旧 revision、原 PDF 或位图。Undo 恢复内容而 revision 递增；图源 Undo 也使核对失效，计划 Undo 回 draft。图源确认动作不作为可以恢复的生成授权。Undo 后新编辑清空 Redo，关闭项目/整套切版清空会话栈；失败不弹出快照。

生成后大纲与讲稿读取 Current 的 sections/speechParagraphs/speech/slides；不依赖已消费计划，也不维护独立可写副本。编辑 Current 走 DeckSession；需要规划重做时创建唯一工作计划，完整候选另按 Project.candidate 保存，不因工作计划被替换而丢失。新 Deck 的结构、讲稿、论文绑定和 omissions 在成功应用时一笔事务切换，原 Current 成为 Previous，更早 Previous 只在不再被引用后回收。失败不覆盖旧版本。

恢复上一版原子交换 Current/Previous，成为 Current 的 revision 递增，绑定该版自己的论文与讲稿，失效旧任务、候选和会话 Undo。Project 工作底稿如与恢复稿不同，界面明确显示，不偷偷重绑或覆盖它；再次恢复可切回另一版。并发 Current 变更让候选 stale，不能绕过事务通过锁 UI“解决”。
