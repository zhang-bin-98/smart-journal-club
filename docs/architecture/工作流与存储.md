# 工作流、持久化与版本迁移

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

## 4. 存储、生成与迁移

继续使用 smartJC 命名空间的一个 IndexedDB、七个 store。app/use-cases 定义保存阶段、提交内容、切换版本等具体原子操作；infrastructure/persistence 实现单次跨 store 事务，不拆成多个 repository.save() 先后写入。业务决定与影响计算在应用/领域完成，事务内重读基准并复用纯规则复核，成功才一次写入；不引入通用持久化框架。

| Store | 内容 |
|---|---|
| projects | Project、当前工作底稿指针与最近位置 |
| papers | 工作 Paper 与 Current/Previous/有效计划仍引用的不可变 Paper |
| assets | 固定主论文/补充 PDF Blob，同项目各底稿版本复用对应资源 |
| plans | 按 projectId 唯一工作 PlanRecord，保存大纲/讲稿/页面规划及基准 |
| decks | 当前稿与唯一上一版，包含讲稿与论文绑定 |
| history | 有限可见消息和已提交摘要，不存模型隐藏推理或撤销快照 |
| settings | 独立模型配置与 Key |

页面、缩略图、裁图和 URL 仅有限内存缓存，分级键、容量、共享请求与释放规则统一见[图像资源调度](../architecture/图源与渲染.md)，不能复用旧框。Undo/Redo 各最多 20 个内容快照，可见历史最多 100 条；不把这些上限写进领域对象。

创建项目、含 document 记录的空 Paper 与全部已选 PDF 同事务，任一文件保存失败不留下半项目；事务前先验证文件数量/角色、基本可读性，计算与读取不占据数据库写事务。删除同时删除所有本项目工作/保留 Paper、计划、Deck、PDF 与历史，不删 settings。Paper 回收只在成功提交后的同一项目内，保留 Project.paperId、Current/Previous.paperId 和有效 PlanRecord 引用的全部底稿，拒绝跨项目或按猜测删除；不持久化论文版本树。

### 阶段与分步推进

| Checkpoint | 完整保存的产物 | 默认下一动作 |
|---|---|---|
| project-created | 项目、全部已选 PDF、document 集合、空 Paper | 解析全文 |
| pdf-parsed | 全部已选文件的页、TextBlock、文字来源 | 分析 Figure/Panel |
| figures-ready | 完整自动图源与恢复基线 | 整理全文发现与证据 |
| paper-ready | 论文底稿、核对版本及关联状态 | 停留论文分析页；用户点击进入图源核对，确认并启动后仅生成大纲与讲稿 |
| outline-ready | 章节、主线/补充、大纲与完整演讲稿 | 结束当前任务，等待用户进入幻灯片步骤 |
| deck-plan-ready | 已分配讲稿、图证据和布局的计划 | 在用户已启动的幻灯片步骤内校验 ready 后 Build |
| deck-ready | 完整 Deck、讲稿和冻结论文绑定 | 编辑/导出；候选更新不覆盖 Current |

checkpoint 记录完整产物，不等于核对确认或任务继续权限。已有 Deck 时 checkpoint 可维持 deck-ready，新的工作底稿/候选进度由各自记录表示，不能隐藏旧稿；不能只比较枚举大小来决定是否允许继续。

两份文件各自解析全文、图注、表格和页内 Figure，再在同一 Paper 整理发现与证据。只有全部已选文件的必需处理成功才能推进 pdf-parsed/figures-ready/paper-ready；某文件失败定位其文件与页，重试复用有效阶段，不把主文件成功显示为整个论文完成。补充材料也参与理解，不只抽图片。

用例组合：preparePaper() 负责准备与必要关联刷新，confirmFigureReview() 保存用户核对，prepareOutline()（大纲+讲稿）完成后结束该步骤任务；用户进入幻灯片时 generatePresentation() 仅编排 planSlides() 与 buildPresentation()。首次与重生成共享这些步骤，不另建第二条 pipeline。名字为目标职责，目标归属为 app/workflows，复用现有 generation 的有效步骤并迁移职责，不保留第二套流程。

论文分析就绪后结束任务且不自动切页；用户显式进入图源核对，不保存“已逐页审核”事实。图核对必须整体确认；大纲与讲稿完成后不跨步骤自动继续，由用户主动进入幻灯片。当前不提供跨步骤一键生成或 pauseAfter 偏好，模型不得擅自启动下一步骤。页面规划与构建在同一幻灯片步骤内自动完成；用户可立即 abort，清除运行权限但保留完整阶段。编辑开始暂停依赖它的任务，完成保存后由用户继续；刷新恢复产物与最近位置但不自动调用模型。用户选择继续只授权当前步骤请求链，旧响应不能沿用新任务授权。

Plan ready 是程序校验，不得伪造为 user confirmed。生成前保存并绑定稳定计划 ID/revision、Paper ID/revision、核对版本、偏好及有效任务。模型仅填充计划允许的内容；构建严格遵守其页面身份、顺序、图源、讲稿分配和结构。布局或结构需改变时返回内部规划步骤形成新 revision 后再 build；有人工修改时先提出变化，不让用户修格式，也不绕过计划合同。

格式/结构、唯一明确的图标签映射和可派生来源由程序处理；需要模型修复时每个失败分析单元/讲述或页面单元最多一次定向 repair，携带相同原文/图像与诊断。临时限流沿[校验与恢复](校验与恢复.md)进行有限等待重试；认证、额度耗尽、网络、截断、取消与超时不自动重试。仍失败时保存已有完整成果，报告具体单元、原因类别和重试入口；不得用空计划、丢发现、丢 Panel 或放宽验证当成功。艺术/科学判断不给任意代码修复器。

排队时间独立显示，不占单次已派发请求的等待预算；排队/退避均可立即取消。每次实际派发请求保留现有 180 秒独立等待预算，覆盖 SDK 加载、流迭代与最终结果；取消和超时不能依赖底层结束才能退出。进度包含文件身份及原页/Figure/讲述或页面单元与已完成数，迟到回调检查有效任务。所有计算、网络和渲染在事务之外，提交事务内重读项目、前置产物、版本与任务。任务取消且事务未完成时 abort；已经提交的成果如实保留。

内部可按页/小批完成制作，只有完整有效的计划或 Deck 才推进对应 checkpoint；不增加 UI-only checkpoint，不保存半条模型输出。局部重试复用同一任务内已完成工作，跨刷新保证最近完整阶段恢复；不承诺尚未持久化的单页结果跨刷新续跑。

### 成果、任务与 UI 状态的唯一归属

| 状态 | 所有者与保存边界 | 派生的界面信息 |
|---|---|---|
| 成果 | Project/Paper/PlanRecord/Deck 持久化；checkpoint 只标完整阶段 | 已有内容、核对是否有效、生成/导出是否具备条件 |
| 任务 | app/workflows 当前运行实例；阶段、运行/暂停/失败、任务 ID 与 AbortSignal 在内存 | 进度、暂停/重试按钮；不写进科学内容 |
| 交互 | ui/workspace 与视图；当前对象、焦点、面板、缩放、未保存草稿 | 选中态、工具栏；最近位置可按已有偏好保存，不持久化运行权限 |

外壳不另存可独立修改的 canGenerate/canExport/needsReview。应用查询从成果、当前任务和草稿事实推导可用操作及原因，所有视图与 Agent 共用；不能各自以 checkpoint、busy 或 plan 是否存在写一遍判断。已有稿可导出与工作底稿待核对可以同时成立，导出始终使用所选已保存稿的证据快照。

| 事件与前置事实 | 应用动作 | 完成后可观察状态 |
|---|---|---|
| 开始分析，PDF/模型可用 | 创建任务，按完整阶段恢复并调用论文准备 | 分析中；已有成果可浏览 |
| 全文与图源及证据阶段保存成功 | 结束分析任务，查询就绪条件 | 分析页就绪，等待用户点击下一步，不自动切页或生成 |
| 用户点击下一步：图源核对 | 重查分析就绪与保存事实 | 进入图源核对，尚未确认切分 |
| 补选图源页 | 提交选择版本，活动分析内排队；就绪后创建局部分析任务；暂停时仅保存待处理项 | 新增范围待处理，完成后仍留原视图等待用户操作 |
| 核对完成并生成讲稿，图源草稿已保存 | 保存本次确认，创建讲稿任务；先补必要关联 | 生成大纲/讲稿，保存后停在讲稿工作台 |
| 大纲/讲稿完整保存 | 结束当前运行权限 | 可编辑，等待下一步 |
| 用户进入幻灯片，讲稿已保存且前置版本有效 | 新建该步骤任务，规划并构建页面 | 步骤内自动推进，完成后供编辑 |
| 立即暂停/取消或开始编辑上游 | 同步使任务失效、abort；保留完整阶段 | 已暂停或已取消；迟到响应不可提交 |
| 继续/重试 | 从最新保存事实推导下一步骤，生成新任务 ID | 未完成单元重试，不复活旧任务 |
| 模型/资源/存储失败 | 结束任务并保留稳定产物与未保存输入 | 单一定位错误与恢复操作 |
| 完整首次 Deck 成功提交 | 冻结绑定底稿，结束任务 | 进入幻灯片工作台 |
| 完整重生成候选就绪 | 保留 Current，展示候选差异 | 待应用；应用时重查基准 |
| 刷新/重新打开 | 读取产物与最近位置，不恢复运行权限 | 可浏览及继续；不自动调用模型 |

暂停与取消均终止当前请求；暂停保留继续意图的界面提示，取消返回最近成果，二者都不删除候选或内容。“放弃候选”是单独的显式操作。整套流程无后台队列，任务不依赖视图是否显示。状态转换通过普通显式函数维护，不为本项目引入通用状态机引擎。

### 基准、工作底稿与候选

字段定义见 [数据模型](数据模型.md) 的“工作计划的基准记录”。

每项目一份计划，开始时捕获基准，保存/编辑/ready/Build/应用各环节重查；initial 不带 current/previous，regeneration 必带 current，previous 只在实际存在时成对记录。当前稿正常编辑后旧候选不可应用，不能自动重绑定到新基准。候选可查看或丢弃后重新生成，保存失败不清空最后完整计划。

Paper 被 Current/Previous 引用后冻结。再次源级编辑或必要局部关联刷新时先复制为新 ID 的工作 Paper，保留来源/图/Claim 的局部身份、documentId 与固定 PDF 集合，Project.paperId 指向工作底稿；旧稿继续按自己的 Paper ID/revision 读取。未被文稿引用的工作 Paper 可以在单一提交入口原地增加 revision。新稿成功保存时冻结其基准 Paper，禁止修改已经被文稿引用的底稿。纯单页裁图仍是 Deck 的 cropOverride，不复制 Paper。

| 用户修改 | 领域影响计算与立即维护 | 后续用例处理 | 保留内容 |
|---|---|---|---|
| 整图/Panel 边框 | 校验范围、增加图核对 revision、列出所引用来源 | 清理对应裁图缓存；新规划/更新候选使用新框 | 原文、无关发现、旧稿绑定图源 |
| 增删 Panel 或改标签 | 维护来源 ID/关联，标记 pendingEvidenceFigureIds | 刷新该图的原文证据关系；必要讲述/页面形成候选 | 其他 Figure 与有效证据 |
| 手动调整图注关联 | 校验 caption 区间与归属、增加 Paper revision，标记该图证据待刷新 | 后续规划前刷新依赖，人工集合不能静默覆盖 | 切分 revision、原图像素、其他 Panel 的关联与旧稿 |
| 修订发现解释 | 根据 Claim/Evidence 引用定位讲稿/页面 | 重算相关内容，人工文字先预览再应用 | 无关发现与人工成果 |
| 编辑讲稿 | 校验所属章节/来源/页面分配，列出关联页 | 用户请求更新时生成页面/过渡候选 | 论文底稿和未涉及页面 |
| 删页/跨章移动 | 同批维护章节、片段归属/分配和来源；删页保留讲稿并标未分配，明确删讲述才记用户省略 | 必要过渡提出修订，不自动改人工文句 | 全文与论文发现 |
| 应用候选/恢复上一版 | 核对目标版本与范围 | 一笔事务切换稿/讲稿/底稿绑定与必要回收 | Current/Previous 各自完整证据 |

影响分析由所属领域纯函数给出稳定 ID 集合；跨域引用查询由应用组合，repository 不再计算另一套影响。根据实际引用现场计算，不建通用任务图或持久化第二套问题表。任何源级修改先走工作底稿复制规则，不能直接就地改旧稿的冻结底稿。

全局主题/语言/主线重排可以影响整套，但必须显示实际范围。基准变化让旧任务整体失效是并发保护，不意味着重算所有未变内容；新任务可复用已验证且不受影响的产物。已有人工内容的覆盖、删改和候选应用必须可预览并显式应用。

全篇重新分析保留独立新项目入口，复制全部本地论文文件与可复用的解析/图源，不继承旧科学解释为新结论，也不标作已核对的新结果；原项目完整保留。源级小调整在本项目工作底稿完成，不要求为每次拖框新建项目。

### 迁移与兼容

v0.3 Deck/Plan v1 仍先使用 M9 已验证的迁移路径；历史 M9 语义以工作记录为准。v0.5 再显式迁移 Project/Paper v1→v2、Deck/Plan v2→v3 与 PlanRecord v1→v2，不能只改类型后强转旧记录。

- 保留所有既有 ID、顺序、标题、元素、来源、图框、cropOverride、Current/Previous 指针和科学内容。页级原文转为带稳定 ID 的块，旧来源保留精度；不猜原句范围、Panel 标签、讲稿或主线取舍。
- 旧单 PDF 项目迁移为一份 role=primary 的 PaperDocument，保留原 pdfAssetId；已有页、原文块和来源绑定该稳定 documentId，不重新编号图/来源。移除 Project/Paper 的旧单 pdfAssetId 字段；同文件被工作/旧版 Paper 复用时保持文档身份。缺失资源保留错误状态，不能伪造补充文件或丢弃旧稿；迁移需幂等。
- 旧 Deck 缺讲稿时 speech/speechIds 为空；旧章节默认 main，明确未做补充分组，不从关键词推测。旧稿可查看编辑并按原内容导出，不因新自动生成要求被锁住。
- 旧计划保留人工内容并转 draft，移除预算确认门槛；旧 confirmed 不能视为已核对图源，也不自动赋予新生成权限。旧 pauseAfter 不再作为新流程运行权限，迁移忽略该偏好；仍保留全部已保存内容。新讲稿和覆盖检查需用户启动后生成，不在迁移中调用模型。
- 旧 Paper 为每页建立 FigurePageSelection；已有图源的页可据历史产物标 detected，其余保留 pending，不把旧候选筛选阴性当作全文已查漏。保留所有旧图源和人工几何；首次新分析完成前相关选择不伪造 processedRevision；旧稿查看与导出不依赖新分析就绪。迁移幂等且不发模型请求。
- 旧 Paper 的图核对状态为未核对，现有图框保留；不把它标为已验证的新算法结果。没有自动基线时“恢复自动结果”不可用，不能拿用户旧框伪装自动结果。
- 迁移先在内存转换并校验，再事务重读基准一致性、原子写入。已升级读取幂等，不生成新身份；Unknown version、损坏引用或写入失败保留原数据，提示恢复，不清空数据库。
- 无法迁移临时计划时保留原记录供恢复，允许显式重新规划；稳定 PDF/Paper/Deck 不丢失。七个 store 无结构变化时不因对象升版而机械提升 IndexedDB 版本；确有存储结构变化才升级并处理旧标签页阻塞。
- Current/Previous 引用的旧 Paper 均冻结可追溯；复制工作底稿、应用更新、恢复上一版与回收必须作为同一数据生命周期验收，不用忽略旧版绑定来减小实现量。
