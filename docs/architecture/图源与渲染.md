# PDF、图源切分、资源调度与渲染

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

## 3. PDF、切分、布局与 PPTX

### 图切分与人工修正

切分借鉴 [split-multipanel-figure](https://github.com/Genesi599/split-multipanel-figure) 的标签锚点、内容块与间隙分析思路，不将其 README 的效果声明视为已验证能力，也不直接移植其 Python/SciPy、全图标签检测、固定阈值、L 形归属或遮罩输出。

1. 按 Paper.documents 的 documentId 分别使用 PDF.js 解析全部已上传文件的全文、图注与页面图像信息，综合定位整图；不能仅以某一种 Fig. 标点正则决定是否存在图。参考文献或正文提到别页 Figure 不等于本页图源。
2. 在完整 Figure 的局部高清图上识别标签、内容关系与粗框；整图原始像素始终保留；对照图注中的实际标签检查漏识别，不按空间顺序补造标签。PDF 图像矩阵可能漏矢量标签，作为参考而非完整图边界。
3. 在粗框及标签邻域，用 Canvas ImageData 的颜色内容、连通内容与间隙提出有限边界调整；考虑浅色和灰色信息，不强制所有图适用同一阈值。
4. 检查空框、越界、漏/重复标签、边缘穿过密集内容和疑似串图；几何合法与科学完整分开。重叠不是硬错误，低把握不自动批准，也不靠删掉难切 Panel 掩盖。
5. 将自动结果提交为可核对来源，用户直接改框、补整张 Figure、添加跨页图块、补删 Panel 或更正标签。无清晰标签的图保留整图与疑点，不编造 A/B/C。共享标注难以独立矩形裁出时可组合展示或保留整图。

坐标运算统一使用原页旋转后的基准；局部放大倍率与窗口缩放不改变持久化坐标，最终导出从 PDF 重裁，不使用被压缩的预览截图。只在必要 Figure/页渲染，任务结束释放临时 Canvas 与无人引用的 URL，可复用缓存按本节容量和生命周期管理；不引入长期位图库。

图源编辑先在 working copy 模拟，再通过应用保存图源用例调用 paper 的唯一内容入口核对 Paper ID/revision、figureReview.revision、PDF 归属、有效任务与引用。移动/缩放、更名、补删、恢复基线均为显式 mutation；保存成功才更新内存与 Undo。保存失败保留输入，取消不写入。删除来源同时处理 Evidence/Story 的该来源关联，保留原文事实及其他证据，缺失关系由系统重算/标疑点，不能写悬空 ID。

几何或标签改变会立即使旧核对失效，增加图核对 revision；相关语义待更新但未变的图不需重新切分。新增 Panel 的原句/发现由系统补充，不把手动补框变成领域数据录入。整图框调整与 Panel 归属冲突须显示影响，不能偷偷移动其它框。

重新识别仅作用于用户指定 Figure，保留原人工结果，显示自动候选供比较和应用；恢复基线也先进入草稿。只维护一份基线和一个当前候选，不保留识别历史树。人工框不被重试、换模型或全篇重新分析自动覆盖。

Figure 为逻辑身份，每个 FigureRegion 在一张 PDF 页上裁切；Panel 仅依附所属图块。现有框选/调框/坐标换算与实际裁图能力共用，“添加 Figure”统一承载创建新图与向已有图追加图块，原图号选择决定明确的应用命令，不另设跨页按钮；“添加 Panel”和“整图边界调整”保持独立，后者只调整已有图块。完整 Figure 跨页时逐图块读取，不把多个页面拼成虚假 bbox；生成可展开成多个独立图像组成图组。无 Panel 的单图直接使用该图块，不能要求无意义细分。

### 交互计算与图像资源调度

本节落实轻量交互、计算分离、局部更新及有界资源四项设计。专项性能验收、数值响应预算和基准测试暂不纳入本轮；以下不是已实现或已测得的性能结论。

| 工作 | 执行位置与职责 |
|---|---|
| 拖框、输入、选择与缩放反馈 | UI 主线程只维护当前对象的短期草稿、覆盖框和可见预览 |
| 像素扫描、连通内容等切分重计算 | paper 提供不含 DOM 的纯计算函数；infrastructure 的 Worker 适配器执行，app 传入数据、任务标识及基准版本 |
| 图源、布局与引用变化 | 领域计算实际影响集合，应用在编辑完成后提交，UI 更新相应对象 |
| PDF 渲染、图像编解码与输出资源 | 适配器按用途和优先级调度；资源生命周期由当前项目/任务管理 |

PDF.js Worker 只承担其自身支持的 PDF 工作，不能当作业务像素计算已移出主线程。async/await 也不改变同步计算的执行线程。业务 Worker 通过窄消息协议接收像素数组/尺寸与任务 ID，返回候选框或结构化错误；不传 React、数据库、模型 Key、整个项目或可执行指令，不直接写领域对象。领域函数不因 Worker 执行而 import Worker API。跨线程隔离遵循 [Web Workers 说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)。

取消先在应用同步失效任务，使迟到结果不可提交；Worker 计算按可取消小段执行，无法合作取消的独占任务可由适配器终止后按需重建实例。不能只发送一个取消消息却等待连续同步循环自然结束。项目关闭释放 Worker 和未使用资源；转移像素缓冲区时不得分离仍由预览持有的缓冲区，同一份显示数据不能因计算调度突然失效。允许小规模有界 Worker 池复用独立像素任务；池总并发考虑 PDF.js 自身 Worker、设备与位图内存，不能每页复制整份 PDF 或按 CPU 核数无限建 Worker。不建设通用池平台或持久化后台队列；池契约见[并发与任务调度](并发与任务调度.md)。

#### 拖框与局部编辑

- pointermove 仅记录最新指针位置，使用 requestAnimationFrame 合并当前帧更新；覆盖框与 PDF 背景分层，移动边框不重新解析或重渲染原 PDF。
- 拖动中的 Panel 预览直接从已有页/Figure 位图绘制到预览 Canvas，不每帧编码 PNG/Base64，不触发模型、完整科学校验或数据库写入。真实预览尚未可用时明确显示加载状态；显示缩放不改变原页坐标。预览先按有效源矩形严格裁切，再以 contain 等比显示；若使用 SVG，viewBox 本身不能代替裁切边界，必须限制选区外绘制，侧栏调宽后的留白不得露出邻图。
- pointerup 使用最终指针位置完成一次领域修改、必要校验与保存，不能提交尚未执行的上一帧坐标；Esc/指针取消清理临时帧和草稿。一次拖动/连续键盘微调是一条 Undo，拖动期间已有候选失效规则仍及时生效。
- 文本输入和输入法组合只更新局部草稿；完整编辑结束再提交。阶段进度、选中态或 AI 消息变化不触发全稿校验、整套缩略图布局或会话重建。
- 按内容 ID/revision 复用未改变的视图输入、布局和引用查询；一页讲稿更新只影响其相关页及覆盖提示。不是给每个对象盲目增加 memo，而是避免以全量 ProjectData 变化驱动所有昂贵工作。
- 保留单一 Session 与事务校验：完整提交的必要引用/版本复核不能因优化而省略。避免在 render、进度事件和指针事件中整份 structuredClone；提交和 Undo 仅持有必要内容快照。复用未变内容时保证不可变，不得让新编辑修改历史快照、Current/Previous 或冻结 Paper。

#### 位图分级、缓存与并发

缩略图、当前编辑预览、科学分析输入和最终导出分别决定清晰度与资源寿命。缩略图只渲染可见项目及少量相邻项，目录使用窗口化或等价的按可见范围挂载；保留稳定 ID、选中定位、键盘与拖放行为。不能只用 CSS 隐藏全部高成本预览，也不能为了流畅缩减论文发现、PPT 页数或最终图证据。

同页不同 Panel 优先复用同一适配分辨率的页/Figure 位图，再裁出局部。页位图键包含 documentId 及对应 PDF 资源身份、页码、旋转和渲染尺寸；裁图键另外包含绑定 Paper 身份/版本、来源及有效框，避免混用工作底稿和旧稿。框变更只失效相应派生裁图，未变的 PDF 页位图可继续复用。

预览优先使用 Canvas、Blob/对象 URL 或可释放位图；toDataURL 会把整个图像编码成内存字符串，不作为拖动/批量缩略图的常规路径。需要 Base64 的模型或导出接口只在适配器调用边界转换，消费后释放临时引用；不能把 Base64 写入领域数据或持久化缓存。参见 [Canvas 图像编码说明](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toDataURL)。

缓存同时限制条目数、渲染像素规模与估算占用，预算集中在适配器配置，不写入 Paper/Deck Schema 或新增设置页。估算包含解码位图、Canvas、临时转换及导出持有的资源，不能仅按压缩 Blob 大小计算。正在使用的资源显式保留；淘汰时释放 Canvas、关闭可关闭位图、撤销对象 URL，引用仍在使用时不能提前销毁。单张超预算时不长期缓存，交互预览可降级，但科学分析与最终导出保持所需图源质量。

当前选中内容优先于可见缩略图和相邻预取。渲染、编码与导出资源准备各设有限并发，复用相同请求，禁止对整份论文或全部页面直接 Promise.all 发起高分辨率渲染。取消/换页移除无消费者的待处理任务，已执行任务检查有效性并释放无用结果。共享请求的一个消费者取消不能误杀其他仍需该资源的消费者；缓存淘汰也不等于取消在途任务。这里只管理当前打开项目的内存工作，不改变既有无后台任务队列的边界。

导出使用独立的已保存快照，逐页或小批准备并复用图源；PDF 与图片临时资源在库不再持有时释放。按批让出界面事件处理机会，但不能承诺异步 PPTX 打包自动不阻塞。PptxGenJS 所需的最终文件数据可能保留到打包结束，因此有限渲染并发不等于整个导出恒定内存。打包若需移至 Worker，先核对实际依赖能力，不把未验证的 Worker 导出写成现成能力；无论实现位置，取消/关闭后不得下载迟到结果。

### 图组布局路线与复用边界

本轮确认以递归矩形分区和有限候选评分为首选路线，支持横排、竖排、规则网格及左两图/右一图等常见不等分图组。这里解决 PPT 内多个独立图像如何摆放；论文 Figure 的检测、跨页归属与 Panel 切分仍由前文处理，不用布局算法推断科学归属。

| 参考方案 | 可借鉴或验证的能力 | 本项目采用边界 |
|---|---|---|
| [FigureJ 手册](https://imagejdocu.list.lu/_media/plugin/utilities/figurej/figurej1_manual.pdf) | 面板横向/纵向分割、拖动分隔线、合并区域 | 首选分区交互思路；Java/ImageJ 工具，不直接作为浏览器依赖 |
| [Flickr Justified Layout](https://flickr.github.io/justified-layout/) | 按图像宽高比生成行式矩形布局 | 实施时用同一批图组作对照；需额外处理固定页面高度和科学分组，尚未决定引入 |
| [React Grid Layout](https://github.com/react-grid-layout/react-grid-layout) | 拖动/缩放交互；v2 提供独立 core 几何能力 | 交互备选，不能替代科学分组和可读性判断；仅自有薄交互不足时评估 |
| [QuickFigures](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0240280)、[OMERO.figure](https://www.openmicroscopy.org/omero/figure/) | 科研组图、对齐、标签及可追溯交互；QuickFigures 有可编辑 PPT 导出 | 借鉴科研操作和输出组织，不整体移植其运行环境 |
| [MaxRects](https://github.com/soimy/maxrects-packer) | 矩形装箱与空间利用 | 不作为默认路线；阅读顺序、成组关系和标注可读性仍需另加规则 |

以上是官方资料支持的能力与本项目选型判断，不是 SmartJC 实测结论；本轮不安装依赖。现有 computeLayout 的双图等分和 panel-grid 固定网格是迁移来源，HTML 已确认的大小/间距操作也不代表分区算法已实现。先在同一 fixture 和既有论文图组上比较候选与 Justified Layout，再按阶段 Gate 判断是否足够，不预设效果或速度提升。

#### 有界候选与保存结果

1. 页面规划先按讲稿、结论和用户已定的图像顺序确定图组，包括前置使用附图；几何只接收已选图像实例、有效裁图宽高比、页面可用区域和必要的相邻/顺序限制，不自行丢图或改变科学关系。
2. 对现有每页容量生成有限的横/竖分区形状与比例候选，保留一图、两图及三四图的常见结构；候选上限与比例档位集中在求解器配置。无需枚举所有自由坐标或随机无限搜索，同样输入和配置得到稳定结果。
3. 先淘汰越界、非法引用、比例或内容容量不合法的结果，再比较最小图像展示尺寸、明显尺寸失衡和 contain 后的空白。完整源像素、有效阅读顺序和必要可读性优先于填满页面；仅靠宽高比/面积无法证明图中文字可读，疑点保留人工检查。评分是有界布局启发式，不充当科学校验。
4. 初次规划选择合法候选并将图像实例与分区写入 Plan；无可用结果则回到分页/布局的有限修复，不能静默截图或无限缩小。已有手工页面请求重新排列时先给变化候选；只保存用户应用的结果，不把评分、候选全集或第三方内部结构写入领域数据。
5. 手动比例与间距调整直接对当前分区求几何，拖动时局部预览、结束后一次提交/Undo；不在 pointermove、React render、每次文字输入或导出时运行布局搜索。重算几何与搜索新排列是不同职责。

分区定义、纯求解与校验归 presentation/layout；应用用例协调规划、候选和保存；UI 仅提供预设、分隔线与有限输入，第三方交互值转换到同一契约。布局计算接收普通数据，不依赖 React/DOM 或 PPTX 库，文字测量等外部能力在边界提供；不新建独立拼图平台或第二套导出布局。数据形状见[数据模型](数据模型.md)，合法性见[数据约束](数据约束.md)。

### 共享几何与导出

PDF 页尺寸使用 scale=1 且应用原页旋转的 viewport。布局输入为 Slide、固定主题与图像宽高比，输出统一 ComputedSlideLayout，含标题、元素、来源与文字排版参数；预览转换成显示尺寸，PptxGenJS 转成 PPT 单位，两端不各算一次布局。先由页面布局确定图像可用区域，再按已保存 figureGroup 分割；gapPt 与统一逻辑页面单位换算后求解，像素缩放仅用于显示。输出同时区分分区框与 contain 后的实际图像框，预览和导出都使用同一实际图像框；不能由浏览器 flex/grid 和 PPTX 分别猜位置。导出每个叶子仍是独立可移动缩放的图片，保留来源，不先合成一张位图。

保留白底、16:9 与六布局：标题、文字、一个大图、图文、双图、3–4 图组。panel-grid 保留既有 layoutId，图像区允许规则网格及有限的跨行/跨列矩形分区。1–2 Panel 使用单图或双图；超过容量先调整规划或拆页，不藏元素。图片等比 contain，不用 cover 截证据；同一来源的页码标签去重，显式 Citation 优先于自动脚注。

布局容量保持现有可验证边界，Citation 最多一个并与自动来源脚注去重：

| layoutId | 图与正文容量（不计 Citation） |
|---|---|
| title | 无图，最多一个副标题 text |
| text-only | 无图，最多四个 text / bullet-list |
| figure-full | 一个 Figure，无额外正文 |
| figure-text | 一个 Figure，最多两个短 text / bullet-list |
| two-figures | 两个 Figure，无额外正文 |
| panel-grid | 三至四个 Figure，无额外正文 |

删除元素后仅在布局不再适用时回退：无图 text-only；一图有辅助文字 figure-text，否则 figure-full；两图 two-figures。回退是同批修改，保留仍引用的来源与 cropOverride。手工空页可保存，不通过占位内容伪造证据。

标题、正文采用统一主题与最小可读字号，超预算优先减少非核心屏幕文字、利用讲稿、换布局或拆页，不能无限缩小字体。检查不承诺 Web 与 PowerPoint 像素相同；科研图像不重绘。

幻灯片顶栏调用统一导出用例，检查面板复用其校验结果：先保存输入，捕获 Deck ID/revision、绑定的 Paper ID/revision、完整讲稿与裁图快照，检查非零页、结构引用、布局及必要资源；启动前版本改变须重查，启动后不混入新编辑。快照包含该 Paper 的固定 document → PDF 资源映射；每个图源按 documentId 回到对应文件与页，不能默认从主论文裁图。必需图片全部按此快照裁出，任何必需资源失败就停止，不下载部分文件。

PPTX 中标题/正文为原生可编辑文字，图像可移动缩放，讲稿按 speechIds 写入对应页讲者备注。备注序列按页面顺序和片段顺序导出，不混入未分配段落。notes 由当前讲稿派生，不持久化第二份文本。旧稿没有讲稿不妨碍按原稿导出。导出进度、防重复点击、失败重试和 URL 释放由同一用例管理；项目关闭/删除使任务失效，普通编辑仅影响下一次导出。
