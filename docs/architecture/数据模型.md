# 数据模型与字段定义

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

## 2. 唯一数据契约

以下是 v0.5 的目标领域形状与应用记录，尚未改动运行代码。实际实现以唯一 Zod Schema 派生类型与工具参数；这里只定义职责与必要字段，不维护第二套运行协议。Project/Paper 目标 schemaVersion=2，DeckPlan/Deck=3，PlanRecord recordVersion=2；数据库版本与对象版本分开，迁移见[工作流与存储](工作流与存储.md)。

ID 稳定且不含位置含义；PDF 页码在各文件内从 1 开始，页面定位使用 documentId + pageNumber，Slide 序号仅用于展示。新增/重排不重建既有身份；revision 单调递增，时间为毫秒，写入身份和基准由应用控制，模型不能分配持久化权限。


字段与关系的合法性见 [数据约束](数据约束.md)；应用接口见 [接口契约](接口契约.md)。

Project.lastOpenedStep 仅保存最近成功打开的工作台步骤，用于项目列表的四段进度、筛选及重开定位；允许回退。它不是成果阶段或运行状态，不参与内容 revision、Undo、候选基准或生成权限；checkpoint 继续记录完整产物。缺少此字段的旧项目按实际可访问产物确定首次入口，不能据此清除已有稿件。

### 全局模型设置

独立 settings 记录是全局配置唯一真值，不放进 Project.preferences 或 Paper；ModelSettings 契约由应用配置用例持有，UI 和适配器不各建一份。以下字段已由 M14 的应用配置用例落实；其余 v0.5 对象仍按所属阶段迁移。

| 字段 | 约束 |
|---|---|
| protocol | 固定 responses，不提供协议回退 |
| baseUrl | 归一化后的 HTTP(S) API 根地址，保留服务自定义路径；不含嵌入账号、查询参数、片段或末尾 /responses |
| modelId | 非空去首尾空白字符串，由用户手填，不是固定字面量 |
| apiKey | 凭据字符串，可清除为空；未配置仍可本地编辑，发送请求必须具备凭据 |
| reasoningEffort | 服务默认保存为 null，显式值候选为 none/minimal/low/medium/high/xhigh/max；候选值不意味着所有模型支持。null 在请求中省略 reasoning.effort，不能用字符串 default 或请求 null 代替省略 |

已知服务/模型可按可靠能力信息过滤选项；未知服务标待验证。模型 ID 相同而 Base URL 不同不能复用能力结论；测试使用当前强度，不支持时报告恢复建议，不静默重写配置。配置测试结果是可失效会话状态，不存第二份“永远可用”标志。原型的 hasKey 是模拟凭据开关，不是正式 settings 字段。URL/参数适配及旧设置迁移规则见[模型与部署](模型与部署.md)。

### 项目、全文与来源

```ts
type BBox = { x: number; y: number; width: number; height: number };
type Checkpoint =
  | "project-created" | "pdf-parsed" | "figures-ready" | "paper-ready"
  | "outline-ready" | "deck-plan-ready" | "deck-ready";
type Preferences = {
  instruction: string;
  language?: string;
  targetSlides?: number;
  strategyId?: string;
};
interface Project {
  schemaVersion: 2;
  id: string; name: string; nameIsCustom?: boolean;
  paperId: string;
  currentDeckId?: string; previousDeckId?: string;
  candidate?: DeckCandidateReference;
  checkpoint: Checkpoint;
  preferences: Preferences;
  lastOpenedSlideId?: string;
  lastOpenedStep?: "paper-analysis" | "figure-review" | "outline-speech" | "slides";

}
interface PaperDocument {
  id: string;
  role: "primary" | "supplement";
  fileName: string; pdfAssetId: string;
  pageCount?: number;
}
interface FigurePageSelection {
  documentId: string; pageNumber: number;
  automatic: "pending" | "detected" | "not-detected";
  manualOverride?: "include" | "exclude";
  revision: number;
  processedRevision?: number;
}
interface TextBlock {
  id: string; documentId: string;
  pageNumber: number;
  kind: "heading" | "paragraph" | "caption" | "table" | "other";
  text: string;
}
interface SourceReference {
  id: string; documentId: string;
  kind: "text" | "figure" | "panel" | "caption";
  pageNumber: number;
  bbox?: BBox;
  textSpan?: { blockId: string; start: number; end: number };
  textQuote?: string;
  geometryOrigin?: "automatic" | "manual";
}
interface CaptionAssociation {
  links: { sourceId: string; role: "panel" | "shared" }[];
  origin: "automatic" | "manual";
  status: "linked" | "needs-review";
}
interface FigurePanel {
  id: string; label?: string; sourceId: string; description?: string;
  labelOrigin?: "automatic" | "manual";

}
interface FigureRegion {
  id: string; sourceId: string; panels: FigurePanel[];

interface FigureRef {
  id: string; label?: string; caption?: string;
  captionSourceIds?: string[];
  description?: string; regions: FigureRegion[];

```

PaperDocument.pageCount 仅在实际读取 PDF 后保存，用于各文件进度分母与完整性检查；未知时缺省，不以已保存页数猜测总页数。

### 大纲、演讲稿与文稿

```ts
type LayoutId = "title" | "text-only" | "figure-full" | "figure-text" | "two-figures" | "panel-grid";
type SlideKind = "title" | "background" | "question" | "method" | "result"
  | "summary" | "discussion" | "conclusion" | "custom";
type SectionKind = "opening" | "background" | "question" | "study-design"
  | "results" | "synthesis" | "limitations" | "takeaways" | "discussion" | "custom";
type ContentTrack = "main" | "supplement";
interface DeckSection {
  id: string; kind: SectionKind; track: ContentTrack;
  title: string; purpose: string; transitionToNext?: string;
}
// id 是本页图像实例身份，构建后沿用为 figure 元素的 id。
interface PlannedFigure {
  id: string; figureId: string; regionId?: string; panelId?: string;
  cropOverride?: BBox;
}
type FigureGroupNode =
  | { kind: "image"; imageId: string }
  | {
      kind: "split";
      direction: "row" | "column";
      ratio: number;
      first: FigureGroupNode;
      second: FigureGroupNode;
    };
interface FigureGroupLayout {
  root: FigureGroupNode;
  gapPt: number;
}
interface SpeechParagraph {
  id: string; sectionId: string; purpose: string; segmentIds: string[];
}
interface SpeechSegment {
  id: string; paragraphId: string; text: string;
  claimIds: string[]; sourceIds: string[];
}
interface PlannedSlide {
  id: string; sectionId: string; kind: SlideKind;
  title: string; purpose: string; message: string;
  layoutId: LayoutId; figureGroup?: FigureGroupLayout; speechIds: string[];
  claimIds: string[]; sourceIds: string[]; figures: PlannedFigure[];
}
type SlideElement =
  | { id: string; type: "text"; text: string }
  | { id: string; type: "bullet-list"; items: string[] }
  | { id: string; type: "figure"; figureId: string; regionId?: string; panelId?: string; cropOverride?: BBox }
  | { id: string; type: "citation"; sourceIds: string[] };
interface Slide {
  id: string; sectionId: string; kind: SlideKind; title: string;
  purpose?: string; message?: string; layoutId: LayoutId;
  figureGroup?: FigureGroupLayout;
  speechIds: string[]; elements: SlideElement[];
  claimIds: string[]; sourceIds: string[];
}
interface CoverageOmission {
  claimId: string;
  reason: string;
  origin: "user";
}
interface DeckPlan {
  schemaVersion: 3;
  id: string; paperId: string; paperRevision: number;
  revision: number; status: "draft" | "ready";
  title: string; language: string;
  sections: DeckSection[]; speechParagraphs: SpeechParagraph[]; speech: SpeechSegment[];
  slides: PlannedSlide[]; omissions: CoverageOmission[];
  createdAt: number; updatedAt: number;
}
interface Deck {
  schemaVersion: 3;
  id: string; paperId: string; paperRevision: number; revision: number;
  title: string; language: string;
  sections: DeckSection[]; speechParagraphs: SpeechParagraph[]; speech: SpeechSegment[]; slides: Slide[];
  omissions: CoverageOmission[];
  createdAt: number; updatedAt: number;
}
```

FigureGroupLayout 由 PlannedSlide 和 Slide 共用，保存本页图像区域的矩形分区与间距，不保存预览像素坐标或候选评分。叶子 imageId 指向本页 PlannedFigure.id / figure 元素 id，不能使用源 Figure/Panel 身份代替；同一来源跨页复用时独立调整。row 表示左右分区，column 表示上下分区；ratio 是扣除该分隔间距后 first 占可用长度的比例，gapPt 使用 PPT 点（1/72 英寸）。例如左侧 A/B 上下、右侧 C 通高，由左右根分区的 first 再做上下分区表达。

figureGroup 可缺省仅用于无图页与旧稿兼容；新生成有图计划必须保存明确布局，单图使用一个叶子。字段约束、旧稿兼容及共享几何分别见[数据约束](数据约束.md)、[工作流与存储](工作流与存储.md)和[图源与渲染](图源与渲染.md)。本轮完善尚未实施的 v3 目标契约，不额外增加版本号。

### 工作计划的基准记录

Project、Preferences、GenerationBase 与 DeckCandidateReference 归 project；PlanRecord 是应用记录，组合 project 的公开元数据与 presentation 的 DeckPlan。领域不得反向导入 PlanRecord；代码归属和依赖方向见[分层与模块](分层与模块.md)。

```ts
interface GenerationBase {
  projectPreferences: Preferences;
  paperId: string;
  paperRevision: number;
  figureReviewRevision: number;
  current?: { deckId: string; revision: number };
  previous?: { deckId: string; revision: number };
}
interface DeckCandidateReference {
  deckId: string;
  generatedFrom: { planId: string; planRevision: number };
  generationPreferences: Preferences;
  base: GenerationBase;
}
interface PlanRecord {
  recordVersion: 2;
  projectId: string;
  stage: "outline-ready" | "deck-plan-ready";
  plan: DeckPlan;
  generationPreferences: Preferences;
  mode: "initial" | "regeneration";
  base: GenerationBase;
}
```

Project.candidate 指向 decks 中唯一完整重生成 Deck，正文、讲稿、图组及 Paper 绑定仍由该 Deck 保存，不复制到 Project。引用保留生成时的计划身份、实际生成偏好与独立基准；generatedFrom 仅记录来源，不要求原 PlanRecord 持续存在或仍是活动计划。候选是否过期、是否可应用由当前事实重算，不保存 stale/canApply 或请求权限。GenerationBase 由计划与候选共用；首次生成仍直接提交 Current，只有重生成候选要求 base.current。既有项目缺 candidate 表示无已保存候选，不从历史消息或半成品推造。沿用尚未实施的目标版本号，不新增 store。

base.projectPreferences 是本轮开始时已保存 Project.preferences 的独立快照，只用于基准比较；generationPreferences 是该计划/候选实际使用的完整偏好，可包含本轮新选 strategyId，不能用它与当前项目偏好做相等检查。两份均按唯一 Preferences 契约归一化，不保留可被原地修改的共享对象。保存工作计划或候选不改写项目默认偏好；首次稿提交或显式应用候选成功时，才与文稿切换同事务提交 generationPreferences。两者不得互相回填来使过期结果通过。
