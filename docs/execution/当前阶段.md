# v0.5 实施顺序与阶段 Gate

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

## 1. 执行约定

M0–M12 保留为已完成的历史阶段；v0.5 按 M13 → M14 → M15 → M16 → M17 → M18 逐个推进。本轮仅授权 M13 文档，完成后停止，后续每个里程碑另行授权。开始前检查最新用户要求、相关设计目录、现有代码和未提交改动；只处理当前阶段需要的模块。主分支为 `main`，每个里程碑实施前从 `main` 创建独立的 `milestone/m<编号>` 分支；上一阶段验收、记录并合并后再开始下一阶段。

2026-09-07 用户先要求复核并讨论，随后依次授权完成 M11 与 M12。两个里程碑均在各自分支完成实现、验收和记录后合并到 `main`；已有提交与有效历史证据按其版本边界保留。

复用顺序为现有代码、已选依赖官方能力、必要薄封装。沿用已接入的 React + TypeScript + Vite + Tailwind CSS。M8 已按[分层与模块](../architecture/分层与模块.md)迁移 app/modules/shared 的真实职责并保持 v0.3 行为；M9 以 `preparePaper()`、`prepareOutline()`、`buildPresentation()` 落地显式 workflow；M10 已以 pi-agent-core 替换交互式通用轮次循环。v0.5 以现有实现为迁移来源，按[分层与模块](../architecture/分层与模块.md)归位 UI / Application / Domain / Infrastructure：三个核心领域为 project、paper、presentation；生成编排和 Agent 接线归 app，外部能力与数据库实现归 infrastructure。按各阶段实际职责渐进迁移，不保留两套生成工作流。不得围绕未来平台预建空目录、空接口、通用 validator framework 或第二套实现。

协作习惯和日常工作流程见根目录 [AGENTS.md](../../AGENTS.md)。[产品目录](../product/README.md)维护范围，[UI 目录](../ui/README.md)维护页面规格，[架构目录](../architecture/README.md)维护数据/接口/运行契约，本计划只规定交付和 Gate。实现发现冲突时修正对应权威段落和受影响引用，不在末尾追加第二套“最终定义”。

每个里程碑完成后将实际工作情况写入 `docs/spec/M<编号>.md`，包含完成内容、关键变更、验证证据、未解决问题及 Gate 结论；格式和分支收尾流程遵循 AGENTS.md。本文记录区只同步状态、结论和记录链接，不复制详细报告或另建日报。验收通过、记录提交后自动合并回 `main`；未通过时保留工作分支并如实记录阻塞。技术参数以实际测量为准，未验证项明确标注。

## 2. 阶段交付

### v0.5 阶段顺序

以下为已确认产品方向的实施拆分；当前只授权 M13 文档，M14–M18 尚未实施，不能因列入计划自动开工。每轮仅推进一个另行授权的里程碑。

| 阶段 | 唯一主要目标 | 当前状态 |
|---|---|---|
| M13 | v0.5 设计契约统一 | 已完成；仅文档，静态 Gate 通过，见 [M13 工作记录](../spec/M13.md) |
| M14 | 文章本位的论文底稿与证据版本 | 未实施 |
| M15 | 自动切分改进与手动核对工作台 | 未实施 |
| M16 | 讲稿与幻灯片分步生成 | 未实施 |
| M17 | 固定窗口的汇报编辑工作台 | 未实施 |
| M18 | 新主链、切分与初稿质量验收 | 未实施 |

### M13：v0.5 文档设计

目标：同步本轮已确认的全文底稿、Figure 切分与手动核对、核对后生成讲稿、主动分步推进与各步编辑、大纲/演讲稿共同规划、主线与补充及版本保护；同阶段补充四层/三个领域的明确依赖、状态与影响表；用户已确认新建流程内完成项目准备及一主一补 PDF 输入，图源核对、大纲讲稿与幻灯片 HTML，并确认将检查与导出合并到幻灯片；按目录维护 UI、数据模型、约束与接口文档。

本阶段仅维护设计文档及其目录、用户已授权的 HTML 原型、AGENTS.md 与 docs/spec/M13.md。直接替换有效旧冲突，保留 M0–M12 的历史实施与验证信息；不改 src、prompts、tests、依赖、构建、工作流，不新建业务空壳。已有未跟踪任务书保留，不吸收为已确认设计。

Gate：用户确认事项可逐项在产品/架构/本计划定位；不残留跨步骤自动推进、逐段确认大纲、固定默认页数、只允许单页裁图或 Notes 仍为候选的矛盾；类型形状、层次/模块所有权、阶段、上下游失效、人工切分与旧稿保护一致；UI 主操作、图源工具、直接编辑、AI 收起、桌面分栏调节与焦点有可实施说明，计算分离/局部更新/有界资源与架构一致，线框、已有有效控件及异常状态未无故丢失；本地链接、术语、Markdown、差异白名单与 git diff --check 通过。仅文档 Gate，完成后提交、合并并仅推 main，然后停止。

### M14：全文底稿与版本基础

目标：让 Paper 真正承载完整文章而非 PPT 摘要，并保护既有 Current/Previous。

涉及：project/paper 领域、相关 app 用例与 infrastructure 的 PDF/存储接线，以及旧 outline/deck 的必要引用迁移。先为本阶段触及代码落实单向依赖：纯定义/校验留领域，解析调用顺序归应用，PDF/数据库归适配器；不预搬所有 UI 或生成模块。按[数据模型](../architecture/数据模型.md)与[工作流](../architecture/工作流与存储.md)将全文转为可定位块，关联原句/段落、实验观察、Claim、Figure/Panel；保留多对多反向查询，不按篇幅删除发现。实现工作 Paper 与冻结证据 Paper 的归属、复制、引用和有界回收，不改 PDF 关联、不创建版本树。

交付与 Gate：本阶段已迁模块不反向依赖 React/DOM/数据库，实际公开入口及依赖方向纳入轻量检查；旧 v0.3/v0.4 当前/上一版完整可打开、旧图框及科学内容保留；旧单 PDF 幂等迁移为主文档，同页码/图号的主辅文件定位不串用、创建全部文件事务失败不留半项目；旧稿缺讲稿或精确句子关系明确未生成，不被强制补全；迁移幂等/失败保留、不同文稿绑定不同 Paper、跨项目引用拒绝、原句片段定位及关联保护通过。使用同一 fixture 派生风险输入，复用已有论文观察全文提取缺口。该阶段不宣称新切分算法、手动核对或分步新链已完成。

### M15：Figure 切分与核对工作台

目标：降低真实切分错误，并让用户直接修正自动结果。首先建立可复用固定窗口外壳及图源视图，其他视图暂接现有功能；不在本阶段夹带讲稿生成。

涉及：paper/figures 纯几何与内容操作、app 图源用例/分析步骤、infrastructure/pdf/llm/persistence 适配器、ui/workspace 和 ui/paper。纯像素规则接收数据，重计算由 Worker 适配器执行，PDF/Canvas 不进入领域；拖框复用位图并合并帧更新、松手一次保存，同页裁图复用及资源并发有界。会话/核对与保存失败通过应用用例连接 UI。按[图源核对规格](../ui/图源核对.md)、[图源与渲染](../architecture/图源与渲染.md)实现整图定位、局部高清识别、像素间隙辅助、疑点检查及原页/裁图联动。加入整图/Panel 拖框、缩放、补删、改标签、Undo/Redo、恢复自动基线与候选重识别；共享图例允许适度重叠，不抹白或强行归网格。

核对确认绑定切分版本，任何身份/标签/几何变化使其失效；模型重识别不得覆盖人工结果。来源级修改保护旧稿，单页 cropOverride 继续独立。用户只改可视对象，系统维护 ID 与证据关联。落实 Panel 专属/共享图注、完整图注高亮及手动关联保护；关联调整不新增人工暂停点。

Gate：既有三篇图源中选实际有风险的图，与当前自动框比较漏 Panel、切断坐标/图例、串图和手动修框操作；至少包含共享图例、不同 Panel 尺寸与必要旋转/缩放坐标风险，不新建论文矩阵。固定响应覆盖保存/取消/重试/恢复/旧响应，浏览器实操拖框与撤销、局部重新识别、刷新保留人工框及核对失效。真实结果未改善就记录具体失败，不以“像素算法已接入”宣称准确率提高。完整工作台外壳按[工作台与图源规格](../ui/README.md)重新实现，不仅搬旧卡片：两行导航/主操作、对象筛选、八手柄与添加模式、自动保存、候选对照、键盘/分隔线及固定滚动所有者实际检查通过。

### M16：大纲、演讲稿与分步生成

目标：主论文及可选补充 PDF 的全文、图源、证据共同完成准备；任一文件失败不得提前推进。用户确认切分后自动完成大纲与讲稿并停在编辑页；用户进入幻灯片后自动规划并制作页面草案，在当前工作台完成编辑、检查和导出。步骤内可暂停和编辑，保留同一组生成用例。

涉及：presentation/planning 与 editing 共享内容定义、app/workflows 和提交用例、阶段 Prompt/模型适配，以及大纲讲稿 UI 接线。把旧 outline/deck 的领域职责收敛到 presentation；保留两个会话而复用共同纯规则，把项目 hook 的阶段分支与任务生命周期移到可脱离 React 执行的用例。复用 M14 底稿，按证据生成完整讲述，再决定页面。主线/补充默认充分覆盖发现，显式篇幅要求或人工删除才形成省略记录；去掉双重预算、focus 最少页数和逐条人工 confirmed 字段，下一步操作授权与程序 ready 校验分开。程序处理来源登记、布局分配与有限修复，不要求用户填字段排错。

保存 outline-ready 与 deck-plan-ready；ready 是程序就绪而非用户确认。支持用户进入下一步、步骤内立即暂停/取消、继续、刷新恢复；上游编辑失效旧任务，仅重做依赖内容；阶段进度与 AI 消息不触发整稿重复校验、复制或无关视图重建。Build 遵守所绑定计划与讲稿版本，失败保护稳定稿。

Gate：应用层在无 React/真实模型时可用窄替身测试步骤内推进、步骤间停止、迟到结果、失败与版本冲突；同一 fixture 主链在切分核对后保存完整讲稿并停止，用户进入幻灯片后得到完整 Deck；在同项目另行操作步骤内暂停、编辑大纲/讲稿、继续和取消，旧响应不覆盖人工改动。原句/图证据进入规划上下文，覆盖缺口与科学不确定分开，自动格式修复有上限。用已有代表论文必要真实调用验证新链和模型原稿，不用历史人工稿或固定响应证明生成质量。

### M17：汇报编辑工作台与讲稿同步

目标：项目管理和新建弹窗接入一主一补 PDF 创建与保存；把大纲/讲稿、含检查与导出的幻灯片接入 M15 的同一固定窗口外壳，完成生成后的修改闭环。

涉及：ui/workspace、ui/presentation、presentation/editing/layout、app 的内容提交/导出用例与 assistant 接线、infrastructure/pptx。完成剩余旧编辑/Agent/导出职责归位，界面 hook 不承载事务或工作流；按可见范围挂载缩略图，讲稿局部更新，预览/导出清晰度和缓存分离，导出按有限批次准备资源并处理迟到结果；工具调用同一内容用例，不复制手工编辑规则。左侧主线/补充与章节缩略图，中间 Canvas，下方当前页讲稿，右侧 Inspector/AI；底部为共用紧凑状态条和按需展开 AI 输入；主操作固定、低频操作进菜单。支持分页/合页、多选删页、重排、讲稿编辑和受影响页面更新候选；讲稿与 Panel 为多对多，多图按结论组合，跨 Figure/附图可提前讲述，组内顺序/大小/间距在有限图组控件调整；删除不删除论文发现，不要求用户修预算。

手工与 AI 修改沿同一提交/提案/Undo；更新候选不能覆盖人工内容。Current/Previous 一并保存讲稿与论文绑定，导出讲稿到 PPTX 对应页备注，保留原生文字与图像。

Gate：按[工作台、讲述与编辑规格](../ui/README.md)重新设计讲述、幻灯片与其检查面板；在桌面窗口检查关键操作入口和用户主动调节分栏，不增加响应式断点或窄屏适配 Gate，复用同一主链，不复制全套 E2E。外层不成长网页，内容区域独立滚动；验证对象往返定位、直接编辑、讲稿调高/收起、AI 展开、键盘/输入法和对话框焦点，不能用缩小字体或只断言无横向溢出替代验收。实际验证生成后大纲可编辑、删页保留讲稿并同步未分配状态、手工内容冲突与版本恢复；顶栏/检查统一导出，普通叙事警告不成为逐项确认门槛，资源/引用错误仍拦截。沿同一主链验证 PPTX 页与备注对应。

### M18：v0.5 内容与交付验收

目标：证明新的切分和分步生成链让用户少修图、少补内容，同时验证兼容、离线与真实导出。

沿[验证策略](验证策略.md)中的同一组 fixture、主链和机制/组学/临床三篇论文执行。区分自动切分、人工修框、模型初稿、人工编辑后的稿；M12 的旧稿与 PowerPoint 检查仅作为历史基线，不能代替新稿、讲稿备注或切分质量。

Gate：目标四层和三个领域归位，移除已无调用的旧路径重导出，无重复 workflow/修改入口；三篇分别核对全文提取完整性与已提取发现的汇报覆盖，主线/补充可查，原句与 Panel 对应可核查，演讲稿解释与页面证据一致；核对后完成讲稿并停止，用户进入幻灯片步骤后自动完成页面，不要求用户找内容或修模型格式。记录图源漏检/边界/串图、人工修框次数、默认生成耗时/失败重试、需人工改动页面和实际内容缺口，不建立覆盖率目标或模型裁判平台。真实 PowerPoint/可用 Keynote 打开新导出，文字可编辑、图像不拉伸、每页备注正确；旧稿/Previous、离线图源编辑与导出、更新及实际 Pages 通过。外部条件未通过则记录未完成，不放宽 Gate。
