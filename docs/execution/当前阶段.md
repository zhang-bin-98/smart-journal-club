# v0.5 实施顺序与阶段 Gate

> v0.5 分阶段实施；M14–M16 已完成且 Gate 通过，当前状态见 [执行目录](../execution/README.md)。

## 1. 执行约定

M0–M12 保留为已完成的历史阶段；v0.5 按 M13 → M14 → M15 → M16 → M17 → M18 → M19 逐个推进。M13 文档已完成；2026-09-10 用户依次授权实施 M14 与 M15，两阶段实现及必要验收均已完成。随后用户授权 M16，2026-09-11 完成实现、真实切分对照及必要验收。后续里程碑仍按各自 Gate 逐个推进。开始前检查最新用户要求、相关设计目录、现有代码和未提交改动；只处理当前阶段需要的模块。主分支为 `main`，每个里程碑实施前从 `main` 创建独立的 `milestone/m<编号>` 分支；上一阶段验收、记录并合并后再开始下一阶段。

2026-09-07 用户先要求复核并讨论，随后依次授权完成 M11 与 M12。两个里程碑均在各自分支完成实现、验收和记录后合并到 `main`；已有提交与有效历史证据按其版本边界保留。

复用顺序为现有代码、已选依赖官方能力、必要薄封装。沿用已接入的 React + TypeScript + Vite + Tailwind CSS。M8 已按[分层与模块](../architecture/分层与模块.md)迁移 app/modules/shared 的真实职责并保持 v0.3 行为；M9 以 `preparePaper()`、`prepareOutline()`、`buildPresentation()` 落地显式 workflow；M10 已以 pi-agent-core 替换交互式通用轮次循环。v0.5 以现有实现为迁移来源，按[分层与模块](../architecture/分层与模块.md)归位 UI / Application / Domain / Infrastructure：三个核心领域为 project、paper、presentation；生成编排和 Agent 接线归 app，外部能力与数据库实现归 infrastructure。按各阶段实际职责渐进迁移，不保留两套生成工作流。不得围绕未来平台预建空目录、空接口、通用 validator framework 或第二套实现。

协作习惯和日常工作流程见根目录 [AGENTS.md](../../AGENTS.md)。[产品目录](../product/README.md)维护范围，[UI 目录](../ui/README.md)维护页面规格，[架构目录](../architecture/README.md)维护数据/接口/运行契约，本计划只规定交付和 Gate。实现发现冲突时修正对应权威段落和受影响引用，不在末尾追加第二套“最终定义”。

每个里程碑完成后将实际工作情况写入 `docs/spec/M<编号>.md`，包含完成内容、关键变更、验证证据、未解决问题及 Gate 结论；格式和分支收尾流程遵循 AGENTS.md。本文记录区只同步状态、结论和记录链接，不复制详细报告或另建日报。验收通过、记录提交后自动合并回 `main`；未通过时保留工作分支并如实记录阻塞。技术参数以实际测量为准，未验证项明确标注。

### M13：v0.5 文档设计

目标：同步本轮已确认的全文底稿、Figure 切分与手动核对、核对后生成讲稿、主动分步推进与各步编辑、大纲/演讲稿共同规划、主线与补充及版本保护；同阶段补充四层/三个领域的架构图和模块依赖图、内部数据所有者、应用会话提交/编辑登记，以及候选生成偏好与冲突基准分离；用户已确认新建流程内完成项目准备及一主一补 PDF 输入，图源核对、大纲讲稿与幻灯片 HTML，并确认将检查与导出合并到幻灯片；按目录维护 UI、数据模型、约束与接口文档。最新确认拆为论文分析、图源核对、大纲与演讲稿、幻灯片四步，分析页查漏补选且完成后手动进入下一步；小规模本地计算池与统一 API 调度分离。

本阶段仅维护设计文档及其目录、用户已授权的 HTML 原型、AGENTS.md 与 docs/spec/M13.md。直接替换有效旧冲突，保留 M0–M12 的历史实施与验证信息；不改 src、prompts、tests、依赖、构建、工作流，不新建业务空壳。已有未跟踪任务书保留，不吸收为已确认设计。

Gate：用户确认事项可逐项在产品/架构/本计划定位；不残留跨步骤自动推进、逐段确认大纲、固定默认页数、只允许单页裁图或 Notes 仍为候选的矛盾；类型形状、层次/模块所有权、阶段、上下游失效、人工切分与旧稿保护一致；UI 主操作、图源工具、直接编辑、AI 收起、桌面分栏调节与焦点有可实施说明，计算分离/局部更新/有界资源与架构一致，线框、已有有效控件及异常状态未无故丢失；本地链接、术语、Markdown、差异白名单与 git diff --check 通过。仅文档 Gate，完成后提交、合并并仅推 main，然后停止。

### M14：模型接入与配置

目标：用户可以在正式配置页保存和验证 Responses 模型，所有已有模型请求经同一调度入口运行。

前置：M13 设计文档已确认，继续以 v0.4 代码和已选依赖为迁移来源。涉及应用配置用例、请求接口与 composition、infrastructure/llm/persistence，以及[模型配置页](../ui/模型配置.md)和实际调用入口；本阶段不迁移论文底稿或重写生成内容。

交付：

- 落实全局 ModelSettings 的唯一契约、纯归一化/校验、旧设置迁移与保存/清除；接入独立设置页的 Base URL、模型 ID、思考强度、来源返回、连接检查和应用能力检查。保存失败保留草稿与旧值，运行中禁止变更，不自动启动论文任务。
- 复用 Pi 的 Responses 适配边界，核对图片、工具调用、结构化结果、流式与取消；“服务默认”真正省略 reasoning.effort，显式档位不被 SDK 默认值或截断逻辑改写。不能用旧 DeepSeek 接入证据替代本次验证。
- 将[统一 API 调度](../architecture/并发与任务调度.md)接入配置测试、固定 workflow、修复及 Pi Agent 的已有请求路径，composition 共享限额桶。按并发/请求频率/Token 预算、优先级与公平性、统一退避及取消处理，不留绕过调度的第二个模型入口；本地计算池留在论文处理阶段接入。
- 设置页先从既有入口进入；M15 新建流程再接入同一返回契约及文件草稿，不为尚未存在的创建会话预建空实现。

Gate：通过配置页完成保存、连接/能力检查、清除与返回，真实浏览器确认必要能力及强度映射，错误与取消不回填旧结果或回显 Key；固定响应验证共享桶在途/频率预算、等待可中断、公平性、SDK 重试不叠乘及已有模型路径无旁路。迁移不擅自向新主机复制旧密钥，旧项目本地查看/编辑/导出仍可用。迁移到本阶段的模块依赖纳入现有轻量检查，不引入新框架。

### M15：项目与论文分析

目标：用户能够新建一主一补 PDF 项目，完成全文分析，查看进度和全部页缩略图，并补选漏图页。

前置：M14 配置页、模型能力及统一 API 调度已通过。涉及 project/paper 领域、app 项目/分析用例、infrastructure/pdf/persistence 与必要 Worker 适配器、ui/workspace、项目管理和论文分析视图。先落实项目/底稿及旧稿兼容，再接创建与分析 UI；复用已有分析算法形成可用图源，切分算法改进及手工核对在 M16 交付。

交付：

- 按[项目准备](../ui/项目准备.md)接入项目管理、存储估算/资产统计、搜索/筛选、重命名/删除与新建弹窗。一份主论文及可选一份补充 PDF 连同项目同事务保存；支持“保存，稍后开始”和“开始分析”。进入 M14 设置页再返回时保留实际文件 Blob 和输入，保存失败不留下半项目。
- 按[数据模型](../architecture/数据模型.md)与[工作流](../architecture/工作流与存储.md)落实本阶段的 project/paper 迁移：完整 TextBlock、原句定位、Figure 多图块、Panel、Claim–Evidence–Source 与跨文件引用。paper 的 document/figures/evidence 由聚合纯操作协调，不反向依赖聚合入口；不按 PPT 篇幅删减发现。
- 保护工作 Paper 与 Current/Previous 各自绑定的证据版本，落实复制、归属检查和有界资源回收；旧图框、稳定 ID、科学内容与旧稿可用性保留。迁移幂等、失败保留，缺失讲稿或精确关系不编造，不以新门槛锁住旧稿。
- 接入双文件分析 workflow、PDF.js Worker 与有界本地计算/图片资源管理；独立页经 M14 调度受限并行，完整全文与跨文件证据统一汇总。完整单元及 inputKey 同事务保存，乱序结果按身份合入最新底稿；任一必需材料失败不提前就绪，刷新后手动续跑未完成/失效部分。
- 建立后续页面复用的固定窗口外壳和应用状态查询，完成[论文分析页](../ui/论文分析.md)：文件/页/阶段计数、排队/限流等待、全部缩略图、人工补选/排除与左栏汇报要求。分析结束留在本页，下一步由用户主动操作；论文 AI 仅只读问答。列表进度跟随最近成功打开步骤，保留已有 PPT，不把浏览位置当成果或运行权限。

Gate：从正式 UI 创建双 PDF 项目、进入设置后返回、分析/暂停/取消/刷新续跑、补选局部处理与保存失败通过；同页码/图号不同文件不串用，兄弟单元提交不丢失或误使彼此失效，人工覆盖优先于旧任务。实际检查原句定位、可提取全文/图注/方法与发现，不以结构摘要或字段合法冒充覆盖完整。用同一 fixture 验证创建/迁移回滚、旧单 PDF 迁为主文档、旧单图保留为稳定单页图块、跨项目引用拒绝、旧稿证据绑定和恢复；用既有论文的必要真实分析验证提取缺口。Worker 消息/释放/崩溃恢复用少量真实浏览器检查，外壳与存储显示按真实操作验收。

### M16：图源核对

目标：降低真实切分错误，用户可以完整检查和修正图源，刷新后保留结果且旧稿不受破坏。

前置：M15 已提供可保存/续跑的论文底稿、图源、分析页和公共外壳。涉及 paper/figures 与聚合纯操作、app 图源用例/编辑登记、PDF/Worker/模型/存储适配器和图源核对 UI；复用 M14 调度，不另建计算或请求平台。

交付：

- 按[图源与渲染](../architecture/图源与渲染.md)实现整图定位、局部高清识别、像素间隙辅助、疑点检查及原页/裁图联动。纯像素规则接收数据，有界 Worker 执行重计算；拖框复用位图并合并帧更新，松手一次提交，同页裁图和缓存有界，不将 DOM 引入领域。
- 接入[图源核对页](../ui/图源核对.md)：从分析页手动进入、连续滚动图卡、筛选与选中联动、八手柄/缩放、统一添加 Figure、标题原位可写可选图号及归入已有图的确认、补删 Panel/改标签、整图边界、Undo/Redo、自动保存、恢复自动基线及重识别候选对照。共享图例允许适度重叠，不抹白或强行归网格。
- 单图允许无 Panel；成功处理但漏整图的原页保留人工框选入口。改归属保留图块/Panel/Source 身份与几何，同批维护引用；图注提供专属/共享关联、完整图注高亮及手动关联保护，必要原文证据局部刷新不增加逐项确认门槛。
- 整体核对确认绑定切分版本，身份/标签/几何变化使其失效；来源级修改走工作底稿复制规则，保护 Current/Previous，单页 cropOverride 保持独立。重识别只给候选，不能覆盖人工结果；图源 AI 只读，重新识别仅由按钮触发。
- 首次实际编辑登记目标与基准，保存失败保留输入与登记；保存中再编辑不被旧回调解除保护，成功后才推进撤销历史。确认成功保存后，生成讲稿由 M17 接入，不伪造尚未交付的下一阶段成果。

Gate：用既有三篇中的风险图比较原始自动框、改进结果与人工修框，包含漏 Panel、切断坐标/图例、串图、共享图例、不同尺寸及必要旋转/缩放风险；没有改善时记录具体失败，不以“算法已接入”宣称准确率提高。固定响应及同一浏览器主链验证添加/改归属/取消、拖框/键盘、重识别候选、保存失败、Undo/Redo、刷新保留和核对失效。两行导航、工具入口、分隔线调节、严格裁切、独立滚动、输入法/焦点实际可用，不以缩小字体或只检查横向溢出替代验收。

### M17：大纲与演讲稿

目标：用户确认切分后得到充分覆盖发现的讲稿，可调整章节/段落与图证据，通过 AI 预览修改、撤销、保存和重开。

前置：M16 图源核对、必要证据关联与版本保护已通过。涉及 presentation/content/planning、必要 Deck 共用内容兼容、应用 PlanRecord/OutlineSession 和实际需要的 Deck 讲述提交接线、app/workflows/assistant、相关阶段 Prompt 与[大纲讲稿 UI](../ui/大纲与演讲稿.md)。共用定义/纯规则按本阶段真实调用迁移，不预建幻灯片构建或排版空壳。

交付：

- prepareOutline 复用完整 Paper 和核对版本，以原句、图注和实际图证据生成稳定章节、SpeechParagraph 与 SpeechSegment，多对多引用可反查；默认覆盖全部发现并区分主线/补充。去掉固定预算、focus 最少页数及逐条人工 confirmed 门槛，用户明确压缩或人工舍弃才形成省略记录。
- 保存完整 outline-ready 后结束任务，供用户编辑，不提前规划页面或生成 PPT；可暂停/取消、有限修复和刷新续跑，失败保护已保存计划与旧稿，不让用户补 ID、来源登记或修模型格式。
- PlanRecord 归应用，内容规则归 presentation；应用 Session 经唯一提交入口保存，成功才更新已保存状态和 Undo。计划的 base.projectPreferences 与 generationPreferences 分离，切换叙事策略不误判过期，项目默认偏好另改仍使旧基准失效。
- 在同一外壳接入跨章节连续滚动、章节/段落新增删除与拖动重排、主线/补充、直接编辑、多 Panel 证据选择和右栏调节；讲稿/引用只保存一份，稳定段落和来源不因排序重建。已有 Current 的大纲视图编辑其讲述内容，不从消费后的 Plan 回写；本阶段落实所需兼容与提交规则，旧稿无讲稿不编造。
- 接入大纲 AI 的读/提案/差异/应用与一次 Undo；生成前可独立绑定有效 Plan，已有 Deck 则绑定 Current 的讲述白名单，不要求空 Deck。发送后范围固定，浏览不改目标，草稿冲突或 Plan/Deck 切换拒绝旧提案；局部提案仅会话内保存。

Gate：同一 fixture 从已确认图源生成并保存完整讲稿后停止，无 Deck 也能编辑、AI 提案、撤销和重开；用户可以调序并核对多图证据，不出现重复正文或悬空引用。固定响应验证应用流程脱离 React/真实模型运行、有限修复、旧响应拒绝、保存/撤销失败不推进会话或游标、保存中继续输入保护及偏好基准检查。既有代表论文的必要真实生成检查自动原稿的发现覆盖、主线/补充、证据与措辞强度，不能用人工稿或固定响应代替质量证据。章节导航、连续滚动、输入法/焦点与 AI 交互通过实际 UI 验收。

### M18：幻灯片

目标：用户主动进入幻灯片步骤后，按讲稿生成、编辑和导出 PPT，完整候选可保存、重开和显式应用。

前置：M17 已交付可编辑的完整讲稿、应用会话和偏好基准。涉及 presentation/planning/editing/layout/build、应用 DeckSession/生成/候选/导出用例及助手、相关 Prompt、infrastructure/pptx/persistence 和[幻灯片与检查 UI](../ui/幻灯片与检查.md)。继续复用调度、外壳、编辑登记与内容规则，不复制第二套 workflow/修改入口。

交付：

- 用户进入下一步才调用 planSlides，分配页面、讲稿、来源与布局并保存 deck-plan-ready，随后步骤内自动 Build。程序 ready 与用户进入下一步授权分开；构建纯映射/合同在 presentation/build 组合 Plan/Deck，严格沿用身份、页序、讲稿、来源和图组，不再次自由规划。分页可细分片段但保留段落身份；暂停/编辑/取消后旧任务不能覆盖人工内容。
- 图组按有限矩形分区和候选评分规划，保存页内图像实例、分区比例、间距和 cropOverride，预览与导出共用几何。以既有图组实际宽高比对照 Justified Layout，保留失败样例；算法选择、六布局容量、旧稿几何及候选应用边界沿[图源与渲染](../architecture/图源与渲染.md)，React Grid Layout 仅作交互备选，不因列入文档安装。
- 按固定窗口规格完成章节/缩略图、中间 Canvas、下方当前页讲稿和右栏 Inspector/AI/检查、底部 AI 输入与持续保存/任务状态。交付分页/合页、多选删页、移页/重排、来源定位、单页裁图、常见不等分图组预设、比例/间距键盘输入及重排候选；分栏与讲稿高度可调，缩略图按可见范围挂载，局部修改不重建整稿。
- 讲稿与页面分配同批维护，跨章合页不隐式迁移段落章节，删页保留未分配讲稿；生成后的大纲继续编辑 Current。备注从唯一讲稿派生，普通措辞或页面更新建议不阻断导出；非法引用/分配/备注、资源缺失及页面溢出必须处理，人工弃图/省略仅提醒。
- 手工和幻灯片 AI 通过相同应用 Session、提案与 Undo；共享页面能力限制并保护人工输入。完整首次稿原子保存为 Current；重生成候选与 Project.candidate 同事务保存、冻结其 Paper，替换/失败/过期/放弃/应用/资源回收按[工作流与存储](../architecture/工作流与存储.md)执行。新策略候选可应用，成功切换才提交实际生成偏好；Current/Previous 各自保留讲稿和证据绑定。
- 检查仅在右栏 Tab，导出统一复核已保存稿；有界准备图像资源、取消无迟到下载，输出原生可编辑文字、独立图片及对应讲者备注。保留旧稿查看/编辑/导出与既有 PWA 能力，不改变发布配置。

Gate：同一主链从讲稿主动生成完整 PPT，编辑/分页/组图/AI 应用后导出；固定响应与真实存储验证构建合同、引用/分配/几何、保存失败不推进 Undo、候选保存/重开不重跑 Build、二次生成失败保护旧候选、过期只读及原子切换/回收。实际 UI 检查源图/讲稿往返、删页未分配、普通提醒可导出、硬错误拦截、图组一次 Undo/刷新与旧稿兼容，跨步骤浏览后项目列表进度可回退且成果不丢。必要真实生成检查页面初稿，实际 PowerPoint 打开确认文字可编辑、图像比例和备注对应；不把真实 PPTX 验证推迟到最终阶段，不扩展浏览器或模型组合矩阵。
