# 验证范围与执行策略

> v0.5 目标设计，应用尚未实施；当前状态见 [执行目录](../execution/README.md)。

## 3. 唯一验证范围

### v0.5 验证规则

本节新规则用于 M14–M18；M13 只执行文档静态检查。复用既有一个最小 fixture、一条主链及机制、组学、临床/转化三篇论文，只增加实际新增风险的检查，不建多模型/多浏览器/多论文组合矩阵。

| 保护风险 | 必要验证 |
|---|---|
| 全文被提前压缩、来源对应失真 | 全文块与原句定位、Claim–Evidence–Source 多对多关系、汇报偏好不删底稿发现 |
| 切分越界、串图、漏图及人工结果丢失 | 图局部/原页坐标换算、共享图例重叠、补删/改框/标签、重识别候选、撤销和刷新 |
| 用户被迫逐阶段修错 | 图核对后生成讲稿并停止，用户进入下一步后生成页面；预算/来源自动维护；有限修复失败定位到单元，不能丢内容假成功 |
| 不能干预或旧任务覆盖编辑 | 步骤间等待、完整分析单元保存后刷新只续跑未完成/失效单元，失败/取消无假完成；步骤内暂停与立即取消、编辑失效、手工草稿、继续、迟到回调和事务版本复核 |
| 讲稿与 PPT 脱节 | 讲稿先行、Panel 多对多关联与反查、分页保留原段落、跨章合页保留讲述归属，备注随正文同步、普通更新提醒不拦截而非法分配拦截；片段分配、主线/补充覆盖、删页/重排/修改同步及候选应用 |
| 源级修正破坏旧稿 | 工作底稿复制、Current/Previous 各自绑定、恢复与有界回收、cropOverride 不扩散 |
| 旧项目迁移丢内容 | v1/v2 分阶段迁移、幂等、失败保留、旧稿无讲稿不伪造或锁住 |
| 页面仍是长网页 | 实际窗口布局、各区域独立滚动、画布可见、焦点/输入法/面板收起，不只检查横向溢出 |
| 图组重排丢来源、布局与导出不一致 | 同一 fixture 增加左二右一及比例/间距边界；实例叶子一一对应、非法树/越界拒绝、跨页复用独立、删除折叠/布局回退、Undo/刷新及旧稿不重排；Build 沿用 Plan 分区，导出独立图像与预览同源几何 |
| 导出与权限失效 | 同一快照、原生文字、每页备注、图像比例、Agent scope/proposal/一次 Undo、资源错误拦截 |

图组路线在 M16 用既有图像的真实宽高比比较有界分区候选与 Justified Layout：记录实际排列、顺序/组关系、最小展示尺寸与标注可读性，保留失败样例；M17 验证交互和实际 PPTX。只运行当前范围的验证对照，不预设胜出结论，不扩展专项性能测试或模型裁判。

新主链：

**上传 → 全文与图源分析 → 分析页补选并手动进入核对 → 补整张 Figure/跨页图块并手动调整切分 → 确认一次 → 生成大纲与讲稿并停止 → 编辑讲稿及多图关联 → 主动进入幻灯片并自动规划/制作 → 调整分页/图组、删页/重排 → 来源与单页裁图 → AI 提案应用 → 导出含讲者备注的 PPTX → 刷新重开。**

在同一项目补充讲稿完成后等待用户进入下一步、规划/制作中的立即暂停、取消和继续，验证每步可介入；不复制完整 E2E 多次运行。自动回归用固定响应，真实模型只用于阶段必要能力与内容验收。三篇只对当前修改影响的内容重新生成，但新初稿质量结论必须有当前生成证据，不能用人工修正稿代替。

人工核对分别记录：自动框缺陷与实际修框；模型原稿遗漏/错误与用户修正；讲述是否完整、组别/物种/终点与因果边界、图例及证据保留、主线收尾及补充覆盖。切分确认是产品操作，不替代验收人员对科学表达的独立检查。无确定性代码能证明的内容标人工判断。

实际办公软件打开新稿并检查备注、文字编辑、图片比例；PWA 离线、本地数据、更新与线上 Pages 继续沿旧边界验证。只记录实际可用的浏览器/办公软件，保持生产部署提交、Actions 和入口证据可追溯。论文与 Key 不进入源码或部署产物。

### 分层验证与 UI 任务验收

性能设计本轮仅纳入四项实现约束：轻量交互路径、重计算与 UI 分离、局部更新、图片资源及并发上限。用户明确暂不考虑第 5 项专项性能验收，因此不新增性能基准、响应时间阈值、帧率目标、扩展页数压力样例或硬件测试矩阵；M15–M17 实现上述职责时沿用原有必要正确性检查，不将其宣称为性能实测。原已约定的功能/UI 任务验收继续保留。

领域规则用普通数据和纯函数验证；应用用例注入有限外部替身验证步骤/暂停/取消/修复；IndexedDB 原子性、PDF 坐标和导出用真实适配器验证；UI 复用同一浏览器主链，不把用例每个分支都做成 E2E。真实模型只负责本阶段科学内容与能力证据。窄接口、职责依赖及具体边界以[分层与模块](../architecture/分层与模块.md)为准，不新建第二套测试工具。

现有 npm run check 包含 lint、format、unit 与 build，不含 check:browser/check:pwa。各阶段按真实改动执行对应脚本并分别记录，不能把单个命令通过写成全栈验收通过。迁移后新增依赖检查纳入现有工具，禁止深层跨领域和反向基础设施引用；兼容性薄重导出的清理随实际调用迁移，不将“改了路径”作为完成。

UI 验收以实际任务为准：定位有疑点的 Figure → 放大并修一个边框 → 补漏 Panel / 修改标签 → 查看实际裁图和原文后返回 → 撤销/重做并确认保存 → 核对后生成讲稿 → 编辑多图关联 → 主动进入幻灯片并分页/组图 → 从页面定位讲稿 → 删除/重排并核对讲稿 → 查看 AI 差异 → 导出。必选操作无需滚动整页找按钮，任务状态持续可见，错误留在原对象并给恢复入口，跨视图不丢位置或输入。按实际改动检查桌面分栏拖动、收起恢复及裁切一致性，不新增响应式适配验收，不重跑模型链。

分别记录自动切分错误、用户修框步骤、模型原稿内容缺口和人为修订，不能把人工修好后的结果当初稿质量。全文相关段落/图注的提取遗漏与“已有 Claim 未进入汇报”分开查；提取覆盖不以引用数量或凭空百分比宣称完整。
