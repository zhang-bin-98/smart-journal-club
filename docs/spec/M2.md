# M2 React 界面、项目、PDF 与来源

- 日期：2026-09-06
- 状态：已完成；Gate 通过
- 工作分支：`milestone/m2`
- 目标：迁移 M1 编辑器到 React，接入本地项目、PDF 解析、来源查看、当前元素裁图和重开恢复。

## 完成内容

- 使用 React 19、React DOM、Vite React 插件和 TypeScript JSX 入口迁移 M1 编辑器；组件位于 `src/ui/`，业务契约、布局、PDF、存储和导出保持普通 TypeScript 模块。
- 保留六类布局、四类元素、文字草稿、中文输入法组合状态、选择、拖动排序、增删页/元素、布局回退、Undo/Redo、零页禁用导出和 PPTX 导出。
- 新增首页和 Hash 项目路由；项目列表支持打开、重命名和确认删除，`nameIsCustom` 保护用户名称不被论文标题覆盖。该字段已同步到架构契约。
- 以一个 `smartjc` IndexedDB 数据库保存 projects、papers、assets、plans、decks、history 和 settings。创建项目的 Project、空 Paper、原 PDF Blob 使用同一事务；阶段、编辑、Undo/Redo 重新校验项目和 Deck 版本，失败不推进内存或稳定成果。
- 接入 PDF.js 文本/元数据解析、页渲染和来源页查看。PDF 解析拒绝加密、扫描件、超出首版上限的文件；原页和图源使用同一归一化 bbox。
- 当前 Figure 裁图只更新当前元素的 `cropOverride`，来源和其他引用保持不变；关闭/取消不提交，应用后支持 Undo，位图缓存有限且项目卸载时释放 PDF 资源。
- 导出以已保存 Deck 快照读取 Figure 图源，使用 PDF 重建裁图并输出可编辑文字和等比图片；项目子路径使用 Hash 导航并随构建分发 PDF.js worker。
- 添加 `tests/contracts.ts` 和 `tests/browser.mjs`，固定检查使用 M1 fixture，真实 PDF 检查使用机制论文本地夹具；测试脚本不把 PDF 或导出产物加入仓库。
