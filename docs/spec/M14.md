## 基线与实际实现

开始时工作区干净，main 比 origin/main 多 29 个既有提交，无远端独有提交；只读 fetch 成功后创建独立阶段分支。已安装 Pi AI / Agent Core 均为 0.85.1，沿用 React、TypeScript、Vite、Tailwind、Biome 和 Vitest，没有新增依赖或修改研究 Prompt / 论文及文稿 Schema。

- `src/app/settings/` 持有唯一 ModelSettings、URL 归一化、纯校验、设置用例、能力检查与已核对强度选项。配置为空仍可进入本地项目；旧固定配置只读保留，不自动复制旧 Key 或发送请求。
- `src/infrastructure/persistence/settingsStore.ts` 在同一 settings 事务保存新配置和旧记录备份；失败回滚，页面基准过期拒绝覆盖；清除同时清除当前/旧备份凭据而保留其他字段。与项目、Paper、Deck 和历史完全分离。
- `src/infrastructure/llm/responses.ts` 复用 Pi Responses 底层 stream，精确覆盖 reasoning payload：服务默认省略，显式值原样发送；保留图片、工具、文本增量与取消，关闭 SDK 内外层自动重试。供应商原始错误只在适配器分类，不进入 UI。
- `src/infrastructure/llm/requestScheduler.ts` 由 composition 共享：在途 2、60 秒 30 请求 / 120000 估算 Token、队列 64，成功响应实际用量校正预留，可读额度/重置头收紧窗口；交互连续两次优先后让分析前进。明确临时限流最多重试两次、总退避不超过 120 秒，其他错误不盲目重试，排队/退避/流等待均可取消。
- `src/app/llm/` 保留原有结构化结果和业务 Schema 校验，改为具名请求参数。固定 workflow、修复和 Pi Agent 全部通过同一应用入口；旧 shared 模型/设置实现及弹窗已移除。未创建第二个 Agent loop。
- `src/ui/settings/` 实现独立双栏固定窗口配置页：地址预览、遮蔽/显示 Key、手填模型、强度、连接及四项能力检查、保存/清除/恢复/来源返回、离线与运行中保护。来源页面保持挂载，避免共用 Suspense 的懒加载使原任务被暂停清理；原任务及输入不因查看设置而取消，返回恢复焦点及窗口滚动；配置写入和任务启动在应用层互斥。

## 实际能力与必要调整

用户指定 `https://api.deepseek.com` / `deepseek-flash`，并明确授权使用本地既有验收凭据；仅发送固定小素材，没有发送项目论文。真实检查通过正式配置页、Edge 和应用 Pi 适配器执行。

- 服务默认连接成功，实际请求未携带 reasoning.effort。
- 图片读取固定数字、工具名称/参数、原生 JSON Schema 结果及真实文本流四项通过。
- `none` / `low` / `high` / `max` 分别通过真实连接检查，浏览器请求中取值一致；其他候选值在固定响应检查中验证原样映射，不宣称第三方普遍支持。
- 真实请求通过页面取消，取消状态不会被迟到结果替换；保存后重新打开和单独清除 Key 通过。截图已视觉检查，布局、标签、结果和按钮可读。
- 首次真实工具检查发现：DeepSeek 默认思考模式拒绝强制指定工具（400）。最终采用自动工具选择，并保留唯一预期工具及返回 Schema 的确定性校验；没有偷偷将强度改为 none，也没有协议回退。修改后四项能力全部通过。

能力依据与边界：已阅读安装包实际 Responses 参数构造、onPayload、fetch、重试和流事件代码；核对 [DeepSeek Responses 指南](https://api-docs.deepseek.com/guides/responses_api/) 与[请求契约](https://api-docs.deepseek.com/zh-cn/api/create-response/)。文档能力说明不替代上述实际运行。
