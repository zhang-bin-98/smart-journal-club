## 真实生成验收

- 用户在本阶段明确回复“授权”后，使用已有配置调用 DeepSeek Responses（`deepseek-flash`、`high`），发送同一公开组学论文的原句、图注与实际图像证据。复用 M15 自动分析结果、M16 Fig 3 的实际人工修框及同一 PDF；没有手写科学讲稿替代模型输出，也没有记录 Key。
- 样例为 Bérard 等的 TORC1 裂殖酵母组学论文（PLoS Biology，2024，DOI：10.1371/journal.pbio.3002963），既有底稿含 338 项发现、473 项证据、41 页和 7 个 Figure。完整生成后正式工作台保存 21 个章节（13 主线、8 补充）、208 个段落、262 个唯一正文片段；338/338 发现覆盖，0 省略，无悬空引用。
- 实际暴露并修复：全稿输入超容量；跨批引用及 Evidence/Claim 混用；高推理输出截断；按单项结果过度拆章；Fig 5 有文字证据却没有图块引用。分别通过无损短索引、完整发现分组、精确引用枚举、紧凑章节分配输出和同页候选图证据解决；没有降低用户选择的推理级别、删发现或交给用户补 ID。
- 大样例使用 11 组含发现的真实生成，额外未引用全文作为最终整理背景。后续修复只复验受影响步骤：最终运行通过 `SMARTJC_REUSE_SPEECH=1 npm run check:m17:live` 重用本次先前真实生成的第 1–4、6–11 组原始响应，重跑第 5 组及全稿整理；原始响应仍经过现行 Schema/引用校验，非固定人工 fixture。最终这次保存耗时约 148 秒，仅代表受影响步骤复验，不能作为全稿生成耗时；没有声称一次全新、不中断的端到端生成通过。
- 科学核查覆盖同步化工具及泄漏边界、交配速度与最终效率区别、组学规模与功能富集、TORC1/TORC2 药理和遗传对照、自噬非必需与 TORC1 活性必要性、Psk1/Rps6 指标与功能因果强度。对照原句检查了 S1837E/S1839E、20/22 分钟等原文差异；修正了富集误写“过表达”及 Torin1 浓度单位，并保留原文记为 μm 的说明，未抹平原文不一致。
- Fig 1–7 均有实际图块引用；Fig 5 的 A–F 六个 Panel 分别对应抗体特异性、抑制剂、耐药等位基因、Psk1 与信息素时程证据。检查最终 `m17-real-speech.png` 的正式三栏界面、完整保存与覆盖提示；真实原稿和调用结果分别留在 `output/playwright/m17-real-speech.json`、`m17-real-calls.json`，先前组响应留在 `m17-real-batches.json`，均为本地产物，不提交。
- 输出容量核对采用服务商 [Responses 文档](https://api-docs.deepseek.com/guides/responses_api/) 与[模型规格](https://api-docs.deepseek.com/quick_start/pricing/)；当前分组输出上限 24576、章节整理 49152，经实际调用成功验证。早期本地服务未启动、开发热更新干扰和输出截断的失败均未产生完整新计划；隔离本地验证实例后完成上述检查。
