# smartJC 产品文档

> 版本：MVP v0.3 · 2026-09-05
> 状态：范围已确认，尚未实现或完成技术验证。
> 本文定义用户行为与首版范围；数据及运行规则见 [架构文档](架构文档.md)，实施与验收见 [执行计划](执行计划.md)。

## 1. 产品目标

smartJC 是面向生物医学原创研究论文汇报的本地优先 PWA，静态部署在 GitHub Pages。

核心闭环：

**上传一篇 PDF → 自动理解论文并识别 Figure/Panel → 生成完整 PPT → 查看来源 → AI 与手工修改 → 撤销 → 导出可编辑 PPTX。**

主要用户是准备 Journal Club、组会和文献汇报的生物医学研究人员。首版成功标准是主要结果讲得清楚、原图可读、来源可查、局部修改可控，导出后可在 PowerPoint 继续编辑。

项目只服务 smartJC，不承担通用 Agent 平台验证或未来组件复用目标。

## 2. 首版范围

| 首版必须具备 | 边界 |
|---|---|
| 单篇 PDF、本地项目列表、重命名、删除 | 一个项目绑定一份固定论文；删除项目需确认 |
| 自动识别 Figure/Panel、理解论文和证据链 | 只分析当前 PDF，不联网寻找论文附件 |
| 自动生成完整 Deck | 不在大纲阶段要求确认 |
| 幻灯片预览、来源查看、当前页裁图 | 来源查看复用裁图所用的 PDF 页面 |
| 文字编辑、新增/删除页、元素删除、页顺序调整 | 不提供自由坐标或富文本编辑器 |
| AI 问答、审核与局部/批量修改 | 修改默认直接执行，附简短摘要，一次请求可一次撤销 |
| 自动保存、阶段续跑、会话内 Undo/Redo | 失败不破坏最近已保存成果 |
| 整套重生成、恢复上一版 | 只保留一个上一版，不提供版本树 |
| PPTX 导出、PWA 安装和本地离线操作 | AI 功能需要联网及用户自己的模型 API Key |

输入只支持生物医学原创研究论文，覆盖机制、组学、临床和转化/混合研究。Review、系统综述、Meta-analysis、指南、纯病例报告和其他领域不纳入首版支持；识别到不支持的类型时说明边界，不建设额外工作流。扫描件、加密或损坏 PDF 提示更换可解析版本，不加入 OCR。

正式编辑体验面向桌面 Chrome/Edge。手机、Safari、Firefox 尽力兼容，不作为首版发布门槛。

## 3. 用户流程

### 创建与生成

首页仅提供上传 PDF、最近项目和模型设置入口。PDF 保存成功后创建项目，名称可先取文件名，再用识别到的论文标题补充；项目名称与论文原标题分开保存。

创建页面只有一个可选自然语言输入框，例如“中文，15 页左右，重点讲结果和创新点”，以及“生成 PPT”按钮。

默认采用论文主要语言，目标约 12–16 页；内容较少或较多时可在约 10–20 页内调整。明确的用户要求优先，但不能通过重复内容、隐藏关键证据或编造事实凑页数。创建页面不再增加语言、研究类型、主题等选择表单。

生成界面按解析、分析图源、理解研究、规划、制作幻灯片显示高层进度，可取消。完成后直接进入编辑器；不展示工具 JSON、推理过程或开发日志。

生成依赖当前打开的页面。关闭、刷新或浏览器终止可能中断任务；重开后显示最近已完成阶段，由用户点击继续，重做未完成阶段。首次生成未完成的幻灯片仅作为当前会话的只读进度预览，不标为正式成果，也不承诺逐页保存。

### 编辑器

桌面编辑器由左侧幻灯片导航、中间预览、右侧 AI 面板组成，顶部提供导出与设置。来源查看使用临时抽屉或弹窗。

- 点击文字进入编辑，编辑结束后形成一次可撤销操作，不把每次按键都写入历史。
- 新增页使用文字布局；删除页或元素直接执行并可撤销，调整顺序后保持对象身份不变。
- 来源入口展示 PDF 原页、定位区域、Figure/Panel 标签、caption 或必要原文。没有精确文字 bbox 时展示原页与定位文字，不伪造高亮位置。
- 裁图在原 PDF 页上重新框选，只更新当前幻灯片的当前 Figure 元素；其他页和共享论文来源不变。恢复默认裁图同样可撤销。
- 来源查看区分“论文识别区域”和“本页使用区域”；手工裁图覆盖值随该元素保存，普通换布局不得清除它。

### AI 行为

| 用户请求 | 预期行为 |
|---|---|
| “解释这张图”“检查有没有逻辑问题” | 回答或给建议，不改 Deck |
| “第 7 页标题短一点” | 明确页码优先，只修改目标标题 |
| “这页太挤”“这张图大一点” | 使用当前选择，先调整布局或精简辅助文字，必要时拆页 |
| “背景压成一页” | 修改背景部分，保留研究问题，不顺便改结果页 |
| “Figure 3 只留 B 和 D” | 使用原论文 Figure/Panel 标识；通过两个独立元素组合，保留各自来源 |
| “整体压到 12 页”“全部改成中文” | 按明确范围批量修改，提供摘要，一次撤销 |
| “按刚才的建议修改” | 使用最近审核上下文；如目标已变化，则重新核对 |

明确目标高于 UI 选择；指代不明确时依次使用当前选择和近期上下文，仍有多个合理目标才询问。“这页”使用当前显示页，不使用之前聊天里提到的页。

一次修改先在工作副本完成，全部通过必要校验才生效。取消、失败或旧响应均不留下半完成修改。手工修改是后续 AI 请求的新事实，AI 不得用旧上下文覆盖它。

## 4. 生成与视觉规则

结果部分占主要篇幅；每页表达一个主要信息，结果页标题优先使用结论句，配原始 Figure/Panel、少量短点和来源。背景、方法仅保留理解结果所需的信息。

| 研究结构 | 故事重点 | 避免 |
|---|---|---|
| 机制实验 | 问题 → 设计 → 现象 → 干预/机制证据 → 验证 → 结论 | 把关联直接写成因果、裁掉必要对照 |
| 组学/生信 | 问题 → 样本与模态 → 主要生物学发现 → 跨模态/独立验证 → 解释 | 按 QC、UMAP、差异分析等工具顺序堆砌内容 |
| 临床 | 人群 → 设计与比较组 → 主要终点 → 结果 → 局限与临床解释 | 混淆终点、用次要亚组替代主要结果 |
| 转化/混合 | 围绕同一结论串联人体、组学、实验和验证证据 | 将不同证据割裂成互不相关的章节 |

这些是同一生成流程中的内容指导，不产生独立模型或独立工作流。方法/工具型原创论文可突出方法和验证，方法流程用短文字或论文原图呈现。

首版只有一个学术白底主题、16:9 比例和六类布局：标题、文字、整图、图文、双图、Panel 网格。网格用于 3–4 个 Panel；更多内容拆页。结论、方法、讨论等复用这些布局，不为章节名称增加新布局。

Figure 优先选择支持主要结论的原图；复杂 Figure 可以按信息单位拆 Panel 或拆页。不得拉伸原图、重画科研数据，或通过裁图隐去理解结果所需的组名、坐标、图例、比例尺和统计信息。人工裁图保留原页查看入口，应用不声称能自动判断所有裁图的科学完整性。

文字过长或图太小时优先换布局、精简非核心文字，再拆页；不通过无限缩小字号解决。完整 caption 和长解释放在来源查看或 AI 回答中。

科学表达遵循：

- 主要结论保留对应证据和来源；不能编造实验、样本量、数值、Figure、引用或作者结论。
- 相关性、预测结果和 pseudotime 不自动升级为因果、实验验证和真实时间。
- 保持物种、组织、细胞、队列、组别及终点语义；不混淆基因表达与蛋白证据。
- 创新点和局限基于论文；额外推断必须明确其解释性质。无法支持的内容宁可省略。
- 用户要求增强措辞也不得超过论文证据；提供准确替代表达。
- 保留专业实体名称及原图文字，整套 Deck 的主要叙述语言保持一致。

结构和引用错误阻止提交；措辞、重复、拥挤等质量问题通过生成规则、轻量提示和人工来源查看处理，不承诺自动证明科研正确性。

## 5. 保存、恢复与导出

自动保存覆盖完整生成阶段、编辑提交、裁图、顺序调整、Undo/Redo 和版本切换。保存失败显示“未保存”并保留待保存草稿，提供重试；不得显示已保存。若空间不足，提示释放本地项目空间，避免关闭当前页面。

重开项目无需调用模型，恢复当前 Deck、来源和上次查看页。普通 Undo/Redo 不跨重启，当前成果和整套重生成前的上一版必须保留。

整套重生成使用已有论文分析和新的生成要求，当前 Deck 继续可查看；新 Deck 成功保存后才切换，失败保留当前版和已有上一版。生成期间不并行编辑或再次重生成同一项目。恢复上一版会交换两个版本并重置会话撤销栈，用户仍可再次切回。

切换模型或删除 Key 不改变项目内容，也不自动重新分析或生成。新设置用于下一次请求；运行中的任务先完成或取消再切换。

导出使用当前已保存 Deck、顺序、语言和裁图，浏览器直接下载 `.pptx`。文字可编辑，Figure 是可继续移动/缩放的图片，原图内部的数据对象不拆解。导出不改 Deck 或产生额外版本。

图像位图不存在时从原 PDF 重建；PDF 或必需图源缺失时保留可读内容、说明受限能力并定位问题页，阻止静默缺图导出。首版不提供重新关联 PDF。

## 6. 本地、联网与 PWA 边界

项目与 PDF 保存在当前浏览器的 IndexedDB；页面、缩略图和裁图片段按需生成，不长期保存缓存位图或导出文件。

用户配置自己的 API Key，首版从通过验证的 DeepSeek/GLM 固定候选中选择。Key 保存在浏览器独立设置中，可单独清除；项目删除不删除 Key。首次设置说明：论文分析所需的文本和图片会直接发送给所选模型供应商，Key 不进入对话、导出或日志。

应用静态资源完成离线缓存后，可离线打开本地项目、查看来源、手工编辑、裁图和导出。模型理解、生成与 AI 修改需要联网。首次访问未完成缓存时不承诺离线可用。

应用更新提示在空闲且已保存时由用户刷新，不打断编辑或生成，不清理项目。请求浏览器持久化存储被拒绝时仍可使用；设置中明确说明清除站点数据可能删除本地项目，PPTX 导出不等于项目备份。

## 7. 后续候选与明确边界

只有实际使用证明必要时才评估：自由拖动缩放、多主题、通用图片/图形、方法流程图、Notes、大纲视图、项目备份导入、原论文重新分析、PDF 重新关联、跨重启撤销历史。当前不为它们增加字段、工具或空目录。

首版不建设账号、云同步、后端代理、后台任务队列、多人协作、通用 Agent/插件平台、多论文工作区、PPTX 导入或完整 PowerPoint 编辑器。

产品验收以 [执行计划](执行计划.md) 的同一条主链和必要内容检查为准，不在本文另建测试清单。
