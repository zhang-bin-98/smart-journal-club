# smartJC 产品文档

> 版本：MVP v0.3 · 2026-09-05
> 状态：范围已确认；各阶段实现状态与验证结果见执行计划。
> 本文定义用户行为与首版范围；数据及运行规则见 [架构文档](架构文档.md)，实施与验收见 [执行计划](执行计划.md)。

## 1. 产品目标

smartJC 是面向生物医学原创研究论文汇报的本地优先 PWA，静态部署在 GitHub Pages。

核心闭环：

**上传一篇 PDF → 自动识别 Figure/Panel → 理解论文与证据链 → 生成完整 PPT → 查看来源 → AI 与手工修改 → 撤销 → 导出可编辑 PPTX。**

主要用户是准备 Journal Club、组会和文献汇报的生物医学研究人员。首版成功标准是主要结果讲得清楚、原图可读、来源可查、局部修改可控，导出后可在 PowerPoint 继续编辑。

项目只服务 smartJC，不承担通用 Agent 平台验证或未来组件复用目标。

## 2. 首版范围

| 首版必须具备 | 边界 |
|---|---|
| 单篇 PDF、本地项目列表、重命名、删除 | 一个项目绑定一份固定论文；删除项目需确认 |
| 自动识别 Figure/Panel、理解论文和证据链 | 只分析当前 PDF，不联网寻找论文附件 |
| 自动生成完整 Deck | 不在大纲阶段要求确认 |
| 幻灯片预览、来源查看、当前页裁图 | 来源查看复用裁图所用的 PDF 页面 |
| 文字编辑、新增/删除页、元素删除、页顺序调整 | 不提供自由坐标或富文本编辑器 |
| AI 问答、审核与局部/批量修改 | 修改默认直接执行，附简短摘要，一次请求可一次撤销 |
| 自动保存、阶段续跑、会话内 Undo/Redo | 失败不破坏最近已保存成果 |
| 整套重生成、恢复上一版 | 只保留一个上一版，不提供版本树 |
| PPTX 导出、PWA 安装和本地离线操作 | AI 功能需要联网及用户自己的模型 API Key |

输入只支持生物医学原创研究论文，覆盖机制、组学、临床和转化/混合研究。Review、系统综述、Meta-analysis、指南、纯病例报告和其他领域不纳入首版支持；识别到不支持的类型时说明边界，不建设额外工作流。扫描件、加密或损坏 PDF 提示更换可解析版本，不加入 OCR。

正式编辑体验面向桌面 Chrome/Edge。手机、Safari、Firefox 尽力兼容，不作为首版发布门槛。

## 3. 页面设计与用户流程

### 3.1 页面与状态关系

```text
首页
 ├─ 上传 PDF → 项目准备 → 正在生成 → 项目编辑器
 ├─ 打开未完成项目 → 项目准备 / 继续生成
 └─ 打开已有成果 → 项目编辑器

模型设置：从首页或编辑器打开对话框
来源查看 / 裁图：从编辑器打开同一个 PDF 对话框
```

首页与项目页是两个导航入口，准备、生成和编辑是同一项目页的状态，不另建独立大纲、设置或来源页面。应用本身使用简洁浅色界面，操作状态使用文字和选中边框表达；幻灯片的固定学术主题见第 4 节。

各页面沿用同一套颜色、字体、间距与控件风格，按钮、表单、边框及选中/聚焦/禁用态保持一致；新增页面不另设视觉主题。实现统一采用 Tailwind CSS，主题与样式边界见 [架构文档](架构文档.md) 第 1 节。

### 3.2 首页与项目准备

```text
┌────────────────────────────────────────────────────┐
│ smartJC                                  [模型设置] │
│                                                    │
│         上传论文，生成可继续修改的 PPT              │
│     ┌────────────────────────────────────────┐     │
│     │       将一篇论文 PDF 拖到这里           │     │
│     │              [选择 PDF]                │     │
│     └────────────────────────────────────────┘     │
│                                                    │
│ 最近项目                                           │
│  项目 A           15 页 · 已完成 · 2 小时前    [⋯]  │
│  项目 B           待继续 · 昨天               [⋯]  │
└────────────────────────────────────────────────────┘
```

- 上传区支持拖入和文件选择，只接受单份 PDF。保存时原位显示“正在保存论文…”，完成后进入项目准备状态。
- 最近项目按最近修改时间排列，显示名称、页数（已有 Deck 时）、状态和时间。点击打开，更多菜单只提供重命名和删除。
- 没有项目时隐藏列表，保留上传说明与主要按钮；读取失败显示原因和“重新选择 PDF”。
- 项目与原 PDF 一起保存成功后进入准备状态；项目名称先取文件名，仅在用户尚未重命名时再用论文标题补充。项目名称与论文原标题分开保存。

项目准备在同一项目页展示：

```text
┌────────────────────────────────────────────────────┐
│ [返回首页]  项目名称                     [模型设置] │
│                                                    │
│ 已保存：paper.pdf                                  │
│ 你希望怎么汇报这篇论文？（可选）                    │
│ ┌────────────────────────────────────────────────┐ │
│ │ 例如：中文，15 页左右，重点讲结果和创新点        │ │
│ └────────────────────────────────────────────────┘ │
│                                      [生成 PPT]    │
└────────────────────────────────────────────────────┘
```

这里只有一个自然语言输入框。默认采用论文主要语言，目标约 12–16 页，内容较少或较多时在约 10–20 页内调整。用户明确要求优先，但不能通过重复、隐藏关键证据或编造事实凑页数。模型 Key 未配置时在生成按钮旁提示并提供设置入口，配置后回到原项目，保留已输入要求。

### 3.3 生成、取消与继续

```text
┌────────────────────────────────────────────────────┐
│ 项目名称                              正在制作 PPT │
│                                                    │
│ ✓ 解析论文                                         │
│ ✓ 分析 Figure / Panel                              │
│ ● 理解研究内容                                     │
│ ○ 规划汇报结构                                     │
│ ○ 制作幻灯片                                       │
│                                                    │
│ 已完成的步骤已保存。                      [取消]   │
└────────────────────────────────────────────────────┘
```

阶段顺序与架构一致，不显示工具 JSON、推理、token 或逐个 API 请求。完成后直接进入编辑器，不额外确认大纲或是否查看结果。

取消后停在同一项目页，显示停止位置以及“继续生成”“返回首页”。任务运行时不提供后台留守入口；关闭、刷新或浏览器终止可能中断生成。重开未完成项目时显示“上次在‘理解研究内容’中断”，由用户点击继续，重做未完成阶段。

失败提示放在当前阶段附近：说明失败原因、已保存内容，并提供“重试当前步骤”或“模型设置”。制作幻灯片时若展示部分结果，只作为当前会话只读预览，不标为正式成果，也不承诺逐页保存。

### 3.4 项目编辑器

```text
┌──────────────────────────────────────────────────────────────────────┐
│ [首页] 项目名称       已保存           [导出 PPTX] [⋯] [模型设置]     │
├────────────┬───────────────────────────────────────┬─────────────────┤
│ 幻灯片     │                                       │ AI 助手         │
│ [＋新增页] │            当前幻灯片预览             │                 │
│            │                                       │ 用户消息        │
│ 01 缩略图  │            16:9，自适应缩放            │ 回答 / 修改摘要 │
│ 02 缩略图  │                                       │                 │
│ 03 已选中  │  选中图：[查看来源] [裁图] [删除]      │ ─────────────── │
│ …          │                                       │ 告诉我怎么调整…│
├────────────┴───────────────────────────────────────┤          [发送] │
│ [撤销] [重做]                          第 3 / 15 页 │                 │
└───────────────────────────────────────────────────┴─────────────────┘
```

| 区域 | 控件与行为 |
|---|---|
| 顶栏 | 项目名、保存状态、导出、更多菜单和模型设置；更多菜单放“重新生成整套 PPT”“恢复上一版”，后者仅在有上一版时出现 |
| 左侧导航 | 缩略图、编号、当前选中态；点击切页，拖动缩略图排序，新增页使用文字布局，页菜单提供删除 |
| 中间预览 | 居中展示当前 Slide，缩放只改变查看比例；点击文字进入编辑，选中元素出现边框和对应操作，不显示自由拖拽/缩放手柄 |
| 底部操作栏 | 撤销、重做和页序号；无可用记录时禁用对应按钮 |
| 右侧 AI 面板 | 可见对话与修改摘要，底部固定输入框；发送时显示“正在调整…”与“取消”，完成后显示受影响页及修改摘要 |

编辑细节：

- 新增页使用文字布局，提供可编辑的标题和一个空文字元素；占位提示仅用于界面，不写入导出。文字编辑支持基础换行，编辑结束形成一次保存和撤销记录，不逐按键写历史。
- 删除页或元素直接执行并可撤销，不逐次弹确认；删除整个项目仍需确认。删图后原布局不再适用时按剩余内容切换到已有布局，布局调整与删除作为同一次撤销。
- 允许删除最后一页。删空后显示“还没有幻灯片”和“新增页”，页数为 0，清除当前页/元素选择，保留可用的 Undo/Redo，禁用导出；仍属于已有项目的编辑状态。AI 可按明确要求新增页，但不能把“这页”解析成不存在的目标。
- 选中 Figure 后显示“查看来源”“裁图”“删除”；引用可点击打开来源。切页和元素选择会进入下一次 AI 请求上下文。
- AI 摘要中的“撤销”只在该修改仍是当前可撤销栈顶时可用；之后已有其他编辑时使用底部统一 Undo，避免误撤销别的操作。
- AI 请求运行时可浏览页面，重复发送禁用。用户实际改变文字或裁图等内容、产生手工草稿时，立即使本轮待提交的 AI 修改失效并取消请求，提示“已转为手工编辑”；单纯浏览和选择不取消请求。
- “重新生成整套 PPT”打开简短对话框，复用项目准备的自然语言要求输入，预填现有要求，提供“取消”和“开始重生成”；开始后顶部显示状态及取消入口，当前 Deck 保持可查看，编辑操作禁用。成功后才保存新要求并切换版本，详见第 5 节。

空间不足时先将 AI 面板收为按钮打开的抽屉，再将导航收为幻灯片列表抽屉；中间预览占主要空间。手机沿用这一收起布局，不另做完整移动编辑器或增加移动端发布验收。

### 3.5 来源查看与当前页裁图

查看与裁图复用同一个对话框、原 PDF 页面和来源信息区：

```text
┌────────────────────────────────────────────────────┐
│ Fig. 3B · 论文第 8 页                        [关闭] │
│ ┌────────────────────────────────────────────────┐ │
│ │                  PDF 原页                      │ │
│ │     虚线框：论文识别区域                        │ │
│ │     实线框：本页使用区域                        │ │
│ └────────────────────────────────────────────────┘ │
│ Figure 标签、caption / 必要来源文字                │
│                                      [调整裁图]    │
└────────────────────────────────────────────────────┘
```

普通查看模式展示原页、来源框和文字；有当前元素覆盖值时显示其实际使用区域，没有覆盖值时两个区域相同，不重复画框。文字来源缺少精确 bbox 时只展示原页和定位文字，不伪造高亮。

“调整裁图”进入同一窗口的框选模式，也可从 Figure 工具条直接进入。用户在原 PDF 页重新框选，底部改为“恢复默认范围”“取消”“应用到本页”。恢复默认先更新待应用框，点击应用后才保存；取消不改变当前元素。

应用只更新当前页当前 Figure 元素，其他页和共享论文来源不变；成功后关闭对话框并刷新当前图，支持一次撤销。保存失败保留当前框选并提示重试。首版没有“修正所有引用”入口。

### 3.6 模型设置与公共状态

```text
┌────────────────────────────────────────────────────┐
│ 模型设置                                    [关闭] │
│ 模型       [已通过验证的固定候选             ▾]   │
│ API Key    [•••••••••••••••••••••••••••••••••]   │
│ 论文分析所需文本和图片将直接发送给所选供应商。      │
│ Key 保存在当前浏览器，可单独清除。                  │
│ [测试连接] [清除 Key]                       [保存]  │
└────────────────────────────────────────────────────┘
```

设置是对话框，仅展示已通过 M0 的模型候选、Key 和连接结果。保存或关闭后返回原页面；关闭丢弃未保存的设置输入。运行中的任务先完成或取消，才允许保存模型切换或清除 Key。

| 状态 | 展示位置与操作 |
|---|---|
| 保存中 / 未保存 | 编辑器顶栏；失败时显示原因与重试，不用 Toast 代替持续的未保存提示 |
| 无网络 / 缺 Key | AI 面板和生成入口提示；本地查看、手工编辑及资源完整时的导出仍可用 |
| 来源缺失 | 来源对话框说明受限原因；导出缺图时指出具体页并提供定位入口 |
| 导出中 / 失败 | 顶栏导出按钮显示进度并防重复点击，失败后可重试，当前 Deck 保留 |
| 可安装 / 可更新 | 首页和编辑器共用的应用提示区；安装仅在浏览器支持时出现，更新按第 6 节规则等待保存和空闲 |

### 3.7 AI 行为

| 用户请求 | 预期行为 |
|---|---|
| “解释这张图”“检查有没有逻辑问题” | 回答或给建议，不改 Deck |
| “第 7 页标题短一点” | 明确页码优先，只修改目标标题 |
| “这页太挤”“这张图大一点” | 使用当前选择，先调整布局或精简辅助文字，必要时拆页 |
| “背景压成一页” | 修改背景部分，保留研究问题，不顺便改结果页 |
| “Figure 3 只留 B 和 D” | 使用原论文 Figure/Panel 标识；通过两个独立元素组合，保留各自来源 |
| “整体压到 12 页”“全部改成中文” | 按明确范围批量修改，提供摘要，一次撤销 |
| “按刚才的建议修改” | 使用最近审核上下文；如目标已变化，则重新核对 |

明确目标高于 UI 选择；指代不明确时依次使用当前选择和近期上下文，仍有多个合理目标才询问。“这页”使用当前显示页，不使用之前聊天里提到的页。

一次修改先在工作副本完成，全部通过必要校验才生效。取消、失败或旧响应均不留下半完成修改。手工修改是后续 AI 请求的新事实，AI 不得用旧上下文覆盖它。

## 4. 生成与视觉规则

结果部分占主要篇幅；每页表达一个主要信息，结果页标题优先使用结论句，配原始 Figure/Panel、少量短点和来源。背景、方法仅保留理解结果所需的信息。

研究结构采用可配置的研究叙事策略：每个策略以 Markdown 正文和少量 YAML 头信息保存在仓库中，用于指导论文解读、证据取舍和汇报结构。下表保留首批策略的适用范围和内容要求；实际提示词在 M3 落成后单独维护，具体措辞与叙事顺序不在本文复制。

| 内置策略 | 适用情况 | 初始内容要求 |
|---|---|---|
| 通用 | 支持范围内难以归入单一类型的研究，以及方法/工具型原创论文 | 围绕问题、贡献及支持证据组织；方法型突出方法和验证 |
| 机制实验 | 以实验干预及机制证据为主的研究 | 串联现象、干预、机制与验证，保留必要对照，不把关联升级为因果 |
| 组学/生信 | 以高通量数据分析及生物学发现为主的研究 | 说明样本与模态，突出发现及跨模态/独立验证，避免按 QC、UMAP 等工具顺序堆砌 |
| 临床 | 以人群、比较组和临床终点为主的研究 | 交代设计和比较组，以主要终点为主，说明局限，不用次要亚组替代主要结果 |
| 转化/混合 | 结合人体、组学、实验等多种证据的研究 | 围绕同一结论衔接不同证据，避免割裂成互不相关的章节 |

首次在已有论文理解步骤中自动选择一个策略，不增加模型调用或要求用户先选研究类型。无法确定时使用通用策略；通用策略不扩大第 2 节的论文支持范围。用户通过项目准备或 AI 输入框说明汇报重点、时长和叙事要求，这些要求优先于策略默认建议，并始终受论文证据约束。

策略提供可调整的叙事建议，不固定章节顺序、每章页数或逐页模板；实际结构由论文内容和用户要求形成。同一生成流程、Paper/Deck 契约和六类布局适用于所有策略，不按研究类型建设独立工作流。方法流程仍使用短文字或论文原图呈现。

维护者修改仓库提示词后重新构建发布，应用更新后用于后续请求；已有论文分析、计划和幻灯片不自动重写，续跑仍保留已完成阶段。首版不增加提示词编辑页面、策略选择表单或远程配置服务。文件格式、选择与更新规则见架构文档第 7 节。

首版只有一个学术白底主题、16:9 比例和六类布局：标题、文字、整图、图文、双图、Panel 网格。网格用于 3–4 个 Panel；更多内容拆页。结论、方法、讨论等复用这些布局，不为章节名称增加新布局。

Figure 优先选择支持主要结论的原图；复杂 Figure 可以按信息单位拆 Panel 或拆页。不得拉伸原图、重画科研数据，或通过裁图隐去理解结果所需的组名、坐标、图例、比例尺和统计信息。人工裁图保留原页查看入口，应用不声称能自动判断所有裁图的科学完整性。

文字过长或图太小时优先换布局、精简非核心文字，再拆页；不通过无限缩小字号解决。完整 caption 和长解释放在来源查看或 AI 回答中。

科学表达遵循：

- 主要结论保留对应证据和来源；不能编造实验、样本量、数值、Figure、引用或作者结论。
- 相关性、预测结果和 pseudotime 不自动升级为因果、实验验证和真实时间。
- 保持物种、组织、细胞、队列、组别及终点语义；不混淆基因表达与蛋白证据。
- 创新点和局限基于论文；额外推断必须明确其解释性质。无法支持的内容宁可省略。
- 用户要求增强措辞也不得超过论文证据；提供准确替代表达。
- 保留专业实体名称及原图文字，整套 Deck 的主要叙述语言保持一致。

结构和引用错误阻止提交；措辞、重复、拥挤等质量问题通过生成规则、轻量提示和人工来源查看处理，不承诺自动证明科研正确性。

## 5. 保存、恢复与导出

自动保存覆盖完整生成阶段、编辑提交、裁图、顺序调整、Undo/Redo 和版本切换。保存失败显示“未保存”并保留待保存草稿，提供重试；不得显示已保存。若空间不足，提示释放本地项目空间，避免关闭当前页面。

存在手工草稿时，新的 AI 修改、撤销/重做、导出、整套重生成、版本切换及应用内离开项目先结束当前编辑并等待保存；保存失败则保留草稿，暂停后续操作，不用旧成果覆盖未保存内容。

重开项目无需调用模型，恢复当前 Deck、来源和上次查看页。普通 Undo/Redo 不跨重启，当前成果和整套重生成前的上一版必须保留。

整套重生成使用已有论文分析和新的生成要求，当前 Deck 继续可查看；新 Deck 成功保存后才切换，失败保留当前版和已有上一版。生成期间不并行编辑或再次重生成同一项目。恢复上一版会交换两个版本并重置会话撤销栈，用户仍可再次切回。

切换模型或删除 Key 不改变项目内容，也不自动重新分析或生成。新设置用于下一次请求；运行中的任务先完成或取消再切换。

导出在开始时固定当前已保存 Deck 的快照，使用该快照的顺序、语言和裁图，浏览器直接下载 `.pptx`；导出期间的新编辑用于下一次导出，不混入正在生成的文件。文字可编辑，Figure 是可继续移动/缩放的图片，原图内部的数据对象不拆解。导出不改 Deck 或产生额外版本，零页文稿禁用导出。

图像位图不存在时从原 PDF 重建；PDF 或必需图源缺失时保留可读内容、说明受限能力并定位问题页，阻止静默缺图导出。首版不提供重新关联 PDF。

## 6. 本地、联网与 PWA 边界

项目与 PDF 保存在当前浏览器的 IndexedDB；页面、缩略图和裁图片段按需生成，不长期保存缓存位图或导出文件。

用户配置自己的 API Key，首版从通过验证的 DeepSeek/GLM 固定候选中选择。Key 保存在浏览器独立设置中，可单独清除；项目删除不删除 Key。首次设置说明：论文分析所需的文本和图片会直接发送给所选模型供应商，Key 不进入对话、导出或日志。

应用静态资源完成离线缓存后，可离线打开本地项目、查看来源、手工编辑、裁图和导出。模型理解、生成与 AI 修改需要联网。首次访问未完成缓存时不承诺离线可用。

应用更新提示在空闲且已保存时由用户刷新，不打断编辑或生成，不清理项目。请求浏览器持久化存储被拒绝时仍可使用；设置中明确说明清除站点数据可能删除本地项目，PPTX 导出不等于项目备份。

## 7. 后续候选与明确边界

只有实际使用证明必要时才评估：自由拖动缩放、多主题、通用图片/图形、方法流程图、Notes、大纲视图、项目备份导入、原论文重新分析、PDF 重新关联、跨重启撤销历史。当前不为它们增加字段、工具或空目录。

首版不建设账号、云同步、后端代理、后台任务队列、多人协作、通用 Agent/插件平台、多论文工作区、PPTX 导入或完整 PowerPoint 编辑器。

产品验收以 [执行计划](执行计划.md) 的同一条主链和必要内容检查为准，不在本文另建测试清单。
