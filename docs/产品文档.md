# smartJC 产品文档

> 版本：MVP v0.5 设计 · 2026-09-08
> 状态：本文定义已确认的 v0.5 目标；当前应用仍为 v0.4。M13 只交付文档，新功能须按执行计划另行实施与验收。
> 本文定义用户行为与范围；数据及运行规则见 [架构文档](架构文档.md)，实施与验收见 [执行计划](执行计划.md)。

## 1. 产品目标

smartJC 是面向生物医学原创研究论文汇报的本地优先 PWA，静态部署在 GitHub Pages。

核心闭环：

**上传一篇 PDF → 全文解析、完整 Figure/Panel 切分与论文底稿 → 用户核对并按需手动调整切分 → 一键生成大纲与演讲稿、页面规划、完整 PPT → 按需编辑 → 检查并导出可编辑 PPTX。**

主要用户是准备 Journal Club、组会和文献汇报的生物医学研究人员。成功标准是论文发现覆盖充分、图证据完整可读、演讲稿与页面相互配合、来源可查，用户主要做取舍和修改，不必自行找遗漏内容、补登记字段或解决模型格式错误。

论文底稿以文章为基础，不按 PPT 页数裁掉发现；汇报默认充分覆盖已识别的论文发现，明确标出主线与补充内容。用户可在任一步骤主动介入，大纲可改、演讲稿可改、PPT 可改。唯一默认必须暂停的人工环节是 Figure 切分核对；核对后默认自动完成全部生成，不再要求逐阶段点击确认。

项目只服务 smartJC，不承担通用 Agent 平台或未来组件复用目标。

## 2. 本版范围

| 必须具备 | 边界 |
|---|---|
| 单篇 PDF、本地项目列表、重命名、删除 | 一个项目绑定一份固定论文；删除项目需确认 |
| 全文底稿、Figure/Panel 与证据关联 | 处理当前 PDF 的正文、方法、图注、表格及内嵌附录；不联网寻找附件 |
| 自动切分与图源核对工作台 | 所有识别到的 Figure 可见；支持修框、补删 Panel、改标签、Undo/Redo，保存至论文图源 |
| 原文片段、观察结果、发现与 Panel 双向查看 | 关联多对多；未确认的解释标疑点，不让用户逐条填写科学字段 |
| 大纲、演讲稿与页面规划联动 | 默认连续生成；允许预设阶段暂停或运行中暂停后编辑 |
| 主线与补充内容 | 默认充分覆盖，不设固定默认页数上限；用户可删页、移动内容或明确限制篇幅 |
| 固定窗口的应用工作台 | 目录、原文、画布、讲稿与 Inspector 各自滚动；不再堆成长网页 |
| 文字编辑、增删页、删除元素与重排 | 无幻灯片自由坐标或富文本编辑器；图源切分框支持自由调整 |
| AI 问答、审核与受控修改 | 显式提问/修改；改写已有成果先展示提案，应用后一次请求一次撤销 |
| 自动保存、续跑与版本保护 | 完整阶段可恢复；失败不破坏已保存成果；Current/Previous 各保留自己的证据与讲稿 |
| PPTX、演讲稿与离线操作 | PPTX 保留原生文字、图片及对应讲者备注；AI 需要联网与用户自己的 Key |

输入仍限定生物医学原创研究，覆盖机制、组学、临床和转化/混合研究。Review、系统综述、Meta-analysis、指南、纯病例报告和其他领域不纳入本版；不支持类型说明边界，不建设额外流程。扫描件、加密或损坏 PDF 提示更换可解析版本，不新增整篇 OCR。Panel 标签的局部识别不等于支持扫描论文，本版不引入独立 OCR 引擎。

正式编辑面向桌面 Chrome/Edge。手机、Safari、Firefox 尽力兼容，不增加首版发布矩阵。

## 3. 页面设计与用户流程

### 3.1 页面与状态关系

```text
首页
 └─ 项目工作台（固定窗口）
     ├─ 论文与图源：全文 / 按发现 / 按 Figure
     ├─ 大纲与演讲稿：章节 / 讲述段落 / 主线与补充
     ├─ 幻灯片：页面 / 本页讲稿 / 图证据
     └─ 检查与导出：问题列表 / 定位与修复

顶栏：项目名 | 论文与图源 | 大纲与演讲稿 | 幻灯片 | 检查
      保存状态 | 阶段进度 | 暂停/继续 | 导出 | 设置
```

首页与工作台是两个导航入口，沿用简单 Hash 导航；各工作视图可识别、可返回，共用同一个外壳、任务状态和选中上下文。切换视图不是重跑阶段，也不自动批准修改。

- 分析完成后进入图源核对，必须由用户整体确认；不强制每个 Panel 逐一打勾，不把科学事实逐条复审作为启动门槛。
- “核对完成，生成 PPT”保存当前切分确认并启动一次连续生成。用户可选择“大纲与演讲稿完成后暂停”或“页面规划完成后暂停”；没有选择则自动继续。
- 运行中可浏览已完成产物、暂停或取消。主动编辑先暂停受影响的后续任务，保留已有内容；保存后由用户选择继续，不能后台覆盖手工修改。
- 有 Deck 后仍可编辑大纲和演讲稿；对应的是当前文稿内容。需要重新编排或生成受影响页面时显示候选变化，用户应用后才替换，不能拿旧临时计划覆盖当前稿。
- 默认人工核对点只有图切分；设置缺失、资源不可用等实际阻塞需可操作提示，不能用“必须确认大纲”替代自动恢复。

桌面工作台高度受可用窗口约束，顶栏和主要操作始终可见，外层不因表单、问题列表或讲稿变长而纵向滚动。左目录、中央 PDF 查看器、右侧 Inspector、讲稿面板各自滚动；幻灯片适配中央剩余空间。面板可收起，讲稿区可调高度，缩小时先收起辅助区域，禁止多个最小高度累加把画布和按钮推到屏幕外。首页项目列表可以正常滚动。

保留统一浅色界面、React 与 Tailwind CSS 主题及控件风格；设置继续使用对话框，PDF 渲染和框选由图源核对与单页裁图复用。技术边界见架构第 1、3 节。

### 3.2 首页与项目准备

```text
┌────────────────────────────────────────────────────┐
│ smartJC                                  [模型设置] │
│                                                    │
│         上传论文，生成可继续修改的 PPT              │
│     ┌────────────────────────────────────────┐     │
│     │       将一篇论文 PDF 拖到这里           │     │
│     │              [选择 PDF]                │     │
│     └────────────────────────────────────────┘     │
│                                                    │
│ 最近项目                                           │
│  项目 A           15 页 · 已完成 · 2 小时前    [⋯]  │
│  项目 B           待继续 · 昨天               [⋯]  │
└────────────────────────────────────────────────────┘
```

- 上传区支持拖入和文件选择，只接受单份 PDF。保存时原位显示“正在保存论文…”，完成后进入项目准备状态。
- 最近项目按最近修改时间排列，显示名称、页数（已有 Deck 时）、状态和时间。点击打开，更多菜单只提供重命名和删除。
- 没有项目时隐藏列表，保留上传说明与主要按钮；读取失败显示原因和“重新选择 PDF”。
- 项目与原 PDF 一起保存成功后进入准备状态；项目名称先取文件名，仅在用户尚未重命名时再用论文标题补充。项目名称与论文原标题分开保存。

项目准备在同一项目页展示：

```text
┌────────────────────────────────────────────────────┐
│ [返回首页]  项目名称                     [模型设置] │
│                                                    │
│ 已保存：paper.pdf                                  │
│ 你希望怎么汇报这篇论文？（可选）                    │
│ ┌────────────────────────────────────────────────┐ │
│ │ 例如：中文组会，重点讲结果与创新点        │ │
│ └────────────────────────────────────────────────┘ │
│                                  [分析论文]    │
└────────────────────────────────────────────────────┘
```

准备阶段保留自然语言要求输入框，可填写语言、听众、时长、重点和篇幅。默认采用论文主要语言并充分覆盖发现；这些汇报要求只影响大纲、讲稿和 PPT 取舍，不改变全文底稿的提取范围。模型 Key 未配置时在生成按钮旁提示并提供设置入口，配置后回到原项目，保留已输入要求。

### 3.3 生成、取消与继续

```text
论文分析：全文解析 → Figure 定位与 Panel 切分 → 论文发现与证据整理
                                                ↓
                                      图源核对（必须暂停）
                                                ↓
一键生成：大纲与演讲稿 → 页面规划 → 页面制作与检查 → 完整 PPT
          [可选停在这里] [可选停在这里]   [暂停 / 取消]
```

进度显示当前阶段、原 PDF 页码或 Figure、已完成/总数和分析/修复状态，不显示工具 JSON、隐藏推理、token 或逐 API 日志。已完成内容可查看，尚未完成的预览明确标识，不能伪装成正式成果。

用户可预选阶段暂停，也可立即暂停/取消当前请求。暂停或取消保留最近完整阶段；运行中未提交部分不自动发布。恢复后只重做未完成或因编辑失效的部分，独立未受影响的论文解析、图源、讲稿及页面成果复用。关闭、刷新、浏览器终止可能中断任务；重开恢复产物与暂停选择，但不自动发送模型请求，由用户点击“继续”。不建设后台留守或任务队列。

模型格式、确定性引用登记、页面分配和布局问题由系统归一化、检查与有限修复，不能要求用户补 ID、来源数组、章节预算或空白页面来通过生成。失败提示在当前对象附近给出原因、保留成果及“重试当前部分”“模型设置”等操作；不能用静默删发现、漏图、缩小到不可读或放松来源校验来通过。无法确定的切分提示核对，无法确定的科学解释标待核查，缺材料明确说明。

取消与请求超时须独立退出等待，迟到响应不更新 UI 或保存成果。实际网络、认证、额度和资源失败保持可见；自动修复有次数上限，不无限重试。用户暂停后，后台不能自作主张续跑。

### 3.4 论文底稿与图源核对

论文底稿涵盖全文结构、背景、问题、方法、实验观察、研究发现、作者解释与局限。每个可追溯事实关联原句或段落及页码；Figure/Panel、原文、实验与发现形成多对多关系。论文底稿不包含页面预算或 PPT 布局，不因用户少讲、不讲或删页而删除事实。分析无法确定的关系标明缺口，不补造原句、实验或 Panel。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 项目名 [论文与图源] 大纲与演讲稿 幻灯片 检查    保存状态 / 设置    │
├──────────────┬────────────────────────────────┬────────────────────┤
│ 按发现 / 按图│ 原 PDF / 当前完整 Figure       │ 当前 Panel 预览    │
│ Figure 1     │                                │ 标签 B             │
│   A  B  C    │ 自动框 / 当前选中框            │ 对应原句与页码     │
│ Figure 2     │ 放大、平移、拖动框、调整四边    │ 实验 / 发现        │
│   A  B       │                                │ 切分疑点           │
│ 待核对 2 项  │                                │ 添加 / 删除 Panel  │
├──────────────┴────────────────────────────────┴────────────────────┤
│ 撤销 / 重做 / 恢复自动结果     保存草稿    [核对完成，生成 PPT]    │
└────────────────────────────────────────────────────────────────────┘
```

核对的主要对象是切分。左侧完整列出 Figure 与所有 Panel，支持按发现切换组织；点击图、框或预览同步选中，定位原页和对应原句。长列表在目录内部滚动，不把全部大图堆在下方。发现和解释可查看、定位、提出修订，但不要求用户逐项审核或填写领域字段。

手动操作包括移动/缩放整图与 Panel 框、添加漏掉的 Panel、删除误框、修改标签、Undo/Redo、恢复自动结果。原页与实际裁图实时联动，保留放大查看能力；不要求输入坐标。修某一框不能偷偷移动其他框。保存通过统一图源提交入口，更新论文来源；“恢复自动结果”先进入草稿，可取消或撤销。新增 Panel 的语义与证据关联由系统补充，无法确认时标疑点，不要求用户填写 Source/Claim ID。删除仅移除该图源身份及其关联，不删除原文事实；相关关联由系统修复或明确标缺失。

自动切分采用“整图定位 → 局部高清识别标签、内容与粗框 → 像素内容/空白间隙辅助边界调整 → 质量检查”。保留完整 Figure；不按标签中点硬切、不按阅读顺序猜标签、不把固定阈值当所有论文的标准。不确定结果进入核对，不宣称语义与像素算法已经证明切分正确。

Panel 是可独立理解的科学裁图，保留数据、标签及必要坐标、组别、图例、比例尺和统计信息。共享图例或标注可以让多个 Panel 适度重叠；重叠本身不是错误，疑似串入邻图主要数据才提示核对。不抹白、擦除、重绘科研像素来制造分隔。矩形难以独立保留必要标注时保留整图并提示，可手动调整或在生成中组合展示，不强行产出残缺子图。

允许对当前 Figure 再次自动识别，结果先作为候选，与人工框对照；只有用户选择应用才替换。必须保留并标识人工调整，不得因重试或换模型静默覆盖。

一次整体确认绑定当前保存的切分版本，不等同于确认论文所有科学解释正确。切分改变后确认失效，影响范围可见；关联重算不要求重复核对未改变的框。确认后系统完成必要关联整理再继续生成。

已有 PPT 时修改论文图源，先保存独立工作底稿并显示受影响的讲稿/页面，旧稿及上一版仍可查看、导出。应用下游更新才切换相关成果，不让共享源变化静默改变旧稿。完整重新分析同一论文沿用“在新项目中重新分析”入口；复制本地原 PDF，保留原项目，失败不覆盖旧事实或成果。

### 3.5 大纲、演讲稿与页面规划

```text
┌──────────────────────────────────────────────────────────────────┐
│ 项目名 论文与图源 [大纲与演讲稿] 幻灯片 检查       暂停 / 继续   │
├───────────────────┬─────────────────────────┬────────────────────┤
│ 主线              │ 当前讲述段落            │ 对应证据 / 页面    │
│ 背景与问题        │ 要让听众理解什么？      │ 原句、发现、Panel  │
│ 发现一            │ 演讲稿正文……            │ 建议展示 A、C      │
│   段落 / 页面     │ 过渡到下一段……          │ 拆为 2 页          │
│ 综合与 Take-home  │                         │ 主线 / 补充        │
│ 补充              │ [保存] [取消]           │ 来源查看 / AI      │
│ 方法细节 / 验证   │                         │                    │
├───────────────────┴─────────────────────────┴────────────────────┤
│ 总页数由实际规划计算 · 不要求维护预算差额        [继续生成 PPT]   │
└──────────────────────────────────────────────────────────────────┘
```

大纲与演讲稿在同一规划过程中形成：先确定讲述结构、段落目的和有证据的讲稿，再决定每段需要哪些图和几页，不能先填 PPT 模板再补讲稿。规划时即考虑实际图证据与可读性。每个讲述段落可对应多页；每页有对应讲述内容，屏幕文字与口头解释互补，不把整篇讲稿粘进页面。

默认覆盖全部已识别发现，以主线/补充分组展示；不同发现不能为固定页数静默消失。用户可移动分组、增删章节/段落/页面、调整顺序与重点、修改讲稿、选择图源。明确篇幅要求影响汇报取舍，不改变论文底稿；省略哪些发现要可查看，不能以重复内容凑数。

默认无需停在此处确认。用户选择阶段暂停或编辑时，大纲、讲稿和页面规划均可保存、恢复和继续；自动流程不能只开放只读大纲。目标页数若由用户指定，仅是生成偏好；实际页数由页面集合计算，不要求预算与页面数双重维护，也不因重点结论不足两页而要求加页。

结构引用、图源来源登记与页面归属由系统维护。调整讲稿或证据后，系统指出受影响页面并准备更新；若页面已有人工修改，先展示差异再应用。单纯删页同步移除相应讲述分配，剩余段落及过渡可提出修订；不删除论文事实，不静默改写相邻人工讲稿。一个操作产生一次 Undo。

问题列表放在工作台内部的可定位面板，点击跳到对象；未保存输入先保存或取消。可选的 AI 修订使用同一提案机制。模型格式错误和可确定的引用补全由系统处理，不要求用户打开字段修错。

```text
├──────────────┴──────────────────────────────┴──────────────────────┤
│ AI 范围：元素 / 当前页 / 章节 / 整套 · 提问 / 修改 · 输入 / 发送   │
└────────────────────────────────────────────────────────────────────┘
```

| 区域 | 控件与行为 |
|---|---|
| 顶栏 | 固定项目名、视图导航、保存状态、Undo/Redo、检查/导出、重生成、恢复上一版和模型设置 |
| 章节导航 | 主线/补充标记、章节折叠、页数、缩略图、编号、选中态；单选/多选、拖动重排、新增与删除 |
| 中央画布 | 居中当前页，缩放仅改变查看比例；点击文字编辑，选中元素有操作，无幻灯片自由坐标手柄 |
| 讲稿面板 | 当前页讲述内容；与页面选择同步，可独立滚动、调高或收起，保存时维护对应关系 |
| 右侧 Inspector | 内容/图源/版式/AI 可切换、可收起；展示页目的、结论、来源、布局、图像操作或对话与提案 |
| 底部命令区 | 固定在工作台内；实际范围、提问/修改模式、输入和发送/取消，不随内容滚到窗口外 |

AI 对话与输入共用一个 controller 和请求状态；右侧不再设第二输入框。切换标签、收起面板或浏览页面不扩大范围，也不发起新请求。无可用 Undo/Redo 时禁用按钮；持续显示当前页/总页数。

- 新增页使用文字布局，标题和空文字可编辑；占位提示不写入导出。保留换行、焦点、光标和输入法；编辑结束一次保存与撤销，不逐按键写历史。
- 删除页或元素可撤销，不逐次弹确认；允许多选删页和删空。系统维护章节、讲稿分配、来源与布局，不让用户为了删页修预算或补占位内容。叙事不足作为可定位提示，非法悬空引用不能写入。
- 零页显示“还没有幻灯片”和“新增页”，清除失效选择，保留 Undo/Redo，禁用导出。AI 不能把“这页”解析成不存在的目标。
- Figure 可查看来源、调整当前元素裁图或删除。单页裁图不修改论文底稿；修改论文切分明确进入图源工作区。
- 手工草稿使待提交的同范围 AI 修改失效并取消；单纯选择不取消。重复发送禁用。AI 的“撤销”只在对应修改仍在撤销栈顶时可用。
- 修改讲稿可请求更新相应页面，修改页面可请求调整讲稿；已有人工内容不被后台改写，差异应用是一笔可撤销操作。
- 整套重生成预填现有要求，以相同自动链准备候选，除用户选择暂停外不强制确认中间大纲。成功并获准替换后切换版本；已有手工成果的替换先展示具体变化。候选存在期间 Current 可正常编辑，基准变化使候选过期，保留当前稿并提示重新生成候选。

辅助面板收起后中央画布优先保留；窄屏依次把 Inspector、讲稿和章节导航收起或转抽屉，不把固定桌面列纵向堆成长页。底部命令区保持紧凑，不挤没画布；手机不另建完整编辑器。

### 3.7 来源查看与两类裁图

论文图源核对与当前页裁图共用原 PDF、渲染与框选能力，但写入目标明确不同：

| 入口 | 修改对象 | 影响 |
|---|---|---|
| 论文与图源 → 调整切分 | 工作底稿的 Figure/Panel 来源 | 用于后续理解、讲稿和规划；已有稿更新先展示影响 |
| 幻灯片 → 调整本页裁图 | 当前 Figure 元素的裁图覆盖值 | 只改变当前页当前元素，其他元素和论文图源不变 |

普通来源查看保留对话框：

```text
┌────────────────────────────────────────────────────┐
│ Fig. 3B · 原文第 8 页                        [关闭] │
│ PDF 原页：虚线为文稿绑定的图源框，实线为本页裁图    │
│ 标签 / caption / 对应原句                          │
│ [查看论文图源工作区]                  [调整本页裁图]│
└────────────────────────────────────────────────────┘
```

没有覆盖值时只显示一个框。文字来源无精确 bbox 时展示原页、原句或段落，不伪造高亮。大纲可查看来源并转到图源工作区，不能隐式把单页覆盖操作当成论文源修改。

本页裁图通过原页框选，提供“恢复默认范围”“取消”“应用到本页”。恢复只改待应用框，应用后一次保存与 Undo；取消不变，失败保留框供重试。默认范围来自该文稿绑定的论文版本；论文工作底稿更新不自动改变旧稿默认框。换图清除旧覆盖，换布局保留覆盖。

```text
┌────────────────────────────────────────────────────┐
│ 模型设置                                    [关闭] │
│ 模型       [已通过验证的固定候选             ▾]   │
│ API Key    [•••••••••••••••••••••••••••••••••]   │
│ 论文分析所需文本和图片将直接发送给所选供应商。      │
│ Key 保存在当前浏览器，可单独清除。                  │
│ [测试连接] [清除 Key]                       [保存]  │
└────────────────────────────────────────────────────┘
```

设置是对话框，仅展示已通过 M0 的模型候选、Key 和连接结果。保存或关闭后返回原页面；关闭丢弃未保存的设置输入。运行中的任务先完成或取消，才允许保存模型切换或清除 Key。

| 状态 | 展示位置与操作 |
|---|---|
| 保存中 / 未保存 | 编辑器顶栏；失败时显示原因与重试，不用 Toast 代替持续的未保存提示 |
| 无网络 / 缺 Key | AI 面板和生成入口提示；本地查看、手工编辑及资源完整时的导出仍可用 |
| 来源缺失 | 来源对话框说明受限原因；导出缺图时指出具体页并提供定位入口 |
| 导出中 / 失败 | 顶栏导出按钮显示进度并防重复点击，失败后可重试，当前 Deck 保留 |
| 可安装 / 可更新 | 首页和编辑器共用的应用提示区；安装仅在浏览器支持时出现，更新按第 6 节规则等待保存和空闲 |

### 3.9 AI 行为

用户显式选择“提问”或“修改”。提问只回答、核查和给建议，从能力上没有写工具；修改先生成提案，任何范围均须用户点击应用后生效。底部命令区输入上方的范围标签可选择元素、页面、章节或整套 PPT；请求含更明确目标时先解析并显示实际范围，模型不得自行扩大范围。对话、工具状态及修改提案显示在右侧 Inspector 的 AI 标签。

| 用户请求 | 预期行为 |
|---|---|
| “解释这张图”“检查有没有逻辑问题” | 回答或给建议，不改 Deck |
| “第 7 页标题短一点” | 明确页码优先，只修改目标标题 |
| “这页太挤”“这张图大一点” | 使用当前选择，先调整布局或精简辅助文字，必要时拆页 |
| “背景压成一页” | 修改背景部分，保留研究问题，不顺便改结果页 |
| “Figure 3 只留 B 和 D” | 使用原论文 Figure/Panel 标识；通过两个独立元素组合，保留各自来源 |
| “整体压到 12 页”“全部改成中文” | 按明确范围批量修改，提供摘要，一次撤销 |
| “按刚才的建议修改” | 使用最近审核上下文；如目标已变化，则重新核对 |

明确目标高于 UI 选择；指代不明确时依次使用当前选择和近期上下文，仍有多个合理目标才询问。“这页”使用当前显示页，不使用之前聊天里提到的页。

一次请求最多一个有效提案；提案先在工作副本模拟，显示受影响页与差异摘要，用户应用时重新校验版本、范围、引用、叙事与布局，成功后产生一次 Undo。取消、手工草稿、项目/Deck 切换或版本变化使提案立即失效，不能提供“仍然应用”。取消、失败或旧响应均不留下半完成修改。手工修改是后续 AI 请求的新事实，AI 不得用旧上下文覆盖它。

### 3.10 检查与导出

```text
┌────────────────────────────────────────────────────────────┐
│ 项目名 论文与图源 大纲与演讲稿 幻灯片 [检查]      [导出]   │
├────────────────────┬───────────────────────────────────────┤
│ 结构 / 证据 / 视觉  │ 当前问题预览与定位                    │
│ 讲稿 / 资源         │ 第 8 页图例较小 → 返回该图             │
│ 主线 / 补充覆盖     │ 第 12 页有未更新的讲稿 → 查看候选      │
├────────────────────┴───────────────────────────────────────┤
│ 结构问题自动检查，科学解释不冒充已验证       [导出 PPTX]   │
└────────────────────────────────────────────────────────────┘
```

检查视图与顶栏使用同一导出用例。资源缺失、非法或悬空引用、无效坐标、无法容纳的元素、未解决的内容同步冲突阻止导出，并给出定位和系统修复/重试入口。零页禁用导出。

叙事比例、标题、重复表达、较小图片、缺少过渡和科学措辞属于提醒，不再强迫用户补页或逐项确认警告。可查看全部发现的主线/补充/用户省略情况；不能把自动遗漏包装成人工取舍。讲稿与页面分别检查来源、分配与一致性，但不建设第二套模型评分器或要求用户逐句验真。

保持问题定位、导出进度、防重复点击和失败重试。检查绑定已保存 Deck 及其论文版本；导出前版本变化重新检查，导出开始后固定快照。原生文字可继续编辑，讲稿进入对应页的讲者备注，图片不拉伸。尚未更新的人工稿允许先保留原版并导出原版，不混入新旧两套来源。

## 4. 生成与视觉规则

默认充分覆盖论文发现，不使用 12–16 页或 10–20 页作为默认硬边界。先按讲述结构组织证据和演讲稿，再按可读性分配页面；内容多就增加必要页，不让用户另找漏掉的内容。主线讲清背景、问题、必要设计、发现、综合/局限与 Take-home；补充内容包括额外验证、方法细节和次要发现，默认位于主线之后并明确标识。

| 内容职责 | 组织原则 |
|---|---|
| 论文身份与意义 | 保留原论文身份，开场交代研究意义 |
| 背景、知识空白与研究问题 | 为听众理解发现提供必要上下文 |
| 设计、样本与实验条件 | 随证据讲清组别、物种、终点与关键限制 |
| 主线发现 | 按科学问题组织，不按 Figure 编号机械串联 |
| 综合、局限与 Take-home | 主线形成清晰收尾，不要求补充内容之后再重复结论 |
| 补充发现与方法 | 保留可调用的内容，用户可删、调序或移入主线 |

每个讲述段落有依据与目的，每页承接具体讲述内容并展示必要证据；结果页关联有效 Claim/Evidence/Source 和匹配原图。标题优先准确结论句，正文与讲稿互补。段落与页面不能为凑数量重复；不把重点 Claim 至少两页当成质量判据。用户删除或重排后保留结构提醒，不以僵硬的学术顺序阻止常规编辑。

研究结构采用可配置的研究叙事策略：每个策略以 Markdown 正文和少量 YAML 头信息保存在仓库中，用于指导论文解读、证据取舍和汇报结构。下表保留首批策略的适用范围和内容要求；实际提示词已由 M3–M5 接入并单独维护，可变措辞在提示词维护，基础骨架与校验规则是稳定产品契约。

| 内置策略 | 适用情况 | 初始内容要求 |
|---|---|---|
| 通用 | 支持范围内难以归入单一类型的研究，以及方法/工具型原创论文 | 问题 → 方法贡献 → 基准/验证 → 生物学或应用价值 → 局限 |
| 机制实验 | 以实验干预及机制证据为主的研究 | 现象 → 干预 → 因果证据 → 机制 → 救援/验证；保留对照，不将关联升级为因果 |
| 组学/生信 | 以高通量数据分析及生物学发现为主的研究 | 研究设计 → 全局图谱 → 关键差异 → 通路/调控解释 → 跨模态或独立验证；不堆砌工具步骤 |
| 临床 | 以人群、比较组和临床终点为主的研究 | 临床问题 → 队列/随机设计 → 主要终点 → 次要终点/安全性 → 局限；不以次要亚组替代主要结果 |
| 转化/混合 | 结合人体、组学、实验等多种证据的研究 | 人体发现 → 组学线索 → 实验验证 → 转化意义；围绕结论衔接证据 |

首次在已有论文理解步骤中自动选择一个策略，不增加模型调用或要求用户先选研究类型。无法确定时使用通用策略；通用策略不扩大第 2 节的论文支持范围。用户通过项目准备或 AI 输入框说明汇报重点、时长和叙事要求，这些要求优先于策略默认建议，并始终受论文证据约束。

策略提供主线叙事建议，不要求各职责独占一页。主线与补充、讲稿和实际证据共同决定页数；用户可调整顺序和内容，不需要确认预算差额。同一生成流程、Paper/Deck 契约和六类布局适用于所有策略，不按研究类型建设独立工作流。方法流程仍使用短文字或论文原图呈现。

维护者修改仓库提示词后重新构建发布，应用更新后用于后续请求；已有论文分析、计划和幻灯片不自动重写，续跑仍保留已完成阶段。首版不增加提示词编辑页面、策略选择表单或远程配置服务。文件格式、选择与更新规则见架构文档第 7 节。

首版只有一个学术白底主题、16:9 比例和六类布局：标题、文字、整图、图文、双图、Panel 网格。网格用于 3–4 个 Panel；更多内容拆页。结论、方法、讨论等复用这些布局，不为章节名称增加新布局。

Figure 优先选择支持主要结论的原图；复杂 Figure 可以按信息单位拆 Panel 或拆页。不得拉伸原图、重画科研数据，或通过裁图隐去理解结果所需的组名、坐标、图例、比例尺和统计信息。人工裁图保留原页查看入口，应用不声称能自动判断所有裁图的科学完整性。

文字过长或图太小时优先换布局、精简非核心文字，再拆页；不通过无限缩小字号解决。完整 caption 放在来源查看中，必要长解释和过渡放在演讲稿中，AI 回答用于按需讨论。

科学表达遵循：

- 主要结论保留对应证据和来源；不能编造实验、样本量、数值、Figure、引用或作者结论。
- 相关性、预测结果和 pseudotime 不自动升级为因果、实验验证和真实时间。
- 保持物种、组织、细胞、队列、组别及终点语义；不混淆基因表达与蛋白证据。
- 创新点和局限基于论文；额外推断必须明确其解释性质。无法支持的内容宁可省略。
- 用户要求增强措辞也不得超过论文证据；提供准确替代表达。
- 保留专业实体名称及原图文字，整套 Deck 的主要叙述语言保持一致。

结构/引用、可渲染性和来源完整性仍由程序保证。叙事比例、章节顺序及页数偏好不再成为用户必须修复的错误；自动生成的内容覆盖缺口由系统处理或明确报告未完成。科学正确性不能由字段合法或用户确认切分来证明。校验边界见架构第 6 节。

## 5. 保存、恢复与导出

保存覆盖论文底稿、图源修正与核对确认、完整大纲/讲稿/规划阶段、页面编辑、裁图、重排、Undo/Redo 和版本切换。已结束的内容编辑通过统一入口保存，未完成输入保留为本地草稿；失败持续显示“未保存”并保留输入，提供重试。空间不足提示清理本地项目并避免关闭当前页面。

手工草稿出现时停止会覆盖它的任务；AI 修改、Undo/Redo、导出、版本切换和离开项目先完成保存或由用户明确取消草稿。保存失败不使用旧结果覆盖输入。纯浏览不取消任务，也不改变暂停选择。

重开无需调用模型，恢复工作底稿、核对状态、计划/讲稿、当前 Deck 和上次查看对象。普通 Undo/Redo 不跨重启，已保存的人工切分、讲稿、Current/Previous 必须保留；恢复旧内容时版本号仍递增，不恢复旧任务权限。

核对确认绑定切分版本，继续生成绑定底稿、讲稿与规划版本。上游编辑只使依赖它的下游结果失效，保留未受影响的成果和已修改内容；更新候选与当前稿明确区分。只改 Panel 边界不重做全文解析，改讲稿不重做图源分析，删 PPT 页面不删论文发现。具体依赖与提交规则见架构第 4、5 节。

整套重生成只保留一个候选，复用论文底稿；完整新稿与讲稿准备好后展示替换变化，应用才原子切换 Current/Previous。用户点击应用前 Current 可继续编辑；版本改变使旧候选不可应用，可保留供查看后重新生成。失败、取消和刷新保留最近完整阶段与旧稿，不创建版本树。恢复上一版同时恢复该版的讲稿与论文依据，不能指向后来修改过的图源。

切换模型或清除 Key 不改变内容，也不触发重分析；新配置用于下次请求，运行中的请求先完成或取消。

导出固定已保存 Deck、演讲稿分配和该稿绑定论文的快照，使用同一顺序、语言、来源与裁图。导出期间的新编辑用于下次导出，不混入本次文件。文字为原生可编辑对象，Figure 为图片、科研数据不重绘，讲稿写入对应页讲者备注。导出不改变版本、不长期保存 PPTX 或位图。

v0.3/v0.4 项目必须可打开，保留 PDF、Current/Previous、裁图和已编辑内容。旧计划的人工修改可保留，但旧大纲确认不等同于新图切分核对；旧稿没有讲稿或句子关联时明确“尚未生成”，不能在迁移时调用模型、编造内容或强迫用户先补全才能查看导出旧稿。生成新稿时才按新流程补齐。

位图失效时从原 PDF 重建；PDF 或必需来源缺失时保留可读内容、定位问题并禁用依赖该资源的导出。不提供 PDF 重新关联。

## 6. 本地、联网与 PWA 边界

项目与 PDF 保存在当前浏览器的 IndexedDB；页面、缩略图和裁图片段按需生成，不长期保存缓存位图或导出文件。

用户配置自己的 API Key，首版从通过验证的 DeepSeek/GLM 固定候选中选择。Key 保存在浏览器独立设置中，可单独清除；项目删除不删除 Key。首次设置说明：论文分析所需的文本和图片会直接发送给所选模型供应商，Key 不进入对话、导出或日志。

应用静态资源完成离线缓存后，可离线打开本地项目、查看来源、手工编辑、裁图和导出。模型理解、生成与 AI 修改需要联网。首次访问未完成缓存时不承诺离线可用。

应用更新提示在空闲且已保存时由用户刷新，不打断编辑或生成，不清理项目；若还打开着其他 smartJC 标签页，提示先关闭后再更新。首次离线缓存准备失败时可联网重试。请求浏览器持久化存储被拒绝时仍可使用；设置中明确说明清除站点数据可能删除本地项目，PPTX 导出不等于项目备份。

## 7. 后续候选与明确边界

只有实际使用证明必要时才评估：幻灯片自由拖动缩放、多主题、通用图片/图形、方法流程图、项目备份导入、完整 Paper 字段编辑、PDF 重新关联、跨重启撤销历史。演讲稿、PPTX 讲者备注和来源级图切分编辑已纳入本版，不再列为候选。

本版不建设账号、云同步、后端代理、后台队列、多人协作、通用 Agent/插件/MCP 市场、多 Agent 编排、多论文工作区、联网补充材料、PPTX 导入、动画/模板市场或完整 PowerPoint 编辑器。沿用浏览器内静态 PWA；不为借鉴拆图项目直接引入 Python/SciPy 服务、独立 OCR 或多边形/遮罩裁图。后续确需改变这些技术边界时先讨论。

产品验收以 [执行计划](执行计划.md) 的同一条主链和必要内容检查为准。当前实现与新目标的差异不能用历史测试通过来掩盖。
