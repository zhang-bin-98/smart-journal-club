# smartJC 产品文档

> 版本：MVP v0.4 · 2026-09-06
> 状态：v0.4 目标设计已统一；M0–M6 为已发布的 v0.3，新增行为待 M9–M12 实施，详见执行计划。
> 本文定义用户行为与首版范围；数据及运行规则见 [架构文档](架构文档.md)，实施与验收见 [执行计划](执行计划.md)。

## 1. 产品目标

smartJC 是面向生物医学原创研究论文汇报的本地优先 PWA，静态部署在 GitHub Pages。

核心闭环：

**上传一篇 PDF → 自动识别 Figure/Panel 并理解论文 → 查看论文理解 → 编辑学术大纲 → 确认大纲 → 生成完整 PPT → 编辑与来源核查 → 结构/证据/可读性检查 → 导出可编辑 PPTX。**

主要用户是准备 Journal Club、组会和文献汇报的生物医学研究人员。首版成功标准是主要结果讲得清楚、原图可读、来源可查、局部修改可控，导出后可在 PowerPoint 继续编辑。

产品以学术大纲作为生成前的控制面，帮助用户组织证据和汇报故事。项目只服务 smartJC，不承担通用 Agent 平台验证或未来组件复用目标。

## 2. 首版范围

| 首版必须具备 | 边界 |
|---|---|
| 单篇 PDF、本地项目列表、重命名、删除 | 一个项目绑定一份固定论文；删除项目需确认 |
| 自动识别 Figure/Panel、理解论文和证据链 | 只分析当前 PDF，不联网寻找论文附件 |
| 论文理解展示 | 查看问题、设计、主要发现和证据；不建设完整 Paper 字段编辑器 |
| 可编辑学术大纲，确认后生成 Deck | 初始大纲生成后停止；支持章节、页预算、Claim 和 Figure/Panel 取舍 |
| 叙事检查与检查/导出步骤 | 硬错误阻止确认或导出，警告可定位并确认继续 |
| 幻灯片预览、来源查看、当前页裁图 | 来源查看复用裁图所用的 PDF 页面 |
| 文字编辑、新增/删除页、元素删除、页顺序调整 | 不提供自由坐标或富文本编辑器 |
| AI 问答、审核与局部/批量修改 | 用户显式选提问/修改；所有 AI 修改先展示提案，应用后一次请求可一次撤销 |
| 自动保存、阶段续跑、会话内 Undo/Redo | 失败不破坏最近已保存成果 |
| 整套重生成、恢复上一版 | 只保留一个上一版，不提供版本树 |
| PPTX 导出、PWA 安装和本地离线操作 | AI 功能需要联网及用户自己的模型 API Key |

输入只支持生物医学原创研究论文，覆盖机制、组学、临床和转化/混合研究。Review、系统综述、Meta-analysis、指南、纯病例报告和其他领域不纳入首版支持；识别到不支持的类型时说明边界，不建设额外工作流。扫描件、加密或损坏 PDF 提示更换可解析版本，不加入 OCR。

正式编辑体验面向桌面 Chrome/Edge。手机、Safari、Firefox 尽力兼容，不作为首版发布门槛。

## 3. 页面设计与用户流程

### 3.1 页面与状态关系

```text
首页
 └─ 项目工作区
     ├─ 准备与生成进度
     ├─ 1 论文理解
     ├─ 2 学术大纲
     ├─ 3 幻灯片
     └─ 4 检查与导出

顶部：[1 论文理解] ─ [2 学术大纲] ─ [3 幻灯片] ─ [4 检查与导出]
模型设置：从首页或工作区打开对话框
来源查看 / 裁图：复用同一个 PDF 对话框
```

首页与项目工作区是两个导航入口；四个步骤是可识别、可返回的独立工作状态，沿用简单 Hash 导航，不要求复杂路由层级。设置与来源继续用对话框。应用使用统一浅色界面，幻灯片主题见第 4 节。

- 到 `paper-ready` 开放论文理解，自动分析可继续规划初始大纲。
- 到 `deck-plan-ready` 停止生成并默认打开学术大纲，等待用户确认。
- 到 `deck-ready` 开放幻灯片和检查与导出；回到已完成步骤查看不回退 checkpoint。
- 已有 Deck 时，大纲默认展示 Current Deck 的最终章节与页面结构，只读；调整整套规划须显式进入候选重生成，不编辑已经消费的临时计划。
- 尚未生成 Deck 的已确认大纲再次编辑前，提示确认将失效、当前生成会取消；保存后回到草稿。任何旧生成结果均不得覆盖修改后的计划或已有 Deck。

各页面沿用同一套颜色、字体、间距与控件风格，按钮、表单、边框及选中/聚焦/禁用态保持一致；新增页面不另设视觉主题。实现沿用已接入的 React 与 Tailwind CSS，按后续里程碑接入新步骤和 Inspector，同时保留既有编辑体验；技术栈、组件及文件组织见 [架构文档](架构文档.md) 第 1 节，迁移顺序和验收见 [执行计划](执行计划.md)。

### 3.2 首页与项目准备

```text
┌────────────────────────────────────────────────────┐
│ smartJC                                  [模型设置] │
│                                                    │
│         上传论文，生成可继续修改的 PPT              │
│     ┌────────────────────────────────────────┐     │
│     │       将一篇论文 PDF 拖到这里           │     │
│     │              [选择 PDF]                │     │
│     └────────────────────────────────────────┘     │
│                                                    │
│ 最近项目                                           │
│  项目 A           15 页 · 已完成 · 2 小时前    [⋯]  │
│  项目 B           待继续 · 昨天               [⋯]  │
└────────────────────────────────────────────────────┘
```

- 上传区支持拖入和文件选择，只接受单份 PDF。保存时原位显示“正在保存论文…”，完成后进入项目准备状态。
- 最近项目按最近修改时间排列，显示名称、页数（已有 Deck 时）、状态和时间。点击打开，更多菜单只提供重命名和删除。
- 没有项目时隐藏列表，保留上传说明与主要按钮；读取失败显示原因和“重新选择 PDF”。
- 项目与原 PDF 一起保存成功后进入准备状态；项目名称先取文件名，仅在用户尚未重命名时再用论文标题补充。项目名称与论文原标题分开保存。

项目准备在同一项目页展示：

```text
┌────────────────────────────────────────────────────┐
│ [返回首页]  项目名称                     [模型设置] │
│                                                    │
│ 已保存：paper.pdf                                  │
│ 你希望怎么汇报这篇论文？（可选）                    │
│ ┌────────────────────────────────────────────────┐ │
│ │ 例如：中文，15 页左右，重点讲结果和创新点        │ │
│ └────────────────────────────────────────────────┘ │
│                          [分析论文并生成大纲]    │
└────────────────────────────────────────────────────┘
```

准备阶段保留一个自然语言要求输入框，细化结构在学术大纲步骤完成。默认采用论文主要语言，目标约 12–16 页，内容较少或较多时在约 10–20 页内调整。用户明确要求优先，但不能通过重复、隐藏关键证据或编造事实凑页数。模型 Key 未配置时在生成按钮旁提示并提供设置入口，配置后回到原项目，保留已输入要求。

### 3.3 生成、取消与继续

```text
┌────────────────────────────────────────────────────┐
│ 项目名称                              正在制作 PPT │
│                                                    │
│ ✓ 解析论文                                         │
│ ✓ 分析 Figure / Panel                              │
│ ● 理解研究内容                                     │
│ ○ 规划汇报结构                                     │
│ ○ 学术大纲待确认（确认后才制作幻灯片）              │
│                                                    │
│ 已完成的步骤已保存。                      [取消]   │
└────────────────────────────────────────────────────┘
```

准备流程自动完成解析、图源、论文理解和初始规划，在大纲保存后停止。用户确认通过校验的大纲后，才启动独立的“制作幻灯片”流程；完整 Deck 保存成功后进入幻灯片步骤。只显示这些高层阶段，不显示工具 JSON、推理、token 或逐个 API 请求。

取消后停在同一项目页，显示停止位置以及“继续生成”“返回首页”。任务运行时不提供后台留守入口；关闭、刷新或浏览器终止可能中断生成。重开未完成项目时显示“上次在‘理解研究内容’中断”，由用户点击继续，重做未完成阶段。

刷新后恢复最近完整产物、计划草稿和确认状态，不自动开始模型请求。制作幻灯片失败保留已确认计划，可重试或返回修改；修改即令旧任务失效。

失败提示放在当前阶段附近：说明失败原因、已保存内容，并提供“重试当前步骤”或“模型设置”。制作幻灯片时若展示部分结果，只作为当前会话只读预览，不标为正式成果，也不承诺逐页保存。

### 3.4 论文理解

```text
┌──────────────────────────────────────────────────────────┐
│ 项目名称   [1 论文理解]  2 学术大纲  3 幻灯片  4 检查    │
├──────────────────────────────────────────────────────────┤
│ 论文标题 · 研究类型 · 叙事策略                            │
│ 研究问题 / 知识空白                                      │
│ 研究设计：对象、样本、组别、模态、实验与终点              │
│ 主要发现                                                │
│ ① Claim A     Figure 2A–D        [查看证据]              │
│ ② Claim B     Figure 3B、4A      [查看证据]              │
│ 创新点 · 局限 · 不确定项 · 来源警告                      │
│ [模型设置] [重新分析]               [查看学术大纲 →]    │
└──────────────────────────────────────────────────────────┘
```

展示 3–6 个主要 Claim 的摘要及其 Evidence、Figure/Panel 和原文来源；主要发现更多时可展开其余项，不能为凑数量编造或丢弃证据。未识别图源、来源不全、无法确认的事实需明确标记；没有可用大纲时“查看学术大纲”禁用并展示规划状态或重试入口。这里仅做结构化摘要与来源核对，不提供完整 Paper 字段编辑器。

“重新分析”允许补充自然语言要求，复用已解析的 PDF 和完整图源，重新运行论文理解和规划。未生成 Deck 时先提示旧大纲会失效，成功后替换分析及大纲；失败保留已有完整产物。有可用 Deck 时，明确使用“在新项目中重新分析同一论文”：复制本地原 PDF 与可复用解析/图源到独立项目，保留原项目、Current/Previous 和全部证据关联，避免让旧 Deck 指向新分析。两个入口都只分析当前 PDF，不增加上传替换或重新关联 PDF 能力。

### 3.5 学术大纲

```text
┌────────────────────────────────────────────────────────────────┐
│ 项目名称   1 论文理解  [2 学术大纲]  3 幻灯片  4 检查与导出    │
├───────────────────┬────────────────────────────────────────────┤
│ 章节               │ 当前章节 / 当前页                         │
│ 开场           1页 │ 章节目的：说明研究的重要性                 │
│ 背景与空白     1页 │ 页目的：交代已知事实                       │
│ 研究问题       1页 │ 本页结论：……                               │
│ 研究设计       1页 │ Claim：…… [重点讲 / 简略讲 / 不讲]        │
│ 主要发现一     3页 │ Figure：2A、2C       [更换] [查看来源]    │
│ 主要发现二     4页 │                                            │
│ 综合与局限     2页 │ [添加文字页/结果页] [删除页] [移动]       │
│ Take-home      1页 │                                            │
├───────────────────┴────────────────────────────────────────────┤
│ 14 页 · 结果 7 页 · 2 个警告    [保存草稿] [确认大纲并生成]    │
└────────────────────────────────────────────────────────────────┘
```

大纲是持久化的 DeckPlan，显示草稿/已确认、保存状态、总页数、结果页数和问题数。支持新增章节、删除空章节、拖动章节、修改标题/目的及页数预算；支持页在章节内或跨章节拖动，编辑页目的和本页结论、添加文字页或结果页、删除非必要页。章节预算与实际页数的差异直接显示，不以复制空页自动凑数。

主要 Claim 可标记重点讲、简略讲或不讲，保存为计划偏好；不讲的 Claim 不再分配到章节/页面，移除后无 Claim 的结果页必须补选证据、删除或明确改为纯过渡页。更换图源仅从当前 Paper 的已有 Figure/Panel 选择，可随时查看来源；不在大纲页裁图或更改原始 Source。

- 保存草稿允许暂存叙事错误和预算差异，但结构、ID 和引用必须有效；保存失败保留输入并显示未保存。
- 确认前列出定位到章节/页面的错误与警告。硬错误须修复；警告说明规则后允许用户确认继续。确认保存成功才启动生成，未确认或过期版本不能生成。
- 修改已确认大纲会回到草稿并使尚未开始或正在运行的生成失效。生成失败保留确认版本；刷新保留草稿和确认状态。
- 计划缺失或版本不兼容时提示恢复方式，不能伪造确认状态；其他标签页已更新时拒绝覆盖，提示重新打开最新版本。
- 整套重生成也进入这一步编辑并确认候选大纲；可返回查看 Current，候选成功前不覆盖稳定成果。

### 3.6 幻灯片编辑工作区

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 项目名  1 理解  2 大纲  [3 幻灯片]  4 检查  已保存 [撤销/重做] [导出]│
├──────────────┬─────────────────────────────────┬─────────────────────┤
│ 章节 / 页数  │                                 │ Inspector           │
│ ▾ 背景  1页  │        当前 Slide Canvas        │ 内容 / 图源 / 版式  │
│   02 缩略图  │        16:9，自适应缩放          │ AI（可收起）        │
│ ▾ 发现一 3页 │                                 │ 本页目的 / 结论     │
│   05 已选中  │  选中图：[来源] [裁图] [删除]   │ Claim / 来源 / 布局 │
│ [＋新增页]   │                                 │                     │
├──────────────┴─────────────────────────────────┴─────────────────────┤
│ AI 范围：[选中元素] [当前页] [当前章节] [整套 PPT]   提问 / 修改      │
│ 输入要求… [发送]   提案：影响 3 页 · 修改摘要 [查看差异] [应用]       │
└──────────────────────────────────────────────────────────────────────┘
```

| 区域 | 控件与行为 |
|---|---|
| 顶栏 | 项目名、步骤导航、保存状态、Undo/Redo、检查/导出、更多菜单和模型设置；更多菜单保留重生成和有上一版时的恢复 |
| 章节导航 | 按章节折叠，显示页数、警告、缩略图、编号和选中态；点击切页，拖动重排，新增文字页，页菜单删除 |
| 中间 Canvas | 居中当前页，缩放只改变查看比例；点击文字编辑，选中元素有边框和对应操作，无自由坐标手柄 |
| Inspector | 未选元素显示页目的、本页结论、Claim、来源、布局；文字选择显示编辑和已有基础属性；Figure 选择显示图源、裁图和删除；AI 标签显示对话、工具状态及提案 |
| AI 命令区 | 输入上方始终显示实际作用范围和提问/修改模式；可放底部或右侧，发送期间可取消，提案显示影响页、摘要和应用按钮 |

编辑器可查看和修改本页目的与本页结论；二者保存在当前幻灯片，旧稿未填写时明确提示，不依赖临时大纲或用章节目的冒充。无可用 Undo/Redo 时禁用按钮，保留当前页/总页数显示。

编辑细节：

- 新增页使用文字布局，提供可编辑的标题和一个空文字元素；占位提示仅用于界面，不写入导出。文字编辑支持基础换行，编辑结束形成一次保存和撤销记录，不逐按键写历史。
- 删除页或元素通过校验即执行并可撤销，不逐次弹确认；删除必要叙事结构导致硬错误时提示改用同批重组或返回大纲，删空及旧稿修复按第 4 节的兼容边界处理；删除整个项目仍需确认。删图后原布局不再适用时按剩余内容切换到已有布局，布局调整与删除作为同一次撤销。
- 允许删除最后一页。删空后显示“还没有幻灯片”和“新增页”，页数为 0，清除当前页/元素选择，保留可用的 Undo/Redo，禁用导出；仍属于已有项目的编辑状态。AI 可按明确要求新增页，但不能把“这页”解析成不存在的目标。
- 选中 Figure 后显示“查看来源”“裁图”“删除”；引用可点击打开来源。切页和元素选择会进入下一次 AI 请求上下文。
- AI 摘要中的“撤销”只在该修改仍是当前可撤销栈顶时可用；之后已有其他编辑时使用底部统一 Undo，避免误撤销别的操作。
- AI 请求运行时可浏览页面，重复发送禁用。用户实际改变文字或裁图等内容、产生手工草稿时，立即使本轮待提交的 AI 修改失效并取消请求，提示“已转为手工编辑”；单纯浏览和选择不取消请求。
- “重新生成整套 PPT”打开简短对话框，复用项目准备的自然语言要求输入，预填现有要求，提供“取消”和“开始重生成”；开始后顶部显示状态及取消入口，当前 Deck 保持可查看，编辑操作禁用。先生成并保存候选大纲，等待编辑确认，再制作候选 Deck；成功后才保存新要求并切换版本，详见第 5 节。

空间不足时先收起 AI 和 Inspector 为抽屉，再将导航收为按章节分组的列表抽屉；中间预览占主要空间。手机沿用这一收起布局，不另做完整移动编辑器或增加移动端发布验收。

### 3.7 来源查看与当前页裁图

查看与裁图复用同一个对话框、原 PDF 页面和来源信息区：

```text
┌────────────────────────────────────────────────────┐
│ Fig. 3B · 论文第 8 页                        [关闭] │
│ ┌────────────────────────────────────────────────┐ │
│ │                  PDF 原页                      │ │
│ │     虚线框：论文识别区域                        │ │
│ │     实线框：本页使用区域                        │ │
│ └────────────────────────────────────────────────┘ │
│ Figure 标签、caption / 必要来源文字                │
│                                      [调整裁图]    │
└────────────────────────────────────────────────────┘
```

论文理解和大纲仅开放查看模式，裁图操作只在已有 Deck 的当前 Figure 元素上开放。普通查看模式展示原页、来源框和文字；有当前元素覆盖值时显示其实际使用区域，没有覆盖值时两个区域相同，不重复画框。文字来源缺少精确 bbox 时只展示原页和定位文字，不伪造高亮。

“调整裁图”进入同一窗口的框选模式，也可从 Figure 工具条直接进入。用户在原 PDF 页重新框选，底部改为“恢复默认范围”“取消”“应用到本页”。恢复默认先更新待应用框，点击应用后才保存；取消不改变当前元素。

应用只更新当前页当前 Figure 元素，其他页和共享论文来源不变；成功后关闭对话框并刷新当前图，支持一次撤销。保存失败保留当前框选并提示重试。首版没有“修正所有引用”入口。

### 3.8 模型设置与公共状态

```text
┌────────────────────────────────────────────────────┐
│ 模型设置                                    [关闭] │
│ 模型       [已通过验证的固定候选             ▾]   │
│ API Key    [•••••••••••••••••••••••••••••••••]   │
│ 论文分析所需文本和图片将直接发送给所选供应商。      │
│ Key 保存在当前浏览器，可单独清除。                  │
│ [测试连接] [清除 Key]                       [保存]  │
└────────────────────────────────────────────────────┘
```

设置是对话框，仅展示已通过 M0 的模型候选、Key 和连接结果。保存或关闭后返回原页面；关闭丢弃未保存的设置输入。运行中的任务先完成或取消，才允许保存模型切换或清除 Key。

| 状态 | 展示位置与操作 |
|---|---|
| 保存中 / 未保存 | 编辑器顶栏；失败时显示原因与重试，不用 Toast 代替持续的未保存提示 |
| 无网络 / 缺 Key | AI 面板和生成入口提示；本地查看、手工编辑及资源完整时的导出仍可用 |
| 来源缺失 | 来源对话框说明受限原因；导出缺图时指出具体页并提供定位入口 |
| 导出中 / 失败 | 顶栏导出按钮显示进度并防重复点击，失败后可重试，当前 Deck 保留 |
| 可安装 / 可更新 | 首页和编辑器共用的应用提示区；安装仅在浏览器支持时出现，更新按第 6 节规则等待保存和空闲 |

### 3.9 AI 行为

用户显式选择“提问”或“修改”。提问只回答、核查和给建议，从能力上没有写工具；修改先生成提案，任何范围均须用户点击应用后生效。输入上方的范围标签可选择元素、页面、章节或整套 PPT；请求含更明确目标时先解析并显示实际范围，模型不得自行扩大范围。

| 用户请求 | 预期行为 |
|---|---|
| “解释这张图”“检查有没有逻辑问题” | 回答或给建议，不改 Deck |
| “第 7 页标题短一点” | 明确页码优先，只修改目标标题 |
| “这页太挤”“这张图大一点” | 使用当前选择，先调整布局或精简辅助文字，必要时拆页 |
| “背景压成一页” | 修改背景部分，保留研究问题，不顺便改结果页 |
| “Figure 3 只留 B 和 D” | 使用原论文 Figure/Panel 标识；通过两个独立元素组合，保留各自来源 |
| “整体压到 12 页”“全部改成中文” | 按明确范围批量修改，提供摘要，一次撤销 |
| “按刚才的建议修改” | 使用最近审核上下文；如目标已变化，则重新核对 |

明确目标高于 UI 选择；指代不明确时依次使用当前选择和近期上下文，仍有多个合理目标才询问。“这页”使用当前显示页，不使用之前聊天里提到的页。

一次请求最多一个有效提案；提案先在工作副本模拟，显示受影响页与差异摘要，用户应用时重新校验版本、范围、引用、叙事与布局，成功后产生一次 Undo。取消、手工草稿、项目/Deck 切换或版本变化使提案立即失效，不能提供“仍然应用”。取消、失败或旧响应均不留下半完成修改。手工修改是后续 AI 请求的新事实，AI 不得用旧上下文覆盖它。

### 3.10 检查与导出

```text
┌────────────────────────────────────────────────────────────┐
│ 项目名称  1 理解  2 大纲  3 幻灯片  [4 检查与导出]        │
│ 14 页 · 中文 · 1 个错误 · 2 个警告                         │
│ 结构：背景 / 问题 / 设计 / 结果 / 总结                     │
│ 错误：结果页缺少 Claim               [定位章节/第 7 页]   │
│ 警告：Figure 较小                    [定位第 8 页图源]    │
│ 待复核：因果措辞、组别/物种/终点                           │
│ 资源：原 PDF 与图源可用                                    │
│ [返回修改]                        [确认警告并导出 PPTX]   │
└────────────────────────────────────────────────────────────┘
```

汇总确定性的学术结构、证据引用、标题长度/文字拥挤/小图/溢出、PDF 与图源资源检查，以及科学表达的人工复核提醒。每条问题可定位章节、页面或元素；没有机器证据时标作待人工复核，不冒充事实判定。硬错误阻止导出；警告说明后可确认导出。顶栏导出入口也走同一检查，不绕过门槛。

显示导出页数、语言、进度和失败重试；零页禁用导出。检查及警告确认绑定当前已保存 Deck 版本，内容改变后重新计算；导出开始后固定快照，详见第 5 节。不引入模型评分器、多模型裁判或第二条模型审核流程。

## 4. 生成与视觉规则

默认 12–16 页按以下弹性骨架分配，内容及明确要求可在约 10–20 页内调整；各区间不是可同时取上限的固定模板。

| 叙事职责 | 初始页数建议 |
|---|---|
| 封面与一句话研究意义 | 1 |
| 背景与已知事实 | 1–2 |
| 知识空白、研究问题或假设 | 1 |
| 研究设计、样本或整体路线 | 1 |
| 按科学问题组织的主要结果 | 5–8 |
| 综合模型、贡献或意义 | 1 |
| 局限与批判性讨论 | 1 |
| Take-home / 讨论问题 | 1 |

结果通常不少于总页数一半，背景和方法服务于理解结果；结果前交代问题和必要设计，结尾有综合或 Take-home，Journal Club 包含局限/讨论。每页一个主要信息，结果页须有子问题、take-home、有效 Claim 及其 Evidence/Source 和匹配原图。标题优先是结论句，不能只写 Figure 标签。纯过渡页使用 custom，不以 result 绕过 Claim 要求。

研究结构采用可配置的研究叙事策略：每个策略以 Markdown 正文和少量 YAML 头信息保存在仓库中，用于指导论文解读、证据取舍和汇报结构。下表保留首批策略的适用范围和内容要求；实际提示词已由 M3–M5 接入并单独维护，可变措辞在提示词维护，基础骨架与校验规则是稳定产品契约。

| 内置策略 | 适用情况 | 初始内容要求 |
|---|---|---|
| 通用 | 支持范围内难以归入单一类型的研究，以及方法/工具型原创论文 | 问题 → 方法贡献 → 基准/验证 → 生物学或应用价值 → 局限 |
| 机制实验 | 以实验干预及机制证据为主的研究 | 现象 → 干预 → 因果证据 → 机制 → 救援/验证；保留对照，不将关联升级为因果 |
| 组学/生信 | 以高通量数据分析及生物学发现为主的研究 | 研究设计 → 全局图谱 → 关键差异 → 通路/调控解释 → 跨模态或独立验证；不堆砌工具步骤 |
| 临床 | 以人群、比较组和临床终点为主的研究 | 临床问题 → 队列/随机设计 → 主要终点 → 次要终点/安全性 → 局限；不以次要亚组替代主要结果 |
| 转化/混合 | 结合人体、组学、实验等多种证据的研究 | 人体发现 → 组学线索 → 实验验证 → 转化意义；围绕结论衔接证据 |

首次在已有论文理解步骤中自动选择一个策略，不增加模型调用或要求用户先选研究类型。无法确定时使用通用策略；通用策略不扩大第 2 节的论文支持范围。用户通过项目准备或 AI 输入框说明汇报重点、时长和叙事要求，这些要求优先于策略默认建议，并始终受论文证据约束。

策略在基础学术骨架内提供可调整的结果叙事建议，不要求所有章节固定占一页；用户可调整章节顺序和预算，但确认前仍须通过硬性叙事校验。同一生成流程、Paper/Deck 契约和六类布局适用于所有策略，不按研究类型建设独立工作流。方法流程仍使用短文字或论文原图呈现。

维护者修改仓库提示词后重新构建发布，应用更新后用于后续请求；已有论文分析、计划和幻灯片不自动重写，续跑仍保留已完成阶段。首版不增加提示词编辑页面、策略选择表单或远程配置服务。文件格式、选择与更新规则见架构文档第 7 节。

首版只有一个学术白底主题、16:9 比例和六类布局：标题、文字、整图、图文、双图、Panel 网格。网格用于 3–4 个 Panel；更多内容拆页。结论、方法、讨论等复用这些布局，不为章节名称增加新布局。

Figure 优先选择支持主要结论的原图；复杂 Figure 可以按信息单位拆 Panel 或拆页。不得拉伸原图、重画科研数据，或通过裁图隐去理解结果所需的组名、坐标、图例、比例尺和统计信息。人工裁图保留原页查看入口，应用不声称能自动判断所有裁图的科学完整性。

文字过长或图太小时优先换布局、精简非核心文字，再拆页；不通过无限缩小字号解决。完整 caption 和长解释放在来源查看或 AI 回答中。

科学表达遵循：

- 主要结论保留对应证据和来源；不能编造实验、样本量、数值、Figure、引用或作者结论。
- 相关性、预测结果和 pseudotime 不自动升级为因果、实验验证和真实时间。
- 保持物种、组织、细胞、队列、组别及终点语义；不混淆基因表达与蛋白证据。
- 创新点和局限基于论文；额外推断必须明确其解释性质。无法支持的内容宁可省略。
- 用户要求增强措辞也不得超过论文证据；提供准确替代表达。
- 保留专业实体名称及原图文字，整套 Deck 的主要叙述语言保持一致。

结构、引用及叙事硬错误阻止大纲确认、正式生成提交和导出；草稿保存、零页编辑和旧稿修复的明确兼容边界见架构文档第 6 节。背景超 25%、结果少于 50%、无目的重复、宽泛标题、过多 Panel、缺局限/过渡/清晰 Take-home 或重点页数不足作为可解释警告；科学正确性仍需人工核对。

## 5. 保存、恢复与导出

保存覆盖完整生成阶段、大纲草稿与确认、编辑提交、裁图、顺序调整、Undo/Redo 和版本切换；大纲每次已结束的编辑经统一提交保存，“保存草稿”可主动提交待保存输入。保存失败显示“未保存”并保留待保存草稿，提供重试；不得显示已保存。若空间不足，提示释放本地项目空间，避免关闭当前页面。

存在手工草稿时，新的 AI 修改、撤销/重做、导出、整套重生成、版本切换及应用内离开项目先结束当前编辑并等待保存；保存失败则保留草稿，暂停后续操作，不用旧成果覆盖未保存内容。

重开项目无需调用模型，恢复当前 Deck、来源和上次查看页。普通 Undo/Redo 不跨重启，当前成果和整套重生成前的上一版必须保留。

整套重生成复用已有 Paper，先保存一个候选大纲并等待用户确认，再按确认版本生成新 Deck。刷新后可恢复候选计划，运行中的半成品不保存；取消保留计划供下次继续，主动放弃才删除候选。当前 Deck 继续可查看；新 Deck 成功保存后才切换，失败保留当前版和已有上一版。候选流程内不并行编辑或再次重生成同一项目；要修改或恢复 Current，先明确放弃候选。恢复上一版会交换两个版本并重置会话撤销栈，用户仍可再次切回。

切换模型或删除 Key 不改变项目内容，也不自动重新分析或生成。新设置用于下一次请求；运行中的任务先完成或取消再切换。

导出在开始时固定当前已保存 Deck 的快照，使用该快照的顺序、语言和裁图，浏览器直接下载 `.pptx`；导出期间的新编辑用于下一次导出，不混入正在生成的文件。文字可编辑，Figure 是可继续移动/缩放的图片，原图内部的数据对象不拆解。导出不改 Deck 或产生额外版本，零页文稿禁用导出。

v0.3 项目按确定性迁移补齐基础章节，保留原页面顺序、元素与证据；旧稿叙事不足在检查页定位，不因新规则丢失可读内容。计划不可迁移时仅重新规划，迁移失败提示恢复方式，不能清空项目。

图像位图不存在时从原 PDF 重建；PDF 或必需图源缺失时保留可读内容、说明受限能力并定位问题页，阻止静默缺图导出。首版不提供重新关联 PDF。

## 6. 本地、联网与 PWA 边界

项目与 PDF 保存在当前浏览器的 IndexedDB；页面、缩略图和裁图片段按需生成，不长期保存缓存位图或导出文件。

用户配置自己的 API Key，首版从通过验证的 DeepSeek/GLM 固定候选中选择。Key 保存在浏览器独立设置中，可单独清除；项目删除不删除 Key。首次设置说明：论文分析所需的文本和图片会直接发送给所选模型供应商，Key 不进入对话、导出或日志。

应用静态资源完成离线缓存后，可离线打开本地项目、查看来源、手工编辑、裁图和导出。模型理解、生成与 AI 修改需要联网。首次访问未完成缓存时不承诺离线可用。

应用更新提示在空闲且已保存时由用户刷新，不打断编辑或生成，不清理项目；若还打开着其他 smartJC 标签页，提示先关闭后再更新。首次离线缓存准备失败时可联网重试。请求浏览器持久化存储被拒绝时仍可使用；设置中明确说明清除站点数据可能删除本地项目，PPTX 导出不等于项目备份。

## 7. 后续候选与明确边界

只有实际使用证明必要时才评估：自由拖动缩放、多主题、通用图片/图形、方法流程图、Notes、项目备份导入、完整 Paper 字段编辑、PDF 重新关联、跨重启撤销历史。当前不为它们增加字段、工具或空目录。

首版不建设账号、云同步、后端代理、后台任务队列、多人协作、通用 Agent/插件/MCP 市场、多 Agent 编排、多论文工作区、联网补充材料/文献检索、PPTX 导入、动画/模板市场或完整 PowerPoint 编辑器。模型不支持任意 Base URL、任意路由或自动切换。

产品验收以 [执行计划](执行计划.md) 的同一条主链和必要内容检查为准，不在本文另建测试清单。
